# Story / Mission Manager — RoleForge 0.73.0

เปิดแชท → **ไม้กายสิทธิ์ → Story / Mission Manager** เป็นปุ่มแยกจาก Character / Lore Manager ไม่เพิ่มแถบถาวรเหนือช่องแชท หน้า Quests มีปุ่มเปิดบันทึกภารกิจชุดเดียวกันด้วย

## เริ่มสร้างภารกิจ

1. เปิด **แม่แบบ → สร้าง** ตั้งชื่อ เลือกภารกิจหรือเส้นเรื่อง และเขียนคำอธิบาย
2. ข้อมูลผู้เล่าเรื่องเก็บเบื้องหลัง/สปอยล์ไว้ต่างหาก ส่งให้ AI เฉพาะบทที่เข้าเงื่อนไข ข้อมูลของบทที่ยังล็อกไม่ถูกส่งทั้งคลัง
3. ใน **เงื่อนไข** เลือก AND หรือ OR แล้วเพิ่มสถานที่ NPC ไอเทม Stats พลัง วัน เวลา ภารกิจก่อนหน้า ธงเรื่อง หรือเหตุการณ์ที่ยืนยันในบท
4. ใน **เป้าหมาย** เพิ่มงานที่ต้องทำและงานเสริม งานเสริมไม่ขวางการจบ
5. ใน **รางวัล** ใส่ EXP เงินตามหน่วยจริงของโลก ไอเทม และธงปลดล็อก เช่น `[{"id":"chapter-two","value":true}]` เลือกยืนยันรับรางวัลหรือรับเมื่อยืนยันจบ
6. เปิดแม่แบบแล้วบันทึก แม่แบบที่ปิดมีป้ายและรูปแบบหม่นให้แยกได้ รายการแบ่งหน้าละ 10
7. ใช้ **ลองเงื่อนไข** ตรวจสถานะจริง หรือจำลองให้ผ่าน/ยังไม่ทราบ การทดลองไม่เริ่มงานหรือเปลี่ยนสถานะผู้เล่น

มือถือเปิดรายละเอียดและ Editor เป็นหน้าเต็ม พร้อมปุ่มกลับ ส่วนคอมแสดงรายการกับรายละเอียดข้างกัน

## ตอนเล่นจริง

- เมื่อ AI ตอบจบ RoleForge ตรวจสถานะที่บันทึกแล้ว และข้อมูล `storyEvents` ที่มากับคำตอบนั้น ไม่มีการเรียก AI เพิ่ม
- แม่แบบ “เสนอให้รับก่อน” สร้างข้อเสนอ ผู้เล่นรับได้ใน **บันทึกภารกิจ** หรือพิมพ์รับงานชัดเจนในแชท ส่วน “เริ่มเหตุการณ์เนื้อเรื่อง” เริ่มเองเมื่อเข้าเงื่อนไข
- แต่ละแม่แบบเริ่มได้ครั้งเดียวต่อคลัง/แชท ตรวจสูงสุด 8 บทที่เกี่ยวข้องเพื่อเตรียม prompt และเริ่มสูงสุด 3 งานต่อคำตอบ
- เป้าหมายต้องมีหลักฐานจากคำตอบที่จบแล้ว ข้อมูลสมมุติ แผนในอนาคต OOC หรือ ID ที่ไม่มีอยู่ไม่ใช่ความคืบหน้า สามารถยืนยันเป้าหมายด้วยตนเองในบันทึกได้
- การพิมพ์ถึงชื่อ NPC ไม่ทำให้เงื่อนไข “พบแล้ว” ผ่าน การโหลดประวัติไม่เปลี่ยน enabled/met/การอยู่ในฉากหรือเวอร์ชัน NPC
- ค่าที่ยังไม่ทราบรอไว้ รวมถึง NOT; จะไม่ตีความว่า “ไม่มี” เพื่อปลดล็อกเรื่อง
- จบเป้าหมายจำเป็นก่อนจบงาน รางวัลทั้งชุดจ่ายครั้งเดียว หากหน่วยเงินหายหรือบันทึกไม่สำเร็จจะไม่จ่ายบางส่วน
- แก้หรือลบแม่แบบไม่เปลี่ยนกติกาของงานที่เริ่มไปแล้ว งานนั้นใช้สำเนากติกาที่บันทึกเมื่อเริ่ม
- Swipe คืนความคืบหน้า เงิน ไอเทม และใบรับรางวัลตามแขนงเรื่อง แต่ไม่ย้อนทับแม่แบบที่ผู้สร้างบันทึกภายหลัง
- การติดตามอัตโนมัติใช้ตัวเลือก **ติดตามข้อมูลจากคำตอบปกติของ AI โดยไม่เรียกเพิ่ม** ของเดิม หากปิดไว้ยังจัดแม่แบบ/ยืนยันด้วยตนเองได้

## คลังของการ์ดและคลังแชท

- **Current library** ใช้คลังการ์ด เว้นแต่แชทนั้นมีชุดเฉพาะ
- **Character · คลังของการ์ด** แก้แม่แบบที่แชทของการ์ดนี้ใช้ร่วมกัน ความคืบหน้าแต่ละแชทแยกกัน
- **Chat · ชุดเฉพาะแชท** บันทึกเป็นสำเนาสำหรับแชทนี้ การ์ดต้นฉบับไม่เปลี่ยน
- การสลับคลังไม่ลบงานที่เริ่มไปแล้ว ยังคงดูและเล่นต่อจากบันทึกได้

แม่แบบไม่ถูกคัดลอกลงทุก checkpoint เก็บเฉพาะสถานะและรหัสอ้างกติกา ส่วนกติกาที่ใช้งานจริงบันทึกครั้งเดียวใน metadata ของแชท การสำรองแชท/ส่งออกสถานะเก็บกติกาเหล่านี้เพื่อกู้คืนได้

## Import / Export และการ์ดใบเดียว

- **Story Preset → Export JSON / Import JSON** ส่งเฉพาะนิยาม ไม่ส่งความคืบหน้า Import มีหน้าตรวจและเลือกผสานตาม ID หรือแทนที่คลัง ไม่ลบงานที่เริ่มแล้ว
- **World Preset** ในตั้งค่าส่วนเสริมมีประเภท **Stories & missions / เนื้อเรื่องและภารกิจ** บันทึกแยกหรือรวมกับ Power, Stats, Currency และระบบอื่นได้
- **Export self-contained card** ใน Manager บันทึกคลังที่เลือกกลับไปที่การ์ดแล้วสร้าง JSON ของ SillyTavern ให้ดาวน์โหลด ผู้รับ Import การ์ดเพียงใบเดียว
- การ์ดทั่วไปเก็บ `data.extensions.roleforge_story_pack` เพียงชุดเดียว ตัว Character Pack เก็บ `storyPresetRef` แทนสำเนาซ้ำ
- การ์ด World Pack เก็บดัชนีและไฟล์เรื่องราวใน Worker/IndexedDB การแก้คลัง Character อยู่ในเครื่องก่อน ต้องกด Export การ์ด/Update embedded archive เพื่อพกการแก้ล่าสุดไปเครื่องอื่น การ Export จาก Chat scope รวมชุดเฉพาะแชทที่เลือกเข้าการ์ดอย่างชัดเจน
- World Pack ยังคงใช้ `roleforge_world_archive` คู่ `roleforge_world_archive_payload` แบบ gzip-base64 เดิม สร้าง hash/revision ใหม่ ตรวจครบก่อนบันทึก reference/payload และเก็บคลัง revision เก่า
- ไม่มีการบีบอัดใหม่ทุกข้อความ และไม่เพิ่ม API ภายนอก

ไฟล์ JSON แม่แบบจำกัด 8 MiB; World Preset ใช้เพดานไฟล์เดิม 1 MiB คลังภายนอกแสดงรายการจากดัชนีและโหลดรายละเอียดเมื่อใช้ การ Export การ์ด World Pack ไม่ต้องดึงนิยามทั้งคลังกลับ main thread

ไฟล์ Preview เก่าที่มี `previewOnly: true` นำเข้าเป็นข้อมูลใช้งานจริงไม่ได้ ใช้ [ตัวอย่าง JSON ที่ใช้งานจริง](story-preset.example.json) หรือสร้างจาก Editor รุ่นนี้แทน

## สำหรับผู้สร้างแพ็ก

รูปแบบหลักคือ `roleforge-story-preset`, version 1 มี `id`, `revision`, `name` และ `entries` ดูไฟล์ตัวอย่างประกอบ

- เงื่อนไขซ้อน AND/OR และเงื่อนไข `when` ต่อเป้าหมายรองรับผ่าน JSON; Editor รุ่นนี้เก็บโครงซ้อนที่นำเข้าไว้และไม่แก้ทับ
- World Pack เพิ่ม `indexes.stories`, `storyPack` (header ของ preset ไม่รวม entries), `counts.storyTemplates`; ดัชนีเป็น `[{"id":"…","path":"stories/….json"}]`
- manifest.files ต้องระบุขนาดและ SHA-256 ของ index/ทุกไฟล์เรื่องราวเหมือนไฟล์อื่น Worker ตรวจเส้นทาง hash จำนวน และ ID ก่อนประกาศพร้อมใช้
- คำตอบ AI ใช้ `storyEvents` ใน `<!--tretaresia_patch:{…}-->` เดิม เช่น action `trigger`, `accept`, `objective`, `complete`, `fail`, `claim` พร้อม exact-quote `evidence` โดยใช้ ID ที่ให้ใน prompt เท่านั้น ระบบเป็นผู้จ่ายรางวัลของภารกิจเหล่านี้
