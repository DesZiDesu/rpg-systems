# RoleForge 0.58.2 — ปุ่มให้ AI เติมข้อมูลรายการซื้อขาย

แผงซื้อ/ขายที่แจ้งข้อมูลรายการไม่ครบมีปุ่ม **ให้ AI เติมข้อมูลรายการ** แล้ว พร้อมคำแนะนำว่าควรกดเมื่อใดและผลของการกด ใช้กับข้อเสนอซื้อ/ขายที่คำตอบ NPC จบแล้ว ไม่แสดงปุ่มกู้รายการระหว่าง AI ยังตอบแชตหลัก

## วิธีใช้

1. กดเมื่อ NPC เสนอสินค้าและราคาแล้ว แต่แผงเหนือ ChatBar ยังแจ้งว่าข้อมูลไม่ครบหรือข้อมูลข้อเสนอไม่ผ่าน
2. AI อ่านคำตอบ NPC ล่าสุดและบทสนทนาก่อนหน้าที่เกี่ยวข้อง แล้วเติมรายการและรายละเอียดไอเทมผ่าน API ปัจจุบัน **หนึ่งคำขอต่อการกด**
3. เมื่อเติมสำเร็จ ให้ตรวจชื่อสินค้า จำนวน ราคาปกติ ราคาทั้งชุด วิธีใช้ ผลสเตตัส และสกิลที่ไอเทมมอบ ก่อนกด **ยืนยัน** ซื้อ/ขาย
4. หากยังไม่มีชื่อสินค้าหรือราคาในบทโรล หรือ AI ยังเติมไม่ครบ ให้โรลถาม NPC ให้ระบุรายการและราคา หรือลองปุ่มใหม่ตามข้อความผิดพลาด

ปุ่มเติมข้อมูลไม่ได้จ่ายเงิน เพิ่ม/ลบของ สอนสกิล หรือเขียนบทโรลเพิ่ม การซื้อยังต้องยืนยันแยก และไอเทมที่มอบวิชายังต้องใช้ไอเทมภายหลัง ซื้อหนังสืออย่างเดียวไม่สอนวิชา รายการเดิมที่ AI ส่งมาครบอยู่แล้วใช้การซื้อขายตามปกติ ไม่ต้องกดปุ่มนี้

## เคสหนังสือของ Barth

AI อ่านชื่อหนังสือและราคาที่เสนอไว้ก่อนหน้า: Wind Arrow 15, Light Barrier 20, Aura Flow 10 เหรียญเงิน และอ่านคำตอบล่าสุดที่ลดทั้งชุดจาก 45 เหลือ 40 เหรียญเงิน

รายการที่เติมสำเร็จเลือกหนังสือ **สามชนิดอย่างละหนึ่งเล่ม** เก็บราคาต่อเล่มเดิม 15/20/10 และแสดงราคาทั้งชุด 40 แยกกัน ไม่แบ่งส่วนลดเป็นราคาต่อเล่มที่แต่งขึ้น และไม่ตีความ “ทั้งสามเล่ม” เป็นสามเล่มของทุกชนิด UI แสดง “ราคาตามรายการ 45 เงิน · ข้อเสนอทั้งชุด 40 เงิน” เพื่อให้ตรวจได้ชัดเจน

AI ได้รับคำสั่งให้เติม description/category/rarity/properties และ usage ที่มี action, consumable, effect, conditions, target, cooldown, charges, stats และ learns ให้ครบตามระบบไอเทมเดิม รวมทั้งข้อมูลวิชาที่ไอเทมมอบถ้ามี การตรวจสอบปฏิเสธข้อมูลขาดหรือผลสเตตัส/วิชาผิดรูปแบบ แทนการเปิดธุรกรรมจากข้อมูลที่ไม่ครบ

## การป้องกันปัญหา

- อ่านเฉพาะบทสาธารณะ ไม่ใช้ planning/think/analysis เป็นข้อเสนอหรือราคา
- จำกัดบริบทก่อนหน้าไม่เกินแปดข้อความ และหยุดเมื่อพบร้าน/สถานที่อื่นหรือการซื้อขายที่จบแล้ว ราคาต้องผูกกับชื่อสินค้าของ NPC ปัจจุบันจริง ๆ ไม่ใช้เพียงตัวเลขที่พบที่ใดก็ได้
- ไม่แต่งชื่อสินค้า ราคา ส่วนลด จำนวน สต็อก หรือเงินผู้รับซื้อขึ้น ข้อมูล stock ที่ทราบต้องตรงกับบท; ค่าที่ยังไม่ทราบคงเป็น unknown
- จำนวนต่อรายการที่มากกว่าหนึ่งต้องมีข้อมูลจำนวนในข้อเสนอ ไม่เปลี่ยนราคาต่อชิ้นเป็นราคารวมของหลายชิ้นเอง
- ส่วนลดต้องตรงกับราคาสุดท้ายที่ NPC ปัจจุบันเสนอ ไม่รับราคาที่ถูกปฏิเสธหรือเป็นข้อเสนอในอนาคต
- ปุ่มถูกปิดระหว่างรอคำตอบ กดซ้ำไม่เริ่มคำขอที่สอง และ API ล้มเหลวไม่ลองผ่านอีก preset อัตโนมัติ
- ทิ้งผลที่กลับมาช้าหากเปลี่ยนแชต แก้คำตอบล่าสุด แก้ข้อความราคาที่อ้างอิง เปลี่ยน swipe เพิ่มข้อความ ปิดระบบ เปลี่ยน state หรือยกเลิกงาน
- บันทึกเฉพาะ session ข้อเสนอที่ยังเปิดอยู่ผ่านคิว metadata เดิม พร้อม checkpoint การบันทึกล้มเหลวย้อนค่าก่อนหน้า ไม่ทำรายการการเงินระหว่างเติมข้อมูล
- โหลดแชตกลับมาแล้วใช้รายการที่บันทึกไว้ได้ ไม่เรียก AI เติมซ้ำอัตโนมัติ เงินและไอเทมเปลี่ยนเฉพาะการยืนยันซื้อขายที่ตรวจสอบผ่าน

## ผลทดสอบ

- `npm test`: ผ่าน **1,005/1,005** unit/host tests รวม 35 ข้อใหม่สำหรับการเติมข้อเสนอ/validation/API/retry/stale results
- `npm run check`: ผ่าน syntax checks รวมโมดูล commerce-repair ใหม่
- `npm run test:commerce-repair`: ผ่าน production-loader browser fixture ที่ **320/390/1280px** ตรวจคำแนะนำ, ข้อมูลไม่ครบและ retry, บันทึกล้มเหลวและ rollback, ปุ่มถูกปิดระหว่าง API, บทก่อนหน้าสามชื่อ, ราคาต่อเล่มและส่วนลดรวม, รายละเอียดวิชาที่ใช้ต่อได้, โหลด session กลับมา, ยืนยันชำระ 40 เพียงครั้งเดียว, receipt/ไอเทมครบสามเล่ม, ไม่เรียนสกิลตอนซื้อ และไม่มีแนวนอนล้น
- `npm run test:commerce-pending`: ผ่าน **320/390/1280px** ตรวจแผงเหนือ ChatBar รวมแชตเก่า เปิด/ปิดระบบ และไม่มี API ตอนโหลด/refresh
- `tests/commerce-stock-selection.browser.mjs`: ผ่าน **320/390/1280px** ตรวจตะกร้าสองชนิดอย่างละสาม จำนวน/สต็อก การต่อรอง โหลดรายการกลับมา การชำระและการส่งมอบครั้งเดียว
- `git diff --check`: ผ่าน ตรวจ main ต้นทางก่อน commit และเผยแพร่แบบ fast-forward

การทดสอบใช้ Chromium และโฮสต์/คำตอบ API แบบ fixture ไม่ใช่การเข้าโทรศัพท์ผู้ใช้หรือทดสอบทุกโมเดล หากข้อมูลจากโมเดลยังไม่ครบ แผงจะแจ้งและรอการลองใหม่โดยไม่ทำรายการ ชุด combined chat fixture เดิมมี baseline assertion failure ตามรายงานก่อนหน้า รอบนี้ไม่อ้างว่าชุดนั้นผ่าน

อัปเดตส่วนเสริมเป็น 0.58.2 แล้วรีโหลด SillyTavern เพื่อให้ไฟล์และ cache key ใหม่ทำงานร่วมกัน เปิดแชตเดิมและกดปุ่มเติมข้อมูลได้เมื่อแผงแจ้งข้อมูลไม่ครบ ไม่ต้องแก้คำพูด “แล้วกัน” หรือเขียน schema เอง
