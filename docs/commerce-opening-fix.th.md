# แก้ null และแถบประมูลไม่เปิด — v0.51.4

คำว่า `null` ใต้บทพูดเกิดจากตัวแสดงผลนำผลลัพธ์ของการ์ดที่ซ่อนไว้ (`null`) ไปใส่ใน DOM ด้วย `append(null)` จึงกลายเป็นข้อความจริง แก้ให้ต่อท้ายเฉพาะเมื่อมีการ์ด โดยไม่ลบคำว่า null ที่เขียนอยู่ในเรื่องโดยตั้งใจ

ข้อความดิบที่ผู้ใช้ส่งมามีแค่ Planning/Thinking และบทพูด NPC แม้ Planning จะบอกว่าจะสร้างข้อมูลประมูล แต่คำตอบจริงไม่มี `tretaresia_patch` ระบบจึงไม่มีรายการ ราคา และงบผู้ร่วมประมูลสำหรับเปิดปุ่ม อีกจุดหนึ่งคือตัวตรวจข้อความรอข้อมูลพึ่งคำว่า “ประมูล” และคำแสดงรายการในบทพูดมากเกินไป จึงซ่อนแถบเมื่อผู้ดำเนินประมูลพูดเพียงราคา

เวอร์ชันนี้คงแถบรอข้อมูลสำหรับคำขอปัจจุบันไว้ เมื่อคำตอบมีราคาแต่ไม่มีข้อมูลเปิดระบบที่อ่านผ่าน จะเรียก API ที่ใช้อยู่หนึ่งครั้งเพื่อจัดข้อมูลจากฉากให้ครบโดยอัตโนมัติ เป็นงานข้อมูลแยกจาก preset บทโรล ไม่มีข้อความแชตใหม่ ไม่แก้บทพูด NPC ไม่บิดเพิ่ม ไม่เลือกผู้ชนะ ไม่หักเงิน และไม่ส่งของ ขั้นตอนนี้ใช้ API เพิ่มเฉพาะกรณีข้อมูลเปิดระบบขาด; คำตอบที่มีข้อมูลครบหรือร้านที่กู้รายการจากบรรทัดราคาได้อยู่แล้วไม่ต้องเรียกเพิ่ม

ถ้า NPC บิด 6 เหรียญเงินไว้แล้ว แถบแสดงราคา 6 และราคา Bid ถัดไปเป็น 7 พร้อมงบจริงที่ AI กำหนดให้ NPC จากตัวละครและฉาก งบนี้ไม่ใช่เพดานความอยากซื้อหรือเป้าหมายเพื่อบังคับผู้เล่นชนะ ระบบตรวจชื่อสินค้า ราคา ผู้ร่วมประมูล ผู้พูดราคาปัจจุบัน และค่าเข้า/มัดจำ; ไม่ยอมรับราคาหรือผู้ร่วมประมูลที่แต่งเพิ่มระหว่างกู้ข้อมูล

ถ้าการกู้ยังได้ข้อมูลไม่ครบหรือ API ล้มเหลว แถบคงอยู่พร้อมเหตุผลและข้อมูลดิบสำหรับคัดลอกตรวจสอบ ไม่มีการเรียกซ้ำวนเอง การหยุด เปลี่ยนแชต แก้ข้อความ ส่งเทิร์นใหม่ หรือปิดระบบระหว่างรอจะทำให้ผลเก่าไม่ถูกนำมาใช้

ตรวจด้วยตัวแสดงผลและ loader จริงบน Chromium ที่ 320/390/1280 px รวมทั้งข้อมูลเปิดประมูลที่ไม่มี patch, ราคาปัจจุบัน 6 → Bid 7, การกู้ล้มเหลว, การปิดรายการ และการแสดง null คำตอบ API ในการทดสอบเป็นข้อมูลจำลอง ยังไม่ได้เชื่อมต่อ provider ส่วนตัวของผู้ใช้

อัปเดต extension เป็น v0.51.4 แล้ว reload ไม่ต้องล้างข้อมูล RPG การกู้อัตโนมัติทำงานเมื่อประมวลผลคำตอบ NPC รอบใหม่
