# คลัง NPC / Lore ขนาดใหญ่ และ World Pack

RoleForge 0.69.0 แยกคลังอ้างอิงออกจากข้อมูลระหว่างเล่น รายการใน Management อ่านข้อมูลย่อ ประวัติและเวอร์ชันอ่านเมื่อเปิดหรือเมื่อข้อความที่จะส่งเกี่ยวข้อง ส่วนสถานะแชตและ checkpoint เก็บเฉพาะส่วนต่างจากคลัง ตัวละครที่ยังไม่ได้โหลดจะไม่ถูกนับว่าถูกลบหรือซ่อน

การ์ดเดิมที่ฝัง NPC / Lore ยังใช้ได้ โดยใช้ cache และรายการย่อแบบเดียวกัน แต่ SillyTavern ยังต้องอ่าน JSON การ์ดทั้งใบ ถ้าแพ็กใหญ่มากให้ใช้ World Pack แยกต่างหาก

## ใช้แพ็ก Fate ที่ส่งมาทดสอบ

1. Import `01-core/Fate-Nasuverse-Core.json` เป็นการ์ดตามปกติ แล้วเปิดแชตใหม่
2. เปิดส่วนเสริม **RoleForge → Presets & character cards → การ์ดตัวละคร / Character card**
3. ใน **World Pack** กด **Import World Pack ZIP** แล้วเลือก ZIP ที่ส่งมาได้ทั้งชุด หรือเลือก ZIP ที่มี `manifest.json` เป็นราก ส่วน **Import folder** ใช้โฟลเดอร์ `02-world-pack`
4. รอข้อความ **Library ready / คลังพร้อมใช้งาน** จึงเปิด Character / Lore Management

Core มี NPC ฝังอยู่ 0 รายการ จึงต้องนำเข้าคลังในเบราว์เซอร์นั้นด้วย หากไม่พบคลัง ระบบแจ้งเตือนและหยุดการส่ง prompt ที่ต้องใช้คลัง แทนการถือว่า Core มีข้อมูลครบแล้ว ไม่ต้อง Import Native control หรือทางเลือก Preset ทุกอันซ้ำเข้า Core

แพ็กทดสอบมี NPC 800 ตัว, เวอร์ชัน 1,771 รายการ, Lore โลก 178 รายการ และข้อมูลเสริมพลัง 4,329 รายการ ข้อมูลเสริมจะอ่านเฉพาะพลังที่เกี่ยวข้องและอยู่ในงบข้อความ การอ้างอิง FGO/ข้อมูลจำลองไม่ใช่คำสั่งปลดล็อกพลังในเรื่อง

## ย้ายการ์ดเดิมออกเป็นคลังแยก

เปิดการ์ดที่ฝัง NPC / Lore แล้วกด **Move embedded archive to World Pack** ระบบอ่านการ์ดผ่าน API ปกติของ SillyTavern ใน Worker ตรวจและบันทึกคลังให้เสร็จก่อน แล้วตรวจว่าต้นฉบับยังไม่เปลี่ยน จึงบันทึกรหัสอ้างอิงและนำอาร์เรย์ NPC / Lore ฝังเดิมออก การ์ดยังคง Preset เดิม

การย้ายเป็นคำสั่งที่ผู้ใช้กดเอง การ Import ZIP ปกติไม่ลบข้อมูลฝังในการ์ด หากไฟล์เสีย ยกเลิก พื้นที่เก็บไม่พอ หรือเซิร์ฟเวอร์บันทึกการ์ดไม่สำเร็จ ข้อมูลเดิมจะยังอยู่ อาจมีคลังที่บันทึกสำเร็จแล้วให้เลือกเชื่อมภายหลังได้

## การเล่นและการแก้ข้อมูล

- ค้นจากชื่อ นามแฝง และข้อมูลบริบทภายในเครื่องก่อนส่ง prompt ไม่ส่งรายชื่อ 800 ตัวเข้าโมเดลทุกครั้ง ชื่อร่วมที่กำกวมจะไม่สุ่มเลือกตัวละครให้
- การอ่านประวัติไม่เปลี่ยน `enabled`, `met`, การอยู่ในฉาก ความสัมพันธ์ หรือเวอร์ชันที่เลือกเอง การเปิดใช้งานยังใช้ตัวเลือกเดิมใน Management
- เลือกเวอร์ชันที่ต้องการใน Management เช่น Gilgamesh Archer / Strange Fake การกล่าวถึงชื่อภายหลังไม่สลับเวอร์ชันเอง
- ตัวละครที่โมเดลเพิ่งสร้างขึ้นในคำตอบไม่สามารถได้ข้อมูลจากคลังย้อนหลังเข้าไปในคำตอบนั้นได้ ข้อมูลที่เพิ่งพบจะเตรียมสำหรับเทิร์นถัดไป
- หน้า Management แสดงครั้งละ 20 รายการ เปิดตัวละครหรือ Lore จึงอ่านประวัติเต็ม การแก้ข้อมูลคลังบันทึกแยกตามการ์ด ส่วนความเปลี่ยนแปลงระหว่างเล่นยังแยกตามแชต
- Swipe / rollback คืนสถานะระหว่างเล่น โดยรักษาการแก้ข้อมูลฐานที่ผู้ใช้บันทึกทีหลัง และไม่คืนเวอร์ชันที่ถูกลบไปแล้ว
- ไม่ลบ Lore อัตโนมัติเพราะมีชื่อเหมือน NPC ชุด Fate นี้ใช้ข้อมูลที่ผู้จัดแพ็กลดส่วนซ้ำไว้แล้ว ไม่ใช่ผลจากระบบลบอัตโนมัติของส่วนเสริม

World Pack ไม่รันสคริปต์หรือแพตช์ที่แถมมาใน ZIP แพตช์ mention activation สำหรับ 0.68.4 ในชุดทดสอบไม่ได้ถูกนำมาใช้กับรุ่นนี้

## สำรองและย้ายเครื่อง

คลังอยู่ใน **IndexedDB ของเบราว์เซอร์และ address นั้น** ไม่ได้อยู่บนเซิร์ฟเวอร์ SillyTavern การ Import การ์ด Core อย่างเดียวบนเครื่องอื่นจึงยังไม่ครบ

1. เปิดการ์ดต้นทางแล้วกด **Export / Backup** รอเตรียมไฟล์ แล้วกด **Download World Pack ZIP** และ **Download reference JSON** จะได้ ZIP ของคลังรวมการแก้ไขของการ์ดนี้ และไฟล์ reference JSON ของ ZIP นั้น
2. Export การ์ดและสถานะแชตตามปกติด้วย คลังสำรองไม่ใช่ไฟล์เซฟความคืบหน้าแชต
3. ที่เครื่องใหม่ Import การ์ด แล้ว Import ZIP สำรองใน World Pack หากเป็น Backup ที่แก้ข้อมูลแล้ว ให้เอาเครื่องหมาย **Match the card’s pinned archive** ออก เพราะ hash/revision เปลี่ยนจากแพ็กต้นฉบับ ระบบจะเชื่อม reference ใหม่หลังตรวจไฟล์สำเร็จ
4. โหลดหน้าใหม่แล้วตรวจรายการก่อนล้างข้อมูลจากเครื่องเก่า ใช้ **Refresh installed libraries → Link selected library** เมื่อต้องการเชื่อมคลังที่นำเข้าไว้แล้ว

สำรองก่อนล้างข้อมูลเว็บ เปลี่ยนเบราว์เซอร์ หรือเปลี่ยน address ภาพที่อ้างอิงไฟล์บนเซิร์ฟเวอร์ยังต้องสำรองไฟล์ภาพของ SillyTavern ตามเดิม World Pack ไม่ฝังไฟล์ภาพที่อยู่นอกแพ็ก

## รูปแบบแพ็กและขอบเขต

รองรับ `roleforge-world-pack` version 1 และ `roleforge-world-archive-ref` version 1 ตาม contract ของชุดทดสอบ ตรวจ SHA-256/ขนาดทุกไฟล์และ manifest ก่อนประกาศคลังพร้อมใช้ ปฏิเสธ path ที่ออกนอกแพ็ก, ไฟล์ซ้ำ, JSON ที่ใช้ prototype keys และรายการที่ขาดเวอร์ชันอ้างอิง

ขีดจำกัดการรับไฟล์คือ ZIP 64 MiB, ขนาดคลายรวม 256 MiB, ไฟล์ข้อมูลหนึ่งรายการ 4 MiB, จำนวนไฟล์ 50,000 และไม่เกิน 20 เวอร์ชันต่อตัวละคร ไม่ใช่เพดาน 800 ตัวละคร ใช้ Worker ทำงานหนักและ cache ประวัติที่เปิดล่าสุดไม่เกิน 48 ตัวร่วมกับตัวที่กำลังใช้อยู่ พร้อมงบตัวละครใน runtime/prompt เพื่อไม่โหลดทั้งโลกเข้าแชต

ผลทดสอบจริงและภาพหน้าจออยู่ใน [บันทึกตรวจสอบ](world-packs-validation.th.md) การทดสอบใช้เบราว์เซอร์บน Linux และ viewport มือถือ ไม่ใช่อุปกรณ์ iPhone จริง และไม่ใช้การเรียกโมเดลผ่าน Proxy เป็นหลักฐาน
