# RoleForge 0.55.4 · ราคาที่ NPC ยอมรับจากการต่อรองในโรล

อัปเดตส่วนเสริมแล้วรีโหลดหน้า SillyTavern เพื่อโหลดโค้ดและสไตล์รุ่นเดียวกัน

## เคสที่แก้

ผู้เล่นเสนอ:

> งั้นผมขอลดที่ 190 เหรียญทองแดงได้มั้ยครับ ช่วยผมสักนิดเถอะนะ?

AI ส่ง `commerce.action:"offer"` พร้อมหลักฐานประโยคนี้ และ `decision:{outcome:"accept",amount:190}` แต่ไม่ได้ส่ง `commerce.amount` ซึ่งเป็นยอดเสนอของผู้เล่น ตัวตรวจเดิมจึงคืน error `amount` ก่อนบันทึกข้อตกลง และหน้าต่างยังใช้ราคาเดิม 200

ตอนนี้ถ้า AI ลืมยอดเสนอแยก ระบบอ่านราคาจากหลักฐานประโยคผู้เล่นที่ตรวจแล้วว่ามีอยู่จริงในข้อความล่าสุด ต้องเป็นราคาเดียวชัดเจนและแปลงเข้าหน่วยบัญชีได้พอดี ไม่ใช้ราคาจากผลตัดสินของ NPC มาแทนยอดที่ผู้เล่นเสนอ ราคาหลายแบบที่กำกวม ข้อความไม่ระบุราคา ข้อมูลที่ขัดกัน การปฏิเสธ และสมมุติฐานยังไม่เปลี่ยนข้อตกลง

เคสนี้จึงบันทึก **ตกลงราคาแล้ว · 190 ทองแดง · รอยืนยัน** ได้จากคำตอบโรลเดียว ไม่มี API แก้ข้อมูลเพิ่ม เงินและไอเทมยังเดิมจนกดหรือโรลยืนยัน เมื่อตรวจผลยืนยันผ่านจึงหัก 190 ทองแดง พร้อมบันทึกใบเสร็จและสิทธิ์เช่าด้วยยอดเดียวกัน เหตุการณ์ซ้ำไม่จ่ายซ้ำ

ถ้า NPC เสนอ 195 กลับมา ระบบเก็บ 195 เป็นราคาตอบกลับที่ยังรอยินยอม ไม่ถือว่าผู้เล่นเสนอ 195 และไม่หักเงิน หาก NPC ส่ง `accept` พร้อมราคาที่ไม่ตรงกับข้อเสนอจริง ระบบยังปฏิเสธการยอมรับนั้น

เพิ่มคำสั่งให้ AI ส่ง `commerce.amount` ของผู้เล่นแยกจาก `decision.amount` ของ NPC ให้ชัด แม้ทั้งสองยอดเท่ากัน การอ่านหลักฐานรองรับการขายและการบิดประมูลด้วย โดยยังใช้กฎงบ คู่แข่ง และการยืนยันเดิม

## ช่องราคาหลังต่อรอง

ห้องที่ราคาป้าย 2 เงิน แต่ตกลงเป็น 190 ทองแดง ไม่สามารถแสดงด้วยจำนวนเหรียญเงินเต็มได้ ช่องราคาจึงเลือกหน่วยทองแดงและแสดง **190** ให้ตรงกับหัวหน้าต่างและยอดยืนยัน หากผู้เล่นเลือกหน่วยที่แปลงยอดปัจจุบันไม่ลงตัวเอง ช่องจะว่างพร้อมข้อความให้ระบุราคา แทนการสร้างยอด 1 ขึ้นมา

การจ่าย 200 ที่จบไปแล้วเก็บเป็นประวัติเดิม อัปเดตนี้แก้การบันทึกข้อตกลงและการยืนยันครั้งถัดไป ไม่คืนส่วนต่างหรือเปลี่ยนใบเสร็จเก่าย้อนหลังโดยอัตโนมัติ

## ตัวอย่าง UI คลัง

ทำต้นแบบการ์ดสิทธิ์ให้เข้ากับหน้า RoleForge: กรอบเหลี่ยม เส้นเน้นบาง สีตามธีมเดียวกับไอเทมทั่วไป ไอคอนกุญแจ ชื่อและสถานที่อยู่ด้านบน กำหนดคืนเป็นบรรทัดเรียบ และกดขยายดูสิทธิ์/ราคาที่ชำระ/เงื่อนไขได้ สถานะ “ใช้ได้” เป็นป้ายสถานะ ปุ่มขยายมีเครื่องหมายบวก/ลบและรองรับคีย์บอร์ด

**ต้นแบบนี้ใช้เฉพาะหน้าพรีวิว ยังไม่เปลี่ยน UI คลังจริงของส่วนเสริม** เพื่อให้ตรวจหน้าตาก่อน สไตล์ต้นแบบไม่ถูกนำเข้าโดย runtime ตัวอย่างใช้ข้อมูลการทดสอบหลังชำระ 190 และไม่แก้ข้อมูลแชตหรือเรียก API เมื่อกดดูรายละเอียด

## หลักฐานการตรวจ

- Unit/host tests 806 เคสผ่าน พร้อมเคสคำตอบที่ขาด `commerce.amount` ตามรายงาน เคสตอบราคากลับ/ปฏิเสธ การแปลงหน่วย ราคาไม่ตรงหรือกำกวม การขายและประมูล
- Syntax checks ของ runtime
- ผ่าน loader และเหตุการณ์แชตจริงที่ 320, 390 และ 1280px ด้วยคำตอบโมเดลที่ควบคุมไว้: เลือกห้องในโรล ต่อรอง 190 บันทึกข้อตกลงโดยไม่จ่าย กดยืนยันหัก 190 ได้กุญแจและสิทธิ์ที่บันทึกยอด 190 เหตุการณ์ซ้ำไม่ย้อนราคา
- ตรวจแถบซื้อขาย เมนูต่างหน่วยเงิน การเปิด/ปิดซ้ำ และการเก็บหน้าวิชา/ฝึกจากชุดเดิม
- ต้นแบบคลังทั้งย่อ/ขยายอยู่ในกรอบ และการกดดูรายละเอียดไม่เพิ่ม API
