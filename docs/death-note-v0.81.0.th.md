# Death Note — RoleForge 0.81.0

Death Note 0.3.0 เป็น Addon ใน Workshop เปิดเป็นรายแชทได้ มีสมุดเต็มหน้าและหน้ากระดาษเหนือ chatbar การติดตั้งไม่ได้มอบสมุดให้ผู้เล่น ต้องมีสมุดใน Inventory หรือพบแล้วเลือกหยิบในเนื้อเรื่องก่อน

อัปเดตจาก RoleForge 0.80.2 (`8362ec2`) โดยรักษาข้อมูลแชทและ journal ของต้นแบบเดิมไว้ ไม่ต้องนำเข้าการ์ดใหม่เพื่อเปิดใช้ Addon

## สิ่งที่เปลี่ยน

- หน้าจดเป็นกระดาษว่าง แตะหรือคลิกเพื่อพิมพ์ได้ทุกตำแหน่ง เลือกข้อความเพื่อย้ายและปรับขนาด ยืนยันด้วย ✓ หรือยกเลิกเฉพาะการย้ายด้วย × ไม่มีเส้นพาดตัวอักษรหรือช่องกรอกแบบฟอร์ม
- เอา “Design Preview” และ “RoleForge / Fictional World Rules” ออกจากหน้าสมุด
- กติกาเป็นกระดาษดำทั้งเล่ม คอมแสดงสองหน้าคู่ มือถือแสดงทีละหน้า มีลูกศร ⟵ / ⟶ แบบไม่มีกรอบ พร้อม “กลับหน้าแรก” ตัวเล็กทางซ้ายและ “จารึกเพิ่ม” ทางขวา รวม 71 หน้าสรุปทั้งภาษาไทยและอังกฤษ โดยคงเลขอ้างอิงของต้นฉบับที่มีความต่างระหว่างฉบับไว้
- เพิ่มชื่อจริงสีแดงและอายุขัยเดิมเมื่อเปิดดวงตายมทูต แถวรายชื่อบนมือถือขยายให้วันเวลาไม่ถูกตัด
- ใช้ตราหัวกะโหลกจากภาพอ้างอิงบนพื้นโปร่งใสและฟอนต์ลายมือที่เก็บใน repository ไม่โหลดฟอนต์จากภายนอกตอนเปิดสมุด
- ข้อความปุ่มและกติกาเปลี่ยนตามภาษา RoleForge โดยไม่แปลข้อความที่ผู้เล่นเขียนไว้
- เพิ่มการจารึกข้อความกฎลงสมุดและขีดฆ่า พร้อมข้อความเริ่มต้นของกฎปลอมสิบสามวันและกฎทำลายสมุด

[ภาพจาก SillyTavern บนคอมและมือถือ](previews/death-note-v0.81.0/index.html)

## เปิดใช้งาน

1. อัปเดต RoleForge ใน Extensions ให้เป็น 0.81.0 แล้วรีโหลด SillyTavern
2. เปิดแชทที่ต้องการ ไปที่ **RoleForge Workshop → Death Note → ติดตั้ง** หากมีรุ่นก่อนให้กดอัปเดต แล้วเปิดใช้สำหรับแชทนี้
3. เปิดสมุดด้วยปุ่มของ Addon หรือ Wand Menu เลือกปุ่มย่อบนสมุดเมื่อต้องการใช้เหนือ chatbar
4. หากไม่มีสมุดอยู่กับตัว จะเขียนไม่ได้ เมื่อเรื่องยืนยันว่าสมุดอยู่ในฉาก หน้าต่างเหนือ chatbar จะแสดง **แตะปก / หยิบสมุด / ปล่อยไว้** การพบสมุดอย่างเดียวยังไม่ได้สิทธิ์หรือไอเทม
5. แตะบริเวณว่างของกระดาษแล้วพิมพ์ วางชื่อที่ต้องการจดแต่ละชื่อไว้ในบรรทัดของตัวเอง บรรทัดถัดไปใช้ระบุเหตุและรายละเอียดได้ หรือแยกเป็นกล่องข้อความใกล้ชื่อ เช่น `Elias Voss` แล้วบรรทัดต่อไป `หัวใจวาย` และ `ใน 10 นาที` เมื่อมีหมายเหตุแยกกล่อง ระบบจับคู่กับชื่อที่อยู่ใกล้ที่สุด
6. แตะข้อความเพื่อเลือก จะเห็นกรอบบาง ลากกรอบเพื่อย้ายตำแหน่งหรือใช้ slider ปรับขนาด กด ✓ เพื่อเก็บตำแหน่ง/ขนาดใหม่ หรือ × เพื่อคืนตำแหน่ง/ขนาดเดิม ข้อความที่พิมพ์ยังอยู่ การจัดหน้าไม่เรียก AI
7. กด **ยืนยัน / Confirm** ตัวเล็กมุมขวาล่างเพื่อจดเฉพาะข้อความใหม่ในหน้าปัจจุบัน รองรับหลายชื่อใน Continue ครั้งเดียว ข้อมูลไม่ถูกส่งเป็นข้อความ User และเก็บข้อความร่างในช่องแชทไว้
8. ลูกศรหน้ากระดาษพาไปหน้าก่อน/หน้าถัดไปโดยเก็บหมึกเดิมไว้ ระบบบันทึกข้อความและตำแหน่งหลังหยุดแก้ช่วงสั้น ๆ และรอให้บันทึกก่อนปิดหรือเปลี่ยนหน้า ใช้ได้ทั้งสมุดเต็มหน้าและเหนือ chatbar
9. **ล้างทั้งหมด / Clear all** มีการยืนยันในแถบกระดาษ แล้วกลับหน้าแรกพร้อมกระดาษว่าง ผลตาย รายชื่อที่ยืนยัน และเหตุการณ์ในเรื่องยังอยู่ การล้างไม่ยกเลิกชื่อที่กำลังรอเวลาในเรื่อง

ชื่อปลอมไม่ทำให้ตัวจริงตาย ระบบไม่เฉลยความถูกต้องก่อนเขียน เวลา 40 วินาทีและเวลานัดหมายเป็น **เวลาในเรื่อง** ผลต้องผ่านข้อมูลตอบกลับและหลักฐานที่ตรวจได้จากคำตอบ AI ไม่ใช่ตัวจับเวลาจริงที่แอบส่งข้อความเอง

## ใบหน้าที่จำได้

ไม่มีช่องติ๊กยืนยันใบหน้าบนกระดาษ ตรวจสถานะได้ใน **NPC Management → เปิดข้อมูล NPC → Death Note · การจดจำใบหน้า** ชื่อที่รู้จักกับใบหน้าที่เคยเห็นเป็นข้อมูลแยกกัน

การ์ดกำหนดค่าเริ่มต้นด้วย `knownFaces` ได้ บทที่ยืนยันว่าเห็นใบหน้าหรือภาพถ่ายชัดเจนจะเพิ่มหลักฐานผ่านเหตุการณ์ `face-seen` ส่วนการเพียงบอกชื่อ การปิดบังใบหน้า หรือสัญญาว่าจะเปิดหน้าในอนาคตยังไม่เพียงพอ การ์ดเดิมที่ไม่มีค่านี้ใช้ `met` ของ RoleForge เป็นหลักฐานเดิม ยกเว้นมีข้อมูลว่าปิดบังใบหน้า

## ดวงตายมทูต

ผู้เล่นต้องเป็นเจ้าของสิทธิ์ สัมผัสสมุด และมีข้อมูลยมทูตที่ผูกกับเล่มนั้น จึงเปิดหน้า **สิทธิ์ → ข้อแลกเปลี่ยนกับยมทูต** แล้วกดยืนยันได้ การกดอ่านข้อเสนอเฉย ๆ ไม่มีต้นทุน

เมื่อแลกแล้ว:

- ชื่อที่รับรู้ยังคงอยู่ เช่น `??? (Mara Hale)` หรือ `Victor Lane (Hidden Real Name)` ส่วนชื่อจริงแสดงเป็นสีแดงใน NPC Management และ Header ที่ใช้ตัวแสดงชื่อ NPC ของ RoleForge
- เห็นชื่อจริงเฉพาะมนุษย์ที่ยังมีชีวิตและเคยเห็นใบหน้า ไม่เปิดชื่อของ NPC ที่ยังไม่เคยพบหรือของยมทูต
- แสดงวันเวลาอายุขัยเดิมใต้ชื่อเมื่อการ์ดกำหนดข้อมูลนั้นไว้ อายุขัยนี้ไม่เปลี่ยนตามกำหนดตายที่เขียนลงสมุด และไม่แสดงอายุขัยของตนเองหรือเจ้าของ Death Note คนอื่น
- ได้ข้อได้เปรียบด้านการมองเห็นตามกฎในเรื่องผ่านคำสั่งบริบทของ AI ไม่ใช่การอ่านใจหรือรู้ข้อมูลที่ไม่เคยเห็น
- จ่ายครึ่งหนึ่งของ **อายุขัยที่เหลือ ณ เวลาที่แลก** เมื่อมีเส้นตายตามวันในเรื่อง ระบบคำนวณและบันทึกเส้นตายใหม่จริง หากยังไม่มีข้อมูลอายุขัย จะเก็บสัดส่วนต้นทุนโดยไม่แต่งวันตายขึ้นเอง

การสละสิทธิ์เล่มสุดท้ายทำให้ดวงตาและความทรงจำเรื่องสมุดหายไป แต่ไม่คืนอายุขัย การแลกใหม่หักครึ่งจากส่วนที่ยังเหลือหลังเวลาผ่านไป ผู้ยืมสามารถเขียนได้เมื่อถือสมุด แต่แลกดวงตาแทนเจ้าของไม่ได้

## กฎปลอม

ขณะถือสมุด เปิด **กติกา → จารึกเพิ่ม** แล้วเลือกข้อความเริ่มต้นหรือเขียนเอง ข้อความจะกลายเป็นหน้าใหม่ท้ายเล่ม ไม่มีป้ายเฉลย “กฎปลอม” ในหน้าที่ตัวละครอ่าน และขีดฆ่าได้โดยยังเก็บประวัติไว้

ข้อความที่จารึกเพิ่มไม่ใช่กฎจริงของกลไก NPC อาจเชื่อเมื่อได้อ่านในเรื่อง แต่การเขียนว่าไม่ฆ่าคนสิบสามวันแล้วผู้ใช้จะตาย หรือทำลายสมุดแล้วผู้สัมผัสทุกคนจะตาย ไม่สร้างตัวจับเวลา ไม่ลด HP และไม่เปลี่ยนเจ้าของสิทธิ์ ระบบกรองผลตายที่ AI ระบุว่ามาจากกฎจารึกนั้น การตายจากเหตุอื่นยังติดตามได้ตามปกติ

AI สามารถเสนอหน้ากฎที่ NPC เขียนหรือผู้เล่นอ่านเจอผ่านข้อมูลเหตุการณ์พร้อมข้อความหลักฐานที่ปรากฏในเรื่อง ระบบเก็บเป็นข้อความในสมุดเสมอ ไม่รับคำประกาศของ AI ว่าเป็นกฎใหม่ที่มีอำนาจจริง

## ข้อมูลสำหรับผู้สร้างการ์ด

ใช้ ID เดียวกับ NPC และ Inventory ของ RoleForge ตัวอย่างส่วน `data.extensions.roleforge_death_note`:

```json
{
  "format": "roleforge-death-note-rules",
  "version": 1,
  "canon": "manga",
  "trueNames": {
    "npc-mara": "Mara Hale"
  },
  "knownFaces": { "npc-mara": true },
  "originalLifespans": {
    "npc-mara": { "day": 9000, "date": "2050-04-18", "time": "23:40" },
    "player": { "day": 30000, "time": "20:15" }
  },
  "books": [
    {
      "bookId": "black-notebook",
      "itemId": "black-notebook",
      "originalShinigamiId": "npc-ryuk",
      "firstHumanOwnerId": "player",
      "ownerId": "player",
      "holderId": "player"
    }
  ]
}
```

- หากไม่ระบุ `trueNames` จะใช้ชื่อในบันทึก NPC เป็นชื่อจริง ชื่อที่ NPC กล่าวอ้างเก็บแยกตามแชทและไม่เปลี่ยนชื่อหลักในคลัง
- `day` นับวันในเรื่องแบบเดียวกับ World Clock ใช้คำนวณต้นทุนดวงตา ส่วน `date` เป็นป้ายวันที่ตามปฏิทินของโลกนั้นที่ผู้สร้างกำหนด การระบุวันและเวลาไม่เกี่ยวกับอายุขัยของบุคคลจริง
- ข้อมูลอายุขัยที่ไม่มีหรือไม่ถูกต้องจะไม่ถูกแทนด้วยวันที่สุ่ม ตัวละครที่เป็นเจ้าของสมุดยังไม่แสดงอายุขัยแม้กำหนดไว้
- Inventory ที่ถือสมุดควรมี `quantity` มากกว่า 0 และ `properties: ["roleforge:addon:death-note"]` การประกาศเจ้าของสิทธิ์ใน config อย่างเดียวไม่สร้างไอเทมในมือ
- ใช้ `canon: "a-kira"` เมื่อโลกเล่นตามช่วงตอนพิเศษที่เพิ่มกฎซื้อขายสมุด ค่าเริ่มต้นใช้ยุคมังงะหลัก

## โครงสร้างใน repository

โค้ดใช้งานจริงอยู่ใน `src/workshop/death-note/`: `core.js` ตรวจการจดชื่อและผล, `world.js` เก็บเหตุการณ์และสิทธิ์, `eyes.js` ตรวจข้อมูลดวงตา, `rules.js` เก็บหน้ากติกา, `ui.js` แสดงสมุดและต่อ SillyTavern ส่วน `paper.js` เก็บหน้า/ข้อความและจับคู่คำสั่ง, `paper-editor.js` รับการเขียนและลาก, `faces.js` ตรวจหลักฐานใบหน้า, `strings.js` และ `rules-en.js` เก็บข้อความภาษาอังกฤษ หน้าตาอยู่ใน `styles/death-note.css` แพ็กที่ Workshop ตรวจ hash อยู่ใน `src/workshop/packs/death-note-0.3.0.json`

หน้าสมุดใช้ Shadows Into Light Two และ Mali ใน `assets/workshop/death-note/` พร้อมใบอนุญาต OFL ส่วนปุ่มและข้อความระบบยังใช้ฟอนต์ร่วมใน `assets/chat-fonts/` ไม่มีการคัดลอกฟอนต์เดิมซ้ำ ไม่โหลดโค้ด Addon จากภายนอก และไม่มี runtime import จากโฟลเดอร์ต้นแบบ ข้อมูลเปลี่ยนแปลงเก็บใน journal ของข้อความตามจุด Continue / Swipe จึงไม่ขนเหตุการณ์ท้ายแชทไปยัง Branch ก่อนหน้า

ชื่อคีย์ journal เดิมที่ลงท้าย `_preview` คงไว้เพื่ออ่านข้อมูลจากต้นแบบ รุ่นใช้งานจริงไม่มีป้าย Preview ในหน้าสมุด

`index.js` เชื่อมการบันทึกผลและกรอง patch, `src/workshop/native.js` เชื่อม Workshop/Continue, `src/npc-visibility.js` แยกชื่อที่ผู้เล่นรับรู้จากข้อมูลจริง ส่วน `src/npc-workspace.js`, `src/npc-chat.js` และ `styles/npc-ui.css` แสดงชื่อจริง/อายุขัย/ข้อมูลใบหน้า การเปลี่ยนไฟล์ระบบอื่นส่วนใหญ่เป็น cache version ของ import ให้ตรงกับ 0.81.0
