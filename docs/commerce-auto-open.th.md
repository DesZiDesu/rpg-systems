# v0.51.2 — เปิด UI อัตโนมัติและแก้ผลประมูล

## สาเหตุที่ตรวจพบในโค้ด

- ตัวจับคำขอร้านค้าและประมูลทำงานแยกกัน คำว่า “สินค้า/รายการ” ในคำขอประมูลจึงเรียกร้านค้าด้วย
- การแจ้งรายละเอียดขาดดูเฉพาะการ์ดในข้อความล่าสุด จึงไม่เห็นรายการที่ยังเปิดอยู่ใน composer และคำเตือนเก่าถูกคัดลอกไปยังข้อความที่ต่อเพิ่ม
- prompt ยังขอรายการใหม่แม้กำลังเจรจา และตัวอย่างผล AI ใส่ participants ว่าง ทั้งที่กติกาต้องมีการตัดสินใจของ NPC ที่ยังแข่งขันครบคน
- ตัวอ่านผลรับเฉพาะ ID/ชื่อฟิลด์รูปแบบเดียว และรายงานข้อผิดพลาดหลายประเภทว่า “ผู้ประมูลไม่ครบ” จึงแยกสาเหตุไม่ได้
- ลำดับ NPC ใน JSON เคยกำหนดลำดับการบิด ทำให้รายการบิดพร้อมกันที่เรียงราคาสูงก่อนต่ำถูกปฏิเสธ

ภาพของผู้ใช้แสดงอาการตรงกับเส้นทางเหล่านี้ แต่ไม่ได้มี raw response ของ API เดิม จึงไม่อ้างว่าทราบรูปแบบคำตอบที่ผิดพลาดในแต่ละรอบของผู้ใช้แน่นอน

## Flow ใหม่

ส่งข้อความอยากซื้อ ขาย หรือประมูลในแชต → แถบเหนือช่องพิมพ์ขึ้นสถานะรอทันที → NPC ตอบพร้อมรายการ/ราคา → แถบแสดงรายละเอียดและปุ่ม โดยไม่มีขั้นตอนกดเตรียมข้อความขอดูรายการ

ประมูลกด Bid จากรายการเริ่มต้นได้เลย การบิดครั้งแรกถือเป็นการเข้าร่วมพร้อมค่าเข้าและมัดจำที่แจ้งไว้ ค่าเข้า/การบิดจะถูกบันทึกต่อเมื่อผล AI ผ่านการตรวจครบ หากอยากเข้าร่วมโดยยังไม่บิด มีทางเลือกในรายละเอียดที่ขยายออก รอการตัดสินใช้งานได้หลังเข้าร่วม

การโรลในแชตกับปุ่มใช้ engine เดียวกัน การโรลใช้คำตอบหลักหนึ่งครั้ง ปุ่มใช้ native quiet API หนึ่งครั้งและต่อข้อความ NPC เดิม รายการหายเมื่อจบ ไม่มีการสร้างคำสั่งแทนผู้ใช้หรือข้อความ NPC สำเร็จรูป

## อ่านคำตอบให้ยืดหยุ่นโดยรักษาการตัดสินใจจริง

รับ ID เดิมหรือชื่อ NPC ที่ตรงและไม่กำกวม, choice/motive และชื่อฟิลด์เทียบเท่า, จำนวนเต็มที่ส่งเป็นข้อความ, JSON ใน code fence และคำตอบปกติที่มี hidden commerce decision การบิดพร้อมกันประเมินจากราคาต่ำไปสูงโดยไม่แก้จำนวนเงินหรือเหตุผลที่ AI เลือก

NPC ยังใช้เงินจริงที่กำหนดไว้ตั้งแต่ต้น AI เลือกบิด ผ่าน ถอนตัว ทุ่มเงินหรือปิดประมูลเอง ไม่มีเพดานตามเงิน user หรือจำนวนครั้งที่บังคับให้ user ชนะ หากผลขาด NPC/เหตุผล ไม่รู้จักผู้ประมูล เกินงบ หรือไม่ตรงความยินยอม รอบนั้นไม่เปลี่ยนเงินหรือของ และแจ้งสาเหตุเฉพาะพร้อมชื่อ NPC ที่ขาดเมื่อระบุได้ ไม่มีการเติมการผ่านประมูลแทน NPC

## การตรวจสอบ

ผ่าน unit/host 577 tests และ syntax checks รวมรูปแบบคำตอบต่างกัน, การบิดจาก offered, rollback ค่าเข้าเมื่อคำตอบไม่ครบ, งบจริง, consent, once-only receipts และคำเตือนร้านค้าเก่าหลัง reload พร้อม browser ผ่าน production loader ที่ 320/390/1280px สำหรับปุ่มและโรล ซื้อ/ขาย/ประมูล และเปิดแถบรอก่อน NPC ตอบ ตรวจระบบเสริม เรื่องราว/รางวัลและการแสดงผลร่วมกับ regex

การทดสอบใช้ host จำลองและคำตอบ provider จำลอง รวมหลายรูปแบบที่ parser ต้องรองรับ ไม่ได้เรียก API/provider ของผู้ใช้หรือเข้าถึงหน้า SillyTavern จริงของผู้ใช้ การตอบตามสัญญาของโมเดลภายนอกยังต้องตรวจในแชตจริงหลังอัปเดต จึงไม่รับรองว่าทุก provider จะส่งข้อมูลครบ 100%
