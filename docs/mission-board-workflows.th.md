# Mission Board และการแจ้งเตือน — v0.45.1

อัปเดตส่วนเสริมจาก GitHub แล้วรีโหลด SillyTavern หนึ่งครั้ง ไม่ต้องล้างข้อมูลเก่า เปิด Auto tracking และ Inject RPG state เพื่อให้ AI ได้รับคำสั่งและส่งข้อมูลติดตามในคำตอบปกติ

## Workflow: อ่านกระดานและรับภารกิจ

1. เล่นโรลว่าตัวละครเดินไปถึงกระดาน เช่น “ฉันเดินเข้าโถงกิลด์ ไปยืนอ่านกระดานภารกิจ”
2. AI เล่าเหตุการณ์และสร้างภารกิจให้เข้ากับสถานที่ โลก และความสามารถของตัวละคร จำนวน 1–4 ภารกิจ ข้อมูลส่งมาพร้อมคำตอบเดิม ไม่เรียก API เพิ่มสำหรับกระดาน
3. กระดานแสดงท้ายข้อความ AI ใน Main Chat แม้ปิดการจัดรูปแบบบทสนทนา NPC อยู่ แต่ละครั้งต้องยืนยันว่าอยู่ที่กระดานจริง การพูดถึงกระดานเฉย ๆ การวางแผนไปพรุ่งนี้ หรือถาม OOC ไม่ควรสร้างกระดาน
4. แตะกระดาษเพื่อเปิดชื่อ รายละเอียด เป้าหมาย ผู้ว่าจ้าง รางวัล ความยาก กำหนดเวลา และขั้นตอนภารกิจ ถ้ามีข้อมูลนั้น AI ไม่ต้องแต่งวันครบกำหนดหรือระดับความยากเมื่อไม่ได้กำหนดไว้
5. กด **ย้อนกลับ / Back** เพื่อเลือกใบอื่น ขณะอ่านยังไม่เพิ่มลง Quest Log และยังไม่คิดว่าได้รับงานแล้ว
6. กด **รับภารกิจ / Accept mission** ระบบเพิ่มงานที่เลือกเป็น Active ใน Quest Log โดยใช้ ID คงที่ ขั้นตอนเริ่ม Pending และ progress เริ่ม 0
7. ระบบแจ้งการรับภารกิจตามการตั้งค่า notifications ปุ่มของงานที่อยู่ในบันทึกแล้วรับซ้ำไม่ได้ การรับไม่แจกเงิน EXP หรือไอเทม
8. พิมพ์เล่นต่อ เช่น “ฉันนำใบภารกิจส่งให้เสมียน แล้วถามว่าจะรับยาได้จากที่ไหน” AI จะเห็นภารกิจ Active จากสถานะที่แนบในเทิร์นถัดไป ปุ่มรับบันทึกทันทีในเครื่องและแชต โดยไม่สั่งให้ AI เจนคำตอบใหม่เอง
9. ทำเป้าหมายในเรื่อง ระบบติดตามขั้นตอนด้วย Quest Objectives เดิม การจ่ายรางวัลต้องมีเหตุการณ์รับรางวัลที่ยืนยัน และยังใช้ระบบป้องกันจ่ายซ้ำจากเควสเดียวกัน

กระดานต้องมาจาก structured patch ที่ถูกต้องของ AI หากได้แต่ข้อความบรรยายโดยไม่มีข้อมูลกระดาน ส่วนเสริมจะไม่เดาชื่อภารกิจจากข้อความเอง ลองเล่นต่อให้ AI แสดงประกาศที่อ่านได้ชัดเจน ตรวจว่า Auto tracking เปิดอยู่ และโมเดลไม่ได้ตัดคำตอบก่อนส่ง patch ครบ

### ข้อมูลและการเปลี่ยนแชต

- กระดานเก็บใน metadata ของแชตและผูกกับเวอร์ชันคำตอบต้นทาง โหลดใหม่ยังอ่านได้
- รับได้จากกระดานล่าสุดที่สถานที่ตรงกับตำแหน่งปัจจุบันเท่านั้น กระดานเก่ายังเปิดดูได้ แต่ต้องกลับไปกระดานปัจจุบันเพื่อรับงาน
- ระหว่าง AI กำลังเจน รับงานไม่ได้ เพื่อป้องกันสถานะสองชุดเขียนทับกัน
- เปลี่ยน swipe หรือลบ/เปลี่ยนข้อความต้นทางแล้ว กระดานและสถานะติดตามจะยึดเวอร์ชันเรื่องที่ใช้งานอยู่ ปุ่มที่ค้างจากแชตอื่นใช้เปลี่ยนแชตใหม่ไม่ได้
- บันทึกการรับงานไม่สำเร็จ ระบบแจ้งปัญหาและคืนสถานะก่อนรับเพื่อให้ลองใหม่ ไม่แสดงว่างานรับแล้วทั้งที่การบันทึกล้มเหลว
- กำหนดเวลาบนใบเป็นข้อมูลเรื่อง ไม่ตัดสินว่างานล้มเหลวหรือรับเงินอัตโนมัติ การนัดหมาย/เส้นตายยังใช้ระบบ Appointments แยกตามเหตุการณ์ที่ยืนยัน
- กระดาษเก็บอยู่ในแชตเดิม ภารกิจที่รับแล้วเป็น RPG state จึงส่งต่อด้วย Continuity และ Export/Import สถานะตามระบบเดิม

## Workflow: การแจ้งเตือนฝึก ซื้อของ และไอเทม

1. ไปที่ **Extensions → RoleForge → Notification events** เปิด Show RPG event pop-ups over the main chat
2. เลือกประเภทที่อยากเห็น: สกิลใหม่, การฝึกและพัฒนาสกิล, ไอเทมเข้าและออก, การซื้อของ รวมถึง EXP เงิน เลเวล และภารกิจที่มีอยู่เดิม
3. เล่นเหตุการณ์ เช่น ฝึกดาบ ซื้อยา เก็บสมุนไพร ดื่มยา ขายของ หรือเรียนสกิลใหม่
4. AI ส่งการเปลี่ยนแปลงพร้อมคำตอบปกติ เช่น ซื้อยาสองขวดต้องมีทั้งเงินที่จ่ายและยาเข้ากระเป๋า พร้อมเหตุผลของเหตุการณ์
5. ระบบตรวจ patch บันทึกสถานะ แล้วเปรียบเทียบก่อนและหลัง จึงแสดงชื่อของ จำนวนเพิ่ม/ลด ชื่อสกิล และความชำนาญที่เปลี่ยนจริง
6. การอัปเดตคำอธิบายสกิลเดิมไม่ขึ้นว่าเรียนรู้ใหม่ สกิลที่มีอยู่แล้วเปลี่ยน rank/proficiency ใช้การแจ้งเตือนพัฒนาสกิล การฝึกความชำนาญ 99 → 100 แสดง +1% แม้ AI ส่งเพิ่ม 5
7. ซื้อของที่มี category purchase แสดงการซื้อของ เงินที่จ่ายยังแสดงในประเภทเงินด้วย เพราะมีทั้งไอเทมและธุรกรรม ไอเทมจาก loot/gift แสดงไอเทมเข้า การใช้/ขาย/ทิ้งจนหมดแสดงไอเทมออก
8. หากมีหลายเหตุการณ์ ระบบแสดงได้พร้อมกันสูงสุด 4 ใบ ที่เหลือรอคิว กดปิดหรือรอครบเวลาจะเห็นใบถัดไป เปลี่ยนแชตแล้วคิวของแชตเก่าจะถูกล้าง
9. ปรับระยะเวลา pop-up ได้ใน settings ประวัติไอเทมและธุรกรรมเดิมยังดูย้อนหลังได้

notifications ชุดนี้ติดตามผลที่บันทึกจากเรื่อง ไม่แจกความชำนาญหรือของเอง และไม่เรียก API เพิ่ม จำนวนไอเทมใช้ผลรวมก่อน/หลังของเทิร์นนั้น ถ้าได้รับแล้วใช้หมดในเทิร์นเดียวจนยอดสุทธิไม่เปลี่ยน จะไม่มีใบจำนวนเข้าออกสุทธิ การแจ้งเตือนการฝึกต้องมีผลเติบโตที่บันทึก เช่น EXP ความชำนาญ หรือค่าฝึกที่รองรับ ความพยายามที่ยังไม่มีผลยืนยันไม่เพิ่มค่าเอง

Custom Power แบบ rank แจ้งชื่อและระดับที่เปลี่ยน แบบ number ที่มีเหตุผล training แจ้งจำนวนเพิ่ม การเติม resource หรือสลับโหมด toggle ไม่ถูกตีความเป็นการฝึก

## NPC ที่สร้างเองเปลี่ยนเป็น Hostile ได้ไหม

ได้อยู่แล้ว จึงไม่ได้แก้พฤติกรรมส่วนนี้

1. สร้าง NPC ตามปกติ เปิดให้ AI ใช้งาน และไม่ติ๊ก Hostile
2. เล่นเรื่องต่อ ถ้า NPC กลายเป็นศัตรูอย่างชัดเจน AI สามารถส่ง upsert ของ NPC ID เดิม พร้อม `isHostile: true`
3. ระบบเก็บตัวละครเดิมพร้อมประวัติ รูปลักษณ์ และข้อมูลอื่นไว้ใน NPC Management แต่เอาออกจากรายชื่อฝั่งมิตร
4. ถ้าเรื่องยืนยันการคืนดี AI เปลี่ยนเป็น `isHostile: false` ได้เช่นกัน

การไม่ติ๊ก Hostile หมายถึงสถานะเริ่มต้น ไม่ใช่การล็อกให้เป็นมิตรตลอดไป หากปิด NPC ไม่ให้ AI ใช้งาน การอัปเดตบางประเภทจะถูกกันตามระบบเดิม ความสามารถในการส่ง patch ถูกทดสอบแล้ว แต่ AI จะตัดสินใจส่งเมื่อใดยังขึ้นกับเหตุการณ์และโมเดลที่ใช้
