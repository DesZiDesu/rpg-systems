# ไอเทมหลายสเตตัสและ Loot — RoleForge 0.57.0

อัปเดตจาก main `4b31ba816dfe27071bc32e858a260fe8b4972f78` วันที่ 5 ตุลาคม 2026

## สาเหตุที่พบ

- ระบบใช้ไอเทมเดิมอาศัยผลที่ AI ส่งเป็น `meters` เพียง HP/MP/stamina/hunger/thirst ไม่มีนิยามผลต่อหนึ่งชิ้นสำหรับสเตตัสอื่น และตัว normalize ตัด HP ที่เกิน max จึงรักษา 120/100 ไว้หลังบันทึกไม่ได้
- ร้านค้าและของประมูลมีจุดที่ส่งต่อเฉพาะชื่อ หมวด และคำอธิบาย คุณสมบัติการใช้งานจึงอาจหายเมื่อรับเข้าคลัง
- Loot เดิมต้องมีชื่อไอเทมทุกชิ้นในคำยืนยันเดียวกัน การยืนยันว่า “สังหารก็อบลิน 4 ตน” จึงไม่พอสำหรับรายการของที่ AI ออกแบบให้ศพนั้น และจำนวนชนิดข้อความ เช่น `"4"` ไม่ผ่านเงื่อนไขจำนวนเต็ม ทำให้เกิดคำเตือนในภาพ ส่วนคำตอบที่ไม่มี Loot เลยก็ไม่มีเส้นทางเติมข้อมูล
- โฮสต์สร้าง timestamp บางส่วนเมื่ออ่าน NPC เก่า การเทียบ state แบบตรงทั้งหมดทำให้ผลซ่อม Loot ที่ถูกต้องถูกมองว่าล้าสมัย อีกทั้งคำขอเสริมต้องกั้นเหตุการณ์ประมวลผลคำตอบซ้อนกัน

## พฤติกรรมใหม่

**ไอเทม:** นิยามร่วมใช้กับคลัง Loot ร้านค้า และประมูล มี description, category, rarity, properties และ usage ครบ รวมวิธีใช้ การลดจำนวน ผล เงื่อนไข เป้าหมาย cooldown charges และ stats ต่อหนึ่งชิ้น AI ได้รับคำสั่งให้ออกแบบรายละเอียดและจำนวนผลที่เหมาะกับโลกในคำตอบนั้นทันที ข้อมูลธรรมดาที่ตกหล่นมีค่าโครงสร้างสำรองและผลพื้นฐานตามประเภท อาทิ น้ำ อาหาร และโพชั่น ส่วนของเก่าที่ระบุชัดว่าไม่ทราบคุณสมบัติยังต้องตรวจสอบหรือกำหนดก่อนใช้

แสดงผลสเตตัสบนหน้าหลักไอเทมและหน้าสินค้าที่เลือกโดยไม่ต้องกดขยายรายละเอียด ปุ่ม “กำหนดคุณสมบัติไอเทม” ตั้งได้หลายผลต่อชิ้น ทั้งเพิ่ม/ลดตัวเลข กำหนดข้อความ/ค่าบูลีน สเตตัสที่มีในผู้เล่น พลัง custom ที่มีอยู่ EXP และชื่อเสียง การตั้งค่าทำในเครื่อง ไม่เรียก AI ไม่ใช้ของ และไม่รีเซ็ตจำนวน charge หรือประวัติ cooldown

การกดใช้และการใช้ที่ยืนยันในแชทผ่านเครื่องคิดผลเดียวกัน การปฏิเสธ/ล้มเหลวไม่ลดของหรือเพิ่มสเตตัส ผลที่กำหนดไว้ไม่ถูกบวกซ้ำจาก meters หรือ ops ของ AI แต่ยังรับความเสียหายแยกจากการต่อสู้ได้ ผลที่ตั้งเองคงอยู่เมื่อ AI อัปเดตรายละเอียด

ตัวอย่างพายเค้ก: ความอิ่ม +30, HP +20 และสตามิน่า +20 แบบเกินเพดาน 3 เทิร์น เมื่อเต็มจะได้ 120/100 โดย base max ยังเป็น 100 บัฟบันทึกใน chat metadata และหมดตามเทิร์นคำตอบหรือเวลาในเรื่องที่เลือก หากได้รับความเสียหาย การหมดบัฟจะไม่ฮีลกลับ ส่วนยาอีกชนิดสามารถเพิ่มน้ำในร่างกายและกำหนด powerType เป็น Divine Mana ได้ในชิ้นเดียว Hunger/thirst ยังคงอยู่ในช่วง 0–100

**ร้านค้า/ประมูล:** เก็บและส่งต่อ usage/stats/rarity/properties จนถึงของที่ชนะหรือซื้อแล้ว รวมของที่ส่งมอบผ่านสัญญาสิทธิ์/บริการ ไอเทมชื่อเหมือนกันแต่คุณสมบัติต่างกันเก็บแยก ไม่เขียนทับสูตรของเดิม การดูสินค้าไม่เพิ่มสเตตัส ซื้อแล้วต้องใช้ไอเทมจึงเกิดผล

**Loot:** คำตอบหลักต้องสร้างของที่ยังไม่เก็บหลังชนะการต่อสู้ สังหารศัตรู หรือพิชิตดันเจี้ยน และพิจารณาหีบ กล่อง ตู้ ถุง ชั้นหนังสือ โต๊ะ ลิ้นชัก ซาก ศพ รัง แท่นบูชา สมุนไพร เหมือง การตกปลาและเก็บเกี่ยว การสำรวจอาจว่าง ไม่ถือแผนอนาคต การต่อสู้ที่ยังไม่จบ เปิดหีบไม่สำเร็จ การเกือบตาย เหตุการณ์เก่า หรือ OOC เป็นการได้ Loot

หลักฐานสามารถยืนยันแหล่ง/เหตุการณ์ที่เกิดจริงได้ โดยไม่บังคับให้คำยืนยันสั้น ๆ ระบุชื่อของที่ออกแบบใหม่ทุกชิ้น รับจำนวนข้อความที่เป็นเลขจำนวนเต็มบวก แต่ไม่เปลี่ยน null/ไม่ทราบให้กลายเป็นจำนวนเดา ตรวจและคงรายการที่ถูกต้องเมื่อบางรายการไม่ผ่าน ไม่นับของที่รับเป็นรางวัลหรือซื้อเข้าคลังแล้วเป็น Loot อีก

ข้อมูล Loot ที่ถูกต้องในคำตอบหลักไม่เรียก API เพิ่ม หากเหตุการณ์เข้าเกณฑ์แต่ข้อมูลขาด/ผิด จะขอ AI ซ่อมผ่านการเชื่อมต่อปัจจุบันพร้อมแจ้งและนับคำขอ ผลซ่อมรวมถึงเหตุผลของแหล่งว่างถูกบันทึก ป้องกันตรวจคำตอบเดิมซ้ำ ใช้ sourceId คงที่เพื่อไม่เติมแหล่งเดิมที่เก็บหมด และทิ้งผลคำขอที่แชท/ตัวละคร/คำตอบหรือ state เปลี่ยนระหว่างรอ ผลที่ตรวจไม่ผ่านไม่เพิ่มของเข้าคลัง
