# v0.51.7 — ตรวจหลักฐานโรลที่รูปแบบต่างกัน

เคสที่รายงานเป็น `channel:roleplay`, `action:bid`, `error:evidence` โดย AI ส่งราคา `amount:100, denomination:silver` ตามอัตรา 1 ทอง = 100 เงินถูกต้องแล้ว แต่ยังใช้ราคาปัจจุบันเดิม 10 เงินในหน้าต่าง เพราะหลักฐานไม่ผ่านก่อนถึงขั้นปรับราคา

## สาเหตุ

เดิมใช้ `userText.includes(evidence)` กับข้อความที่ trim เท่านั้น เครื่องหมายคำพูดตรง `"` จึงไม่เท่ากับ `“”` และบรรทัดว่างระหว่างบทพูดกับการโรลไม่เท่ากับช่องว่างที่ AI รวมมาใน evidence เช่น:

ข้อความผู้เล่น:

```text
"1 เหรียญทอง"

ฉันชูป้ายก่อนจะเอ่ยขึ้นเบาๆแบบไม่แสดงใบหน้าเพราะเงามันทับช่วงหน้าผากไม่ให้เห็นดวงตา
```

AI ส่งหลักฐาน:

```text
“1 เหรียญทอง” ฉันชูป้ายก่อนจะเอ่ยขึ้นเบาๆ
```

อีกจุดคือ validator ของ action bid รู้จัก `ยกป้าย` แต่ยังไม่รู้จัก `ชูป้าย` เมื่อ evidence มีทั้งบทพูดและการกระทำจึงไม่ได้เป็นเพียงราคาสั้น ๆ และอาจถูกปฏิเสธที่ขั้น intent ต่อ

## การแก้

- เปรียบเทียบหลักฐานโดย normalize Unicode, รูปแบบ quotation marks และช่องว่าง/บรรทัดเท่านั้น แล้วตรวจว่าเป็นข้อความต่อเนื่องจาก user ล่าสุดจริง
- คงคำ ราคา หน่วยเงิน คำปฏิเสธ และเงื่อนไขไว้ ไม่ใช้ fuzzy matching ไม่เปลี่ยนคำกริยา และไม่เติมการยินยอม
- รับทั้ง `ยกป้าย` และ `ชูป้าย` ประกอบราคาเป็นสัญญาณบิด ยังตรวจ session/revision, ราคา, เงินและผลตัดสินคู่แข่งตามเดิม
- สอน prompt ให้คัดลอกหลักฐานสั้นจากข้อความเดิม เช่น `1 เหรียญทอง` โดยไม่เปลี่ยนหลักฐานเป็น 100 เงินตาม amount ที่แปลงแล้ว
- คำตอบปกติเดียวทำรายการได้ ไม่เพิ่ม API task หรือเขียนคำพูดผู้เล่นให้ใหม่

## ตรวจสอบ

เคสที่รายงานผ่านด้วย evidence ที่ใช้ smart quotes รวมสองย่อหน้าเป็นช่องว่าง และใช้คำว่าชูป้าย ราคาใน session เปลี่ยนจาก 10 เงินเป็น 100 เงิน และผู้เล่นเป็นผู้เสนอสูงสุด คิดค่าเข้าตาม fixture ครั้งเดียวและยังไม่จ่ายราคาของจนกว่าปิดประมูล

ข้อความซื้อ/ขายที่ต่างเพียง quotation marks กับบรรทัดผ่านได้เช่นกัน ส่วนเปลี่ยนราคา เปลี่ยนการกระทำ ทำหลักฐานปลอม สมมุติ และปฏิเสธยังไม่ผ่านและไม่เปลี่ยนเงิน/ของ

ผ่าน 669 unit/host tests และ production-loader browser ที่ 320/390/1280 px รวม normal/swipe/regenerate, mixed currency, role-play/buttons, baskets และ settings การทดสอบใช้คำตอบ provider จำลองและไม่ได้เรียกบัญชี API ของผู้ใช้

อัปเดตและ reload หน้าเพื่อโหลด v0.51.7 ข้อมูลเดิมคงอยู่ การ swipe/regenerate คำตอบที่เคยถูกปฏิเสธจะประเมินข้อมูลใหม่ด้วย validator ที่แก้แล้ว โดยยังต้องใช้ session/revision ปัจจุบัน ไม่มีการนำ diagnostic เก่ามาคิดเงินย้อนหลัง

รุ่นนี้แก้พฤติกรรมเท่านั้น หน้าต่าง commerce ยังใช้ดีไซน์เดิม ต้นแบบ UI ใหม่จะนำมาใช้หลังผู้ใช้เลือก
