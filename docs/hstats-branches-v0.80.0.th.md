# H-Stats ที่เลือกและสถานะ ณ จุด Branch — RoleForge 0.80.0

## H-Stats

เหนือ chatbar ใช้แบบแฟ้มสายสัมพันธ์ที่ผู้ใช้เลือก: พื้น charcoal, เส้นสี champagne gold, ภาพ NPC จากคลังภาพเดิม, ค่าความผูกพันขนาดใหญ่, Interest / Trust / Commitment, ผู้ที่ผูกพันและสนใจมากที่สุด และสี่หน้า สัมพันธ์ / ร่างกาย / บันทึก / ความชอบ ปุ่มตั้งค่าเปิดกติกาและตัวแก้ไขเดิม การเปลี่ยนคนและคู่ความสัมพันธ์ใช้รายการค้นหาภายในแผง

ในหน้าต่าง RoleForge คงโครงสร้างเดิม ได้แก่ รายชื่อตัวละคร แผงประจำตัว หมวดร่างกาย แท็บความสัมพันธ์ และแบบฟอร์ม ปรับเฉพาะสี เส้นกรอบ และปุ่มให้เข้ากับ RoleForge เมื่อขยายจากแผงเหนือ chatbar จะเปิด NPC คนเดียวกันในหน้าจัดการ ภาพที่โหลดช้าจากแชตเก่าจะไม่ไปแสดงในการ์ดที่เพิ่งเปลี่ยนไป

[ภาพมือถือ / เดสก์ท็อปจาก SillyTavern](previews/hstats-branches-v0.80.0/index.html)

## สร้าง Branch แล้วได้ข้อมูลของจุดนั้น

ใช้ **Create Branch** ของ SillyTavern ที่ข้อความที่ต้องการตามปกติ ทั้งข้อความผู้ใช้และคำตอบ AI รวมถึง swipe ที่เลือก RoleForge คืนสถานะจากจุดนั้นก่อนแสดงผลหรือสร้าง prompt: ผู้เล่น NPC, H-Stats, ความสัมพันธ์, เงิน, ไอเทม, ภารกิจ, สถานที่ และค่าการเล่นอื่นที่อยู่ใน state รวมถึง chat presets, สัญญาภารกิจ, Character Creation และรายชื่อ H-Stats ที่บันทึกไว้ ณ จุดนั้น

ตัวอย่างทดสอบ: แชตต้นฉบับเล่นถึงคำตอบที่ 8 มี **46 Gold** และไอเทม `FUTURE_ONLY_TOKEN` เมื่อแตก Branch ที่คำตอบที่ 2 เหลือ **13 Gold** และไม่มีไอเทมจากคำตอบที่ 8 เมื่อเล่นต่อใน Branch จนได้ 33 Gold ต้นฉบับยังมี 46 Gold ตามเดิม การ reload ไม่บวกค่าจากคำตอบเดิมซ้ำ

SillyTavern คัดลอก metadata ล่าสุดของต้นฉบับเข้ามาใน Branch รุ่นนี้ตรวจ `main_chat`, ตัวตนการ์ด/กลุ่ม และ `integrity` แล้วคืนข้อมูลตามลายนิ้วมือของข้อความและ swipe ไม่ใช้สถานะล่าสุดแทนจุดเก่า ตัด checkpoint, scene, social events และ manual-sync records หลังจุดนั้นออก รวมถึงไม่ผูกคลังสรุปความจำที่ยังโตต่อจากต้นฉบับ

### วิธีเก็บข้อมูล

เก็บ baseline ของสถานะแชตหนึ่งชุดและส่วนต่างของแต่ละจุดใน `tretaresia_rpg_branch_history` บน chat metadata จุดเดิมที่บันทึกซ้ำถูกรวมเข้าด้วยกัน มีข้อมูลสำหรับ Branch เกินขอบเขต 3 checkpoint ที่ใช้จัดการ swipe เดิม โดยไม่ต้องเก็บ state เต็มใหม่ทุกข้อความ ไม่คัดลอก World Pack, payload หรือคลัง NPC/Lore ทั้งหมดเข้าประวัตินี้ และไม่ส่ง journal เข้า prompt

ข้อมูลอยู่กับไฟล์แชตเมื่อ SillyTavern บันทึก metadata จึงติดไปกับการสำรองแชต ต้องสำรองไฟล์แชต/ข้อมูล SillyTavern ด้วย การส่งออกเฉพาะการ์ดไม่ใช่การสำรองประวัติการเล่น ขนาด metadata โตตามส่วนต่างที่เกิดจริงและจำนวนข้อความ

Branch มี journal ที่ตัดและตั้ง baseline ใหม่ ไม่เก็บไอเทม/ภารกิจจากอนาคตซ่อนอยู่ในประวัติของตัวเอง การแก้คลัง NPC/Lore หรือแพ็กอ้างอิงที่ผู้สร้างการ์ดบันทึกตั้งใจไว้ยังเป็นข้อมูลคลังร่วมเดิม ไม่ใช่ความคืบหน้าที่ระบบย้อนทับอัตโนมัติ

**New Chat ตามปกติ** ยังใช้ระบบสานต่อสถานะล่าสุดตาม toggle เดิม เป็นคนละการทำงานกับการแตก Branch กลับไปจุดเก่า

### แชตที่เล่นก่อนอัปเดต

RoleForge รุ่นเก่าเก็บ checkpoint เพียง 3 คำตอบ และนำ patch ที่ใช้แล้วออกจากเนื้อหาคำตอบ บางจุดเก่าจึงไม่มีข้อมูลพอให้คืนอย่างแม่นยำ รุ่นนี้เก็บจุดใหม่ตั้งแต่อัปเดต และนำ checkpoint เก่าที่ยังเหลืออยู่มาใช้ได้

หากจุดที่เลือกไม่มี snapshot เหลือ ระบบแจ้ง **Branch checkpoint unavailable**, แสดงสถานะเริ่มต้นของการ์ด และหยุด generation ปกติของ Branch นั้น เพื่อไม่ใช้ข้อมูลอนาคต แชตต้นฉบับไม่ถูกลบหรือแก้แทน สามารถ Import state backup ของจุดนั้นผ่านหน้าสถานะใน RoleForge หรือใช้ Manual Sync ที่ผู้ใช้สั่งเองเพื่อสร้างสถานะใหม่ก่อนเล่นต่อ Manual Sync เป็นการอ่าน/สร้างข้อมูลจากข้อความที่เหลือ ไม่ใช่การรับประกันว่าจะสร้างข้อมูลเก่าที่สูญหายได้เหมือนเดิมทุกค่า

## การทดสอบ

ผลตรวจและคำสั่งที่ใช้: [validation-summary.json](previews/hstats-branches-v0.80.0/validation-summary.json)

- Unit / host integration: `npm test` ผ่าน **1,532 tests** และ `npm run check` ผ่าน ทดสอบส่วนต่าง การคืน state เกิน 3 checkpoint, swipe, origin ก่อนข้อความแรก, ข้อมูลผิดรูปแบบ, save ล้มเหลว, การเปลี่ยนการ์ดระหว่างคัดลอกภาพ และการนำเข้า backup
- SillyTavern **1.19.0 / 06bde93** จริง: Chromium เดสก์ท็อปและการจำลองมือถือแบบ touch ใช้ native Import, ปุ่ม Branch, เปิดแชตเดิม, save/reload และ New Chat ตรวจแยกจาก fixture host
- H-Stats: ตรวจหน้าที่เลือกเหนือ chatbar และโครงเดิมใน RoleForge, ค้นหา NPC, รูป, เปลี่ยนคู่, แก้ค่า, กติกา, Import/Export และสลับการ์ดระหว่างโหลดรูป
- ตรวจแผงเหนือ chatbar กับ Dark Lite, Azure, Dark V 1.0 รวมหน้าจอ 320/390/430/768/1440px, gesture ภายในแผงไม่กระตุ้น chat swipe, ข้อความยาวไม่ล้น และเลื่อนภายในแผงได้

การทดสอบใช้คำตอบควบคุมผ่าน event หรือเส้นทาง generation/streaming ของ SillyTavern เพื่อให้ตรวจซ้ำได้ ไม่ได้ใช้ผลจากโมเดลภายนอก และไม่ได้ทดสอบ Safari บน iPhone เครื่องจริง
