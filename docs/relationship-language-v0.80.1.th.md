# การอ่านหลักฐานความสัมพันธ์ภาษาไทย — RoleForge 0.80.1

รุ่นนี้แก้ตัวตรวจความสัมพันธ์ทั่วไปที่ปฏิเสธข้อความยืนยันความรู้สึกบางคำ และการจับคู่ผู้เล่นที่ใช้ชื่อสองภาษา ทดสอบด้วยตัวละครจำลองใหม่ที่เป็นผู้ใหญ่และบทสนทนาที่ไม่มีเนื้อหาทางเพศ

## สิ่งที่แก้

- เพิ่มคำยืนยันด้าน Trust และความรู้สึก เช่น `ไว้วางใจ`, `เชื่อมั่น`, `อยู่เคียงข้าง`, `ให้กำลังใจ`, `หลงใหล`, `เสน่หา`, `คิดถึง` รวมถึงรูปคำอังกฤษ เช่น `trusts` และ `felt` ประโยคยังต้องระบุตัวละครที่เกี่ยวข้องและเกิดขึ้นจริง
- ชื่อผู้เล่นที่ป้อนชัดเจนเป็น `Elian / เอลิอัน` หรือคั่นด้วย `|` ใช้แต่ละชื่อยืนยันบุคคลเดียวกันได้ คงชื่อที่ผู้เล่นบันทึกไว้เดิม ไม่มีการสร้างชื่อ NPC ใหม่หรือเดาการถอดเสียงให้ทุกตัวละคร
- เก็บเครื่องหมายคำถามไว้ระหว่างแยกประโยค คำถามอย่าง `Does Noor love Elian?` หรือ `Noor ชอบเอลิอันหรือเปล่า?` จึงไม่ถูกนับเป็นการยืนยันความรู้สึก คำถามไม่ส่งต่อบริบทคู่ตัวละครไปยืนยันประโยคสรรพนามถัดไป
- แยกการสูญเสียความไว้ใจจากการได้รับความไว้ใจ เช่น `ไม่มีความไว้วางใจ` และ `lost trust` ต้องใช้เหตุการณ์ความขัดแย้งและค่าลดลง ข้อเสนอเพิ่ม Trust จากข้อความเหล่านี้ยังถูกปฏิเสธ
- ไม่ใช้คำ `care` ที่ฝังอยู่ใน `scared` หรือ `carelessly` ยืนยันการช่วยเหลือ และไม่ตีความ `ผ้าไหม` / `ไฟไหม้` เป็นคำถามภาษาไทย
- เปลี่ยนเหตุผลคำเตือนให้กล่าวถึง “ข้อความอ้างอิง” เพราะหลักฐานอาจเป็นคำบรรยาย เก็บ excerpt ไม่เกิน 320 ตัวอักษรกับรหัสเหตุผลใน `relationshipDiagnostics` ของเทิร์นนั้น เพื่อใช้ตรวจจาก Export chat ภายหลัง ไม่ส่งข้อมูลตรวจสอบนี้เข้า prompt

คำเตือนของเหตุการณ์ที่ยังยืนยันไม่ได้ยังทำงานตามเดิม ไม่มีการปิดคำเตือนเพื่อทำให้ดูเหมือนค่าอัปเดตแล้ว งบการเปลี่ยนค่าต่อฉาก การลดผลของเหตุการณ์ซ้ำ และข้อกำหนด milestone ยังเหมือนเดิม

แต่ละเหตุการณ์ยืนยันในตัวอย่างอยู่คนละฉากเพื่อแยกผลการอ่านภาษาจากงบต่อฉาก ตรวจค่าจาก state ที่บันทึกจริง จาก H-Stats เหนือ chatbar และจากหน้าหลัก RoleForge ผลตรงกัน ชื่อสองภาษายังอยู่ครบหลัง reload และการสลับไปอีกการ์ดไม่พาข้อมูล NPC ตามไปด้วย

ข้อความยืนยันที่รองรับไม่สร้าง warning ผิดพลาด ส่วนคำถามยังคงค่าเดิมและแจ้งเหตุผล `unconfirmed` การเปิด UI และ reload ไม่เพิ่มจำนวนการเรียกโมเดล ชุดทดสอบมีเฉพาะ 7 generation ที่สั่งเองต่ออุปกรณ์และตอบด้วย fixture ในเบราว์เซอร์

## ขอบเขตและข้อมูลเดิม

- เป็นการแก้ตัวตรวจสำหรับข้อความใหม่ ไม่ย้อนแก้ state, counter หรือประวัติของแชตเดิมโดยอัตโนมัติ
- แชตส่วนตัวที่ส่งมาตรวจไม่ได้ถูกนำเข้า SillyTavern ทดสอบ และไม่ได้รวมไว้ใน repository หรือภาพประกอบ ตัวอย่างและหลักฐานทดสอบมาจาก fixture ใหม่เท่านั้น
- ตัวตรวจยังต้องได้รับ relationshipEvents ที่ถูกต้องจากคำตอบ การแก้คำศัพท์ไม่ได้ทำให้ทุกข้อความเพิ่มค่า หรือทำให้แผน คำถาม และเหตุการณ์ที่ยังไม่เกิดกลายเป็นข้อเท็จจริง
- ทดสอบ SillyTavern 1.19.0 / Chromium บนเดสก์ท็อปและมือถือจำลองแบบ touch ไม่ได้ทดสอบ Safari บน iPhone เครื่องจริง หรือใช้โมเดลภายนอกตัดสินเนื้อเรื่อง

อัปเดตส่วนเสริมแล้ว reload SillyTavern หลังบันทึกข้อความร่าง รุ่นและ URL cache ของโมดูล/CSS เปลี่ยนเป็น 0.80.1 พร้อมกัน ไม่ต้องนำเข้าการ์ดใหม่
