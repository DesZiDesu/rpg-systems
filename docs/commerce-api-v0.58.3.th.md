# แก้ระบบซื้อและรายละเอียดข้อผิดพลาด — RoleForge 0.58.3

## สาเหตุที่ตรวจพบในโค้ด

เส้นทางเติมข้อเสนอใน 0.58.2 เรียก `generateRaw` ซึ่ง SillyTavern นำคำตอบไปผ่าน `cleanUpMessage` และ Regex ของ AI output ด้วย แม้ตั้ง `trimNames:false` แล้วก็ตาม หาก Regex สำหรับแสดงบทโรลลบหรือเปลี่ยน JSON งานข้อมูลอาจหายหรืออ่านไม่ได้ ก่อนส่งกลับถึง RoleForge

นอกจากนี้ 0.58.2 รวม exception หลายชนิดเป็น `opening-api` และไม่บันทึกข้อความ exception จึงแยกคำตอบว่างออกจากปัญหา provider ไม่ได้ ค่า `rawResponse:null` เพียงอย่างเดียวไม่พิสูจน์ว่าผู้ให้บริการล่ม หรือว่า Regex เป็นสาเหตุของคำขอจริงนั้น

0.58.3 ใช้ `generateRawData` กับ `extractMessageFromData` เมื่อโฮสต์รองรับ เพื่ออ่านข้อความสำหรับงานข้อมูลก่อน Regex และการจัดรูปแบบบทโรล ใช้การเชื่อมต่อปัจจุบันตามเดิม โฮสต์เก่ายังใช้ `generateRaw` หรือ quiet API ที่รองรับ การล้มเหลวไม่ทำให้เรียก API ซ้ำอัตโนมัติ เส้นทางเดียวกันครอบคลุมเติมข้อเสนอ กู้รายการ และปุ่มซื้อขาย

คำขอเคารพขีดจำกัดคำตอบที่ระบุใน host settings ซึ่งอ่านได้ และแยก `opening-empty` / `opening-truncated` / `opening-api` รายงานบันทึกวิธีเรียก API, responseLength และข้อความสาเหตุที่ปิดบังรูปแบบ API key ที่รู้จัก โดยไม่ส่งออก host settings หรือ stack trace

## `invalid-data` จาก `inline-patch`

หมายถึงมี JSON รายการในคำตอบปกติ แต่รายการไม่ผ่านการตรวจข้อเสนอ NPC ไม่ใช่ข้อผิดพลาดเดียวกับการเรียก API ตัวอย่าง: JSON ใช้ชื่อภาษาอังกฤษจาก planning ทั้งที่บทพูดเสนอชื่อภาษาไทย หรือยังใช้ราคาเก่า 15/20/10 ทั้งที่ข้อเสนอปัจจุบันเป็น 13/18/9

รายงานเดิมไม่เก็บช่องที่ล้มเหลว จึงระบุไม่ได้ว่า JSON ของผู้ใช้ผิดตรงไหนจากรายงานสี่ช่องนั้น รุ่นนี้บันทึก `details.reasons` และแสดงคำอธิบายบนแผง สำหรับชื่อสินค้า ราคา สถานที่ ผู้พูด หลักฐาน และเงื่อนไข ตัวอย่าง `item-price-evidence` จะมีชื่อสินค้าและราคาที่ไม่ผ่านตรวจด้วย ข้อมูลที่ขัดกับบทพูดยังคงไม่ถูกนำไปชำระเงินจริง

แก้การเลือก “ซื้อทั้งสามเล่ม” ในเส้นทาง inline ให้เลือกสินค้าทั้งสามอย่างละหนึ่ง ไม่ใช่สามของทุกชนิด ข้อเสนอหนังสือภาษาไทยในรายงานนี้เปิดตะกร้า 13 + 18 + 9 = 40 เหรียญเงินได้ โดยไม่อ้าง planning และยังไม่หักเงินจนยืนยัน

## วิธีใช้งานหลังอัปเดต

1. อัปเดต RoleForge จาก main แล้วโหลดหน้าใหม่ ตรวจว่ารุ่นเป็น 0.58.3
2. สำหรับข้อเสนอค้างเดิม กด “ให้ AI เติมข้อมูลรายการ” เพื่ออ่านบทโรลและเติมรายละเอียดใหม่
3. ตรวจชื่อสินค้า จำนวน และยอดรวม ก่อนกดยืนยันซื้อ
4. หากล้มเหลว เปิด “ดูข้อมูลข้อผิดพลาด” เพื่อดูสาเหตุใหม่ การโหลด record เก่าที่ไม่มีรายละเอียดไม่สามารถสร้าง exception ที่หายไปย้อนหลังได้

## การตรวจสอบ

ทดสอบ Node unit/host ทั้งชุดและ syntax checks ครอบคลุมบทพูด Barth ภาษาไทย ราคาปัจจุบัน 13/18/9 ตะกร้าครบสามเล่ม ข้อมูลเก่าหรือ planning ที่ไม่ใช่หลักฐาน การข้าม story cleanup, คำตอบว่าง, ขีดจำกัดโทเคน, provider exception และการไม่หักเงินระหว่างเติมข้อมูล

สภาพแวดล้อมนี้ไม่มี Chromium และดาวน์โหลด browser archive ไม่สำเร็จ จึงไม่ได้รัน browser suites ในรอบนี้ ไม่ได้เรียก provider ของผู้ใช้หรือทดสอบบน SillyTavern ที่ติดตั้งจริง

อ้างอิง API ต้นทางที่ตรวจ: [SillyTavern script.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js) และ [st-context.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/st-context.js)
