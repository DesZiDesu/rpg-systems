# ข้อเสนอ H-Stats progression ใหม่

**เอกสารเสนอแนวทางเท่านั้น รุ่น 0.78.1 ยังไม่เปลี่ยนกลไก H-Stats**

เป้าหมายคือให้ความรัก ความไว้ใจ ความซื่อสัตย์ และการเปลี่ยนหลักยึดมีพัฒนาการตามเหตุการณ์ ตัวละครไม่เปลี่ยนใจเพราะจำนวนข้อความหรือคำชมไม่กี่ครั้ง และยังรักษาบุคลิกเดิมที่การ์ดกำหนด

## สิ่งที่พบจากระบบปัจจุบัน

- `src/h-stats.js` เก็บ `loyaltyHearts` 0–5, `infidelityStage` 1–5 และ `infidelityProgress` 0–100 แต่ยังไม่มีเงื่อนไขเหตุการณ์ขั้นต่ำหรือจังหวะการเติบโตระหว่าง Stage
- AI ส่ง `set` / `inc` เพื่อเปลี่ยนค่าเหล่านี้ได้ ระบบตรวจชนิดและช่วงตัวเลข แต่ยังไม่ควบคุมการกระโดดของ progression เช่น การลดหัวใจหลายดวงในคำตอบเดียว
- หัวใจหนึ่งดวงเท่ากับ 20% ของสเกลทั้งหมด ทำให้การเปลี่ยนเพียงหนึ่งหน่วยดูรุนแรง ระบบสร้าง baseline เดิมยังตั้งหัวใจ 5 ดวง ซึ่งไม่ใช่หลักฐานว่า NPC ผูกพันหรือมีคำมั่นกับผู้เล่นแล้ว
- Corruption ใน NPC เป็นอีกค่า 0–100 ส่วน Affection / Trust / Loyalty ถูกเก็บแยกกัน ปัจจุบันยังไม่มี engine รวมที่ตรวจเส้นทางพัฒนาการเหล่านี้

หัวใจไม่ได้เป็นตัวสุ่มให้ NPC นอกใจในโค้ดโดยตรง โมเดลอ่านค่ากับคำอธิบายแล้วแต่งเหตุการณ์ จากนั้นส่ง patch กลับมา ดังนั้นต้องแก้ทั้งขอบเขตก่อน AI ตอบและกติกายืนยัน progression ภายหลัง การเปลี่ยนรูปหลอดอย่างเดียวไม่แก้ปัญหา

## ค่าหลักที่เสนอ

| ค่า | ใช้อธิบาย | ไม่ใช้แทน |
|---|---|---|
| Love / Bond 0–100 | ความผูกพันต่อบุคคลที่ระบุ | การเป็นคู่รักหรือการยอมรับทุกการกระทำ |
| Trust 0–100 | ความเชื่อใจจากพฤติกรรมและคำสัญญาที่รักษา | ความรักและความสนใจเชิงรัก |
| Commitment 0–100 | ความตั้งใจรักษาความสัมพันธ์และข้อตกลงที่มีอยู่ | การเป็นเจ้าของ NPC หรือการนับว่าเป็นคู่ตั้งแต่พบครั้งแรก |
| Corruption 0–100 | การเปลี่ยนหลักยึดหรือขอบเขตที่โลก/การ์ดนั้นกำหนด | Lust ความกลัว หรือคำสั่งให้นอกใจ |

ใช้ค่าตัวเลขเดิมที่ความหมายตรงกันต่อไปเท่าที่ทำได้ แทนการเพิ่มค่าใกล้เคียงซ้ำกันหลายชุด ส่วนสถานะความสัมพันธ์เก็บแยกเป็น ไม่ทราบ / โสด / เพื่อน / สนใจเชิงรัก / คู่รัก / คู่สมรส พร้อมข้อตกลง เช่น exclusive หรือความสัมพันธ์ที่ตกลงรูปแบบอื่นไว้ การตกลงคบกันต้องเกิดในเรื่อง ไม่เปลี่ยนจากคะแนนถึงเกณฑ์เพียงอย่างเดียว

ความรู้สึกต่อผู้เล่นและบุคคลอื่นต้องแยกตามคู่ เช่น A → ผู้เล่น กับ A → B ไม่ใช้ค่ารวมเดียวแล้วให้ AI เลือกคู่เอาเอง เก็บเฉพาะคู่ที่เกี่ยวข้อง ไม่สร้างข้อมูลทุก NPC คูณทุก NPC

## จังหวะการเติบโต

แนะนำ **Slow** เป็นค่าเริ่มต้น และให้การ์ด/NPC ปรับเป็น Balanced หรือ Custom ได้ ตัวเลขต่อไปนี้เป็นค่าตัวอย่างสำหรับหารือ:

- คุยทั่วไป ทักทาย หรือชมซ้ำ: ไม่เพิ่มอัตโนมัติ
- เหตุการณ์เล็กที่มีความหมายและสอดคล้องบุคลิก: +1 ในค่าที่เกี่ยวข้อง
- ช่วยเหลือ รักษาคำสัญญา หรือเปิดใจอย่างมีเหตุผล: +2 ถึง +3
- เหตุการณ์ใหญ่จริง: พิจารณาได้ถึง +5 หรือ +6 พร้อมหลักฐานและเหตุผลเฉพาะ ไม่ให้โมเดลเรียกทุกบทสนทนาว่าเหตุการณ์ใหญ่
- จำกัดผลบวกปกติรวมต่อคู่ **ต่อฉาก** แทนต่อข้อความ ฉากหมายถึงเหตุการณ์ต่อเนื่องในเรื่อง ไม่ใช่เลข Scene Tracker ที่เพิ่มทุกคำตอบ พร้อมผลตอบแทนลดลงสำหรับเหตุการณ์ชนิดเดิม เหตุการณ์ใหญ่ใช้ข้อยกเว้นที่ตรวจได้
- การสูญเสียความไว้ใจจากการผิดสัญญาร้ายแรงอาจรวดเร็วกว่าการฟื้นฟู แต่ต้องมีเหตุการณ์จริง การขอโทษซ้ำในฉากเดียวไม่คืนค่าทั้งหมด
- จำนวนเทิร์น เวลาที่ผ่านเฉย ๆ การเปิด UI การถามเกี่ยวกับเหตุการณ์ ความฝัน ข่าวลือ หรือความคิดในใจ ไม่เพิ่ม progression ของการกระทำที่ยังไม่เกิด

ระดับความใกล้ชิดต้องมีทั้งคะแนนที่เหมาะสมและ **milestone** จากบท เช่น ยอมเปิดเผยเรื่องส่วนตัว รักษาคำสัญญาสำคัญ หรือยอมรับความสัมพันธ์ ระดับสูงไม่บังคับให้เปลี่ยนเพื่อนเป็นคู่รัก และไม่ข้ามหลายระดับจากเหตุการณ์เล็กครั้งเดียว

ทุกการเปลี่ยนต้องบอกได้ว่า “อะไรเปลี่ยน เพราะเหตุการณ์ไหน” พร้อมแหล่งข้อความ ป้องกันการนับเหตุการณ์เดิมซ้ำจาก swipe, regenerate, reload และ Manual Sync

## Cheating เป็นสถานการณ์และเหตุการณ์ ไม่ใช่หลอดที่เต็มแล้วต้องเกิด

เสนอให้เลิกใช้ความหมาย “Stage สูงแล้วต้องนอกใจ” เปลี่ยนเป็นสถานะความสัมพันธ์ เช่น:

**มั่นคง ↔ มีรอยร้าว ↔ ลังเล → ล้ำขอบเขต → ยืนยันว่าผิดคำมั่น**

นี่เป็นสถานะที่ต้องมีเหตุผลรองรับ ไม่ใช่ขั้นบันไดบังคับ ตัวละครกลับมารักษาความสัมพันธ์ได้ และความสนใจคนอื่นเพียงอย่างเดียวไม่ใช่หลักฐานการนอกใจ

กติกาสำคัญ:

1. ต้องรู้ก่อนว่ามีคู่และข้อตกลงอะไร ไม่มีข้อตกลงผูกขาดที่ยืนยันไว้จะไม่ติดป้ายว่า cheating อัตโนมัติ
2. ต้องมีบุคคลที่เกี่ยวข้องจริง พร้อมความสัมพันธ์และเหตุการณ์ของคู่นั้น ไม่สุ่มคนใหม่หรือจำลองเหตุการณ์ลับนอกฉากเพราะเวลาผ่าน
3. ความขัดแย้งต้องผ่านการสะสมเหตุการณ์ที่มีความหมาย บุคลิกหนักแน่นหรือถือคำมั่นมีแรงต้านสูงกว่า แต่ไม่ใช้ค่าตายตัวเดียวกับทุกคน
4. การล้ำขอบเขตและการผิดคำมั่นต้องอ้างอิงสิ่งที่เกิดจริงในบท ความคิด ความหวั่นไหว คำขู่ หรือค่าหลอดอย่างเดียวไม่ยืนยันการกระทำ
5. คะแนนเต็มไม่สั่งให้เกิดเหตุการณ์ ตัวละครยังเลือกปฏิเสธ รักษาคำมั่น หรือคุยแก้ปัญหาได้
6. เหตุการณ์ที่ผู้ใช้กำหนดไว้ชัดเจนหรือ canon ตั้งต้นใช้เป็นข้อมูลเริ่มต้น/override ที่แยกจากการเติบโตอัตโนมัติ ไม่บังคับให้เล่นซ้ำเพื่อให้ถึงคะแนน
7. การฟื้นฟูไม่ลบประวัติที่ยืนยันไปแล้ว ความไว้ใจในปัจจุบันกับสิ่งที่เคยเกิดเป็นคนละข้อมูล

## Corruption ต้องมีความหมายเฉพาะโลกและบุคลิก

ผู้สร้างการ์ดกำหนดได้ว่าหมายถึงการเปลี่ยนหลักศีลธรรม การยอมละทิ้งคำมั่น หรืออิทธิพลเหนือธรรมชาติ โดยระบุหลักยึดเดิม เหตุการณ์ที่กระทบ และแรงต้านของแต่ละ NPC

การขยับอาจเป็น **ยึดหลักเดิม → เริ่มตั้งคำถาม → ยืดหยุ่น → เปลี่ยนหลักยึด** แต่ต้องมี milestone และเหตุการณ์รองรับ ไม่ขึ้นเพราะแค่มีคนยั่วยุหรือถูกกดดัน และไม่ผูกสูตรว่า Corruption สูง = นอกใจทันที

แรงกดดัน ความกลัว ความปรารถนา และการเปลี่ยนความเชื่อควรแยกความหมายกัน ตัวละครที่กลัวอาจยังยึดหลักเดิม การฟื้นฟูจุดยืนทำได้จากเหตุการณ์ที่มีน้ำหนัก ไม่ลดค่าทุกวันโดยไม่มีเหตุผล

## ตัวอย่างพฤติกรรมที่ควรได้

NPC เป็นคู่รักกับผู้เล่น Love 80 / Trust 85 / Commitment 90 คนอื่นเข้ามาชมหนึ่งครั้ง:

- NPC อาจรับคำชม เขิน หรือปฏิเสธตามบุคลิก
- ไม่หักความรักหรือความซื่อสัตย์ต่อผู้เล่นโดยอัตโนมัติ
- ไม่ยกระดับเป็นความสัมพันธ์ลับหรือ cheating
- ถ้าความสัมพันธ์กับอีกคนเริ่มก่อตัวจริง บันทึกความรู้สึกของคู่นั้นแยก โดยยังต้องผ่านฉากและการตัดสินใจอีกหลายครั้ง

หากภายหลังมีความขัดแย้งหลายฉาก ระบบแสดงสาเหตุได้ เช่น “ความเชื่อใจลดจากการผิดสัญญาที่ท่าเรือ” และยังมีทางแก้ความสัมพันธ์ ไม่เดินหน้าไปสู่การนอกใจเองเพียงเพราะ progress สะสม

## หน้าตาและการควบคุม

เหนือ chatbar แสดงเพียงชื่อ + สถานะความสัมพันธ์ และหลอดบางของ Love / Trust / Commitment ใช้ตัวเลขละเอียดแทนหัวใจห้าดวง ส่วน Corruption รายละเอียดต่อบุคคล เหตุการณ์ และเหตุผลล่าสุดอยู่ในหมวดความสัมพันธ์ที่กางดูได้ ไม่วางทุกค่าในภาพรวม

เลือกแนว Love / Relationship Drama / Corruption หรือผสมกันได้ พร้อมตัวเลือกห้ามเส้นเรื่องนอกใจสำหรับการ์ดหรือ NPC ที่ต้องรักษา canon; การเปิดแนว Drama ยังใช้กติกา Slow ไม่ได้บังคับให้ต้องเกิดการทรยศ

การ์ด/Preset นำเข้า–ส่งออกความเร็ว บุคลิก เงื่อนไข ข้อตกลง และค่าเริ่มต้นได้ ผู้ใช้กำหนดข้อยกเว้นของ NPC เป็นรายตัวได้ ไม่มีการเรียก API เพิ่มทุกเทิร์นเพื่อสุ่มว่าควรเปลี่ยนใจหรือไม่

ก่อน AI ตอบต้องส่งสถานะและขอบเขตการตัดสินใจปัจจุบันให้ชัดเจน หลังตอบตรวจเหตุการณ์และอนุมัติการเปลี่ยนค่าด้วยกฎเดียวกัน โมเดลยังอาจเขียนนอกกติกาได้ จึงต้องตรวจความขัดแย้งและแจ้ง/ให้แก้คำตอบนั้น ไม่ยืนยันค่าผิดเงียบ ๆ และไม่เรียก API แก้เรื่องอัตโนมัติโดยเพิ่มค่าใช้จ่าย

## ย้ายข้อมูลเดิม

เก็บค่าเดิม ประวัติ รายชื่อ และรายละเอียดอื่นครบ โดยไม่ถือหัวใจ 5 ดวงว่าเป็นคำมั่นรัก และไม่ถือ infidelityStage เดิมว่าเป็นหลักฐานการนอกใจที่เกิดจริง แยกค่าที่สร้างเป็น baseline ออกจากข้อมูลที่มีเหตุการณ์รองรับ ใช้การแมปที่ตรวจสอบได้และเก็บสำเนารูปแบบเก่าสำหรับย้อนดู

ความสัมพันธ์ที่การ์ดหรือแชตยืนยันไว้แล้วเริ่มจากสถานะนั้นได้ ไม่ต้องเริ่มรู้จักกันใหม่ การปรับใหม่ควรเปลี่ยนเฉพาะ progression และการแสดงความสัมพันธ์ ไม่ล้างข้อมูล H-Stats หมวดอื่น
