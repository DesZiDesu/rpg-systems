# ตรวจ H-Stats หลัง Branch — RoleForge 0.80.2

ตรวจการเพิ่มค่าจากข้อความใหม่หลังสร้าง Branch บน SillyTavern จริงแล้ว ทั้งความรู้สึกต่อผู้เล่น ความสัมพันธ์ระหว่าง NPC และประวัติรายตัว ค่าใน state ที่บันทึกตรงกับหน้าหลัก RoleForge และ H-Stats เหนือ chatbar

พบและแก้เพิ่มเติมหนึ่งจุด: ข้อมูลที่ผู้ใช้แก้ในฟอร์ม H-Stats แล้วบันทึกเองอาจถูก checkpoint เก่าทับเมื่อสลับ swipe การบันทึกตอนนี้รักษาเฉพาะช่องที่แก้ไว้ใน checkpoint สำหรับ swipe และ rollback ส่วน counter และข้อมูลจากเนื้อเรื่องช่องอื่นยังย้อนตามคำตอบที่เลือก การบันทึกล้มเหลวจะคืนทั้ง state และ checkpoint เดิม

## สิ่งที่ตรวจบน SillyTavern จริง

[ภาพมือถือและเดสก์ท็อป](previews/hstats-branch-verification-v0.80.2/index.html) · [ผล H-Stats](previews/hstats-branch-verification-v0.80.2/native-hstats-validation.json) · [สรุปการตรวจ](previews/hstats-branch-verification-v0.80.2/validation-summary.json)

ใช้ SillyTavern **1.19.0 / 06bde93**, ธีม **Dark Lite**, Chromium เดสก์ท็อป 1440×1000 และมือถือจำลองแบบ touch 390×844 ตัวอย่างใหม่อิสระ: Noor อายุ 28, Rowan อายุ 31, Elian อายุ 29 เป็นการสนทนาและข้อมูลประวัติทางการแพทย์ ไม่ได้นำเข้าแชตส่วนตัวของผู้ใช้

| ข้อมูล | จุดที่สร้าง Branch | หลังเล่นต่อและ reload |
|---|---:|---:|
| Noor → ผู้เล่น: Trust | 41 | 44 |
| Noor → ผู้เล่น: Love | 16 | 17 |
| Noor → ผู้เล่น: Interest | 21 | 22 |
| Rowan → Noor: Trust | 11 | 14 |
| ประวัติการคลอดของ Noor | 0 | 2 |

- สร้าง Branch ด้วยปุ่มของ SillyTavern จากข้อความเก่าที่อยู่นอก 3 checkpoint ล่าสุด ได้เฉพาะข้อมูล ณ จุดนั้น ไม่มีข้อมูลอนาคตติดมา
- ส่งข้อความใหม่ผ่าน generation และ streaming ของ SillyTavern แล้วค่าทั้ง NPC → ผู้เล่น และ NPC → NPC เพิ่มต่อได้หลัง Branch และหลัง reload
- เหตุการณ์ประวัติระหว่าง NPC ไม่เพิ่ม counter ของผู้เล่นหรือ NPC ที่ไม่เกี่ยวข้อง
- อ่านค่าที่แสดงจริงในทั้งสอง UI ตรงกับ state ที่บันทึก ทั้งค่าความสัมพันธ์และ counter
- สลับ swipe แล้วคืน counter ตามคำตอบนั้น ไม่บวกซ้ำ การแก้ช่องข้อมูลด้วยตัวเองยังอยู่ครบ
- reload และสลับระหว่างแชตต้นฉบับกับ Branch ไม่ replay เหตุการณ์ ไม่ทำให้ค่าเพิ่มซ้ำ และไม่เปลี่ยนแชตต้นฉบับ
- เหตุการณ์ชนิดเดิมที่ขอเพิ่ม +1 ซ้ำในฉากต่อเนื่องยังอยู่ภายใต้กติกาลดผลเหตุการณ์ซ้ำ เปลี่ยนเป็นฉากใหม่แล้วเพิ่มต่อได้ตามกติกา

ชุดทดสอบนี้ใช้คำตอบควบคุม 10 generation ต่ออุปกรณ์ รวม 20 ครั้ง ผ่านเส้นทางส่งข้อความจริงของ SillyTavern การเปิด UI, Branch และ reload ไม่เรียกโมเดลเพิ่ม ยังไม่ได้ใช้โมเดลหรือ API ของผู้ใช้เพื่อตัดสินเนื้อเรื่อง และไม่ได้ทดสอบ Safari บน iPhone เครื่องจริง

รัน [ชุด Branch เดิมซ้ำบนรุ่น 0.80.2](previews/hstats-branch-verification-v0.80.2/native-branch-regression.json) ผ่านทั้งสองขนาดจอด้วย: Branch จบที่ข้อความผู้เล่น, เลือก swipe เดิม/ทางเลือก, checkpoint รุ่นเก่า, จุดเก่าที่หายต้องหยุดส่งข้อมูลอนาคต, Import state กู้จุดนั้น และ New Chat แบบสานต่อปกติ ชุดนี้ใช้เหตุการณ์ของ host และคำตอบทดสอบ ไม่เรียกโมเดล

## Unit tests และไฟล์ที่แก้

`npm test` ผ่าน **1,561 tests**, ชุด relationship / H-Stats / Branch เฉพาะผ่าน **112 tests**, และ `npm run check` ผ่าน

Unit tests เพิ่มกรณีรักษาเฉพาะช่องที่แก้โดยไม่แช่แข็ง counter, provenance ของค่าเริ่มต้น, sparse Character NPC ที่ยังไม่โหลด, การแก้ canon ภายหลัง, การคืนค่าเดิม และ storage failure

- `src/h-stats.js`: รักษาเฉพาะช่อง H-Stats ที่ผู้ใช้แก้ใน checkpoint สำหรับ swipe รวมถึง sparse overrides โดยไม่โหลดคลังหรือเปลี่ยน `met` / การเปิดใช้
- `index.js`: ฟอร์มบันทึกผ่านกลไกบันทึก state และ checkpoint เป็นชุดเดียวกัน
- `tests/h-stats.test.mjs`, `tests/host-integration.test.mjs`: regression tests ของการแก้ข้อมูลและการบันทึกล้มเหลว
- `tests/hstats-branches.real.browser.mjs`: การเล่นต่อหลัง Branch บน SillyTavern จริง รันด้วย `npm run test:hstats-branches:real`
- `manifest.json`, `package.json` และ URL cache ของโมดูล/CSS: รุ่น 0.80.2

ไม่ได้เปลี่ยนเงื่อนไขหลักฐาน ความเร็วการเพิ่มค่า ข้อตกลงความสัมพันธ์ หรือเปลี่ยนหน้าตาหลัก RoleForge

## ใช้กับแชตที่มีอยู่

อัปเดตส่วนเสริมแล้ว reload SillyTavern หลังบันทึกข้อความร่าง ไม่ต้องนำเข้าการ์ดใหม่ ข้อความใหม่ที่มีข้อมูลอัปเดตและหลักฐานถูกต้องจะติดตามต่อได้

ค่าไม่จำเป็นต้องเพิ่มทุกข้อความ: ต้องมีเหตุการณ์ที่ยืนยันได้ และอยู่ภายใต้เพดานต่อฉาก การอัปเดตนี้ไม่ย้อนหลังเพิ่มค่าที่พลาดไปแล้วโดยอัตโนมัติ

ถ้าสร้าง Branch จากจุดเก่าที่ checkpoint ถูกทิ้งไปตั้งแต่ก่อนมีระบบ journal จะยังต้อง Import state ของจุดนั้นหรือใช้ Manual Sync ตามคำเตือน ระบบจะไม่ใช้ข้อมูลอนาคตของแชตต้นฉบับแทนจุดที่หายไป
