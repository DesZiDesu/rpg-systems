# รายงานแก้ NPC กรอกข้อมูลไม่ครบ — RoleForge 0.90.18

ตรวจและทดสอบวันที่ 30 ตุลาคม 2026 กับ API `https://cheeseapi.top/v1` โดยใช้คีย์ที่ผู้ใช้ให้เฉพาะในตัวส่งคำขอชั่วคราวนอก repository คีย์ไม่ได้อยู่ในโค้ด รายงาน หรือการตั้งค่า SillyTavern ที่ใช้ทดสอบ

## ทำไมข้อมูลจึงหาย

1. **คำสั่งของ Addon อนุญาตให้เว้นช่องเอง** คำสั่งสร้างจากคำอธิบายเดิมมีทั้ง “omit optional fields you cannot establish” และ “Do not fill every optional field” โมเดลจึงตอบ JSON ถูกต้องแต่ขาดหลายช่องได้ตามคำสั่ง
2. **คำสั่งลองใหม่ลดเหลือ 8 ช่อง** คำสั่งซ่อมเดิมขอแค่ name, title, occupation, relationship, appearance, personality, background, goals และห้าม stats/abilities/arrays จึงไม่สามารถซ่อมฟอร์มทั้งหมดได้
3. **ร่างบางส่วนผ่านเป็นผลสำเร็จ** ตัวแปลงร่างเดิมยอมรับชื่อและรายละเอียดเพียงหนึ่งช่อง จากนั้นเติมค่าสถานะทั่วไป ทำให้มองเหมือนโมเดลส่งข้อมูลครบ ทั้งที่หลายช่องยังว่าง
4. **งบคำตอบของงาน NPC ต่ำกว่าพรีเซ็ต** พรีเซ็ตที่ส่งมาตั้ง 8,192 tokens และ reasoning high แต่งานสร้างเดิมขอสูงสุด 2,400 การทดสอบบางคำตอบใช้ reasoning มากกว่าข้อความจริง อย่างไรก็ตาม ตัวอย่างก่อนแก้ทั้งสี่ตอบ `finish_reason: stop` จึงยืนยันได้ว่าปัญหาช่องหายในรอบนั้นเกิดแม้ไม่มีการตัดคำตอบจาก API
5. **JSON ใน planning อาจถูกรับผิดก้อน** งานข้อมูลอ่านคำตอบก่อนขั้นตอนตกแต่งของแชท จึงต้องแยก `<planning>` และรูปแบบ reasoning ที่ผู้ใช้ตั้งออกก่อนค้นหา JSON ป้องกันการรับตัวอย่างในส่วนนั้นแทนคำตอบจริง จุดนี้ตรวจด้วย regression tests ไม่ใช่สาเหตุที่ยืนยันว่าเกิดในทุกคำตอบจริง

ไม่พบหลักฐานว่าหน้าบันทึกทำข้อมูลครบจากโมเดลหายไปในกรณีทดสอบ การเปรียบเทียบก่อนแก้พบว่าข้อมูลขาดตั้งแต่คำตอบของ API แล้ว

## สิ่งที่แก้

- สคีมงานสร้างระบุครบ 22 ช่องข้อความ, 9 ช่องค่าสถานะ, 6 ค่าความสัมพันธ์ รวมชื่อเรียก ความสามารถ สี ไอคอนบทบาท และสถานะศัตรู
- ตรวจความครบและชนิดข้อมูลก่อนนำร่างลงฟอร์ม รับค่าตัวเลขที่ API ส่งเป็นสตริงได้ และเก็บศูนย์ที่มีความหมาย เช่น MP 0
- ขอข้อมูลซ่อมได้อีกหนึ่งครั้ง โดยเติมเฉพาะช่องที่ขาด ไม่เปลี่ยนชื่อ ข้อมูลดีจากคำตอบแรก หรือรูปลักษณ์จากภาพอ้างอิง
- หากยังไม่ครบ แจ้งชื่อช่องที่ขาดและเก็บร่างเดิม ไม่แสดงผลสำเร็จบางส่วน
- งานสร้าง/เติมร่างขอได้ถึง 8,192 tokens งานจัดค่าสถานะขอถึง 4,096 โดยเคารพเพดานที่ผู้ใช้ตั้ง ไม่แอบเพิ่มการตั้งค่าทั่วทั้งแอป
- API/เครือข่ายล้มเหลวไม่เรียกซ้ำเงียบ ๆ; การซ่อมข้อมูลแสดงสถานะและนับเป็นคำขอเพิ่มตามจริง
- ปรับข้อกำหนดการสร้าง NPC ใน Main Chat ด้วย ทั้งกรอบข้อความเปิดและปิด ไม่มีการเพิ่มคำขอ AI อัตโนมัติเพื่อแต่งประวัตินอกฉาก
- ตัวละครออริจินัลสามารถมีรายละเอียดที่ออกแบบขึ้นตามแนวคิดได้ ส่วนข้อมูล canon หรือข้อเท็จจริงที่ตั้งใจปิดเป็นความลับให้ระบุ “ยังไม่เปิดเผย” อย่างตรงไปตรงมา ไม่เดาว่าไม่มีคู่ครอง/บุตร การไม่มี aliases/abilities ใช้ `[]` ได้
- รูป ไฟล์อ้างอิง ขอบเขต Chat/Character และสถานะเคยพบยังอยู่ภายใต้การควบคุมของผู้ใช้ กดบันทึกหลังตรวจร่างเช่นเดิม

## ผลทดสอบ API จริง

ใช้ temperature 1, top_p 0.09 และ reasoning high ตามค่าหลักในพรีเซ็ต ทดสอบแนวคิดหมอยาสมุนไพรกับ API โดยตรงก่อน/หลังแก้ แล้วนำพรีเซ็ต Omega ที่ส่งมาเข้า SillyTavern 1.19.0 และสร้าง NPC อีกแนวคิดผ่านปุ่มจริง บันทึก และโหลดแชทกลับมา

| Model ID ที่ API ประกาศ | ช่องที่ขาดก่อนแก้ | หลังแก้ผ่าน API ตรง | ผ่านฟอร์มจริง | จำนวนคำขอในฟอร์ม | เวลารวมสร้าง/บันทึก/โหลดกลับ |
|---|---:|---|---|---:|---:|
| `[备用]gemini-3.8-flash` | 3 | ครบ | ครบ | 1 | 30.44 วินาที |
| `[备用]Gemini-3.8-flash-2` | 26 | ครบ | ครบ | 1 | 17.52 วินาที |
| `[抗截断]gemini-3.8-flash` | 5 | ครบ | ครบหลังซ่อม | 2 | 38.02 วินาที |
| `[芝士ais]gemini-3.8-flash` | 26 | ครบ | ครบ | 1 | 36.15 วินาที |

**แนะนำเริ่มจาก `[备用]Gemini-3.8-flash-2` สำหรับงานสร้าง NPC** เพราะครบโดยไม่ต้องซ่อมและเร็วที่สุดในการทดสอบนี้ ชื่อเหล่านี้เป็นชื่อที่ผู้ให้บริการประกาศ ไม่ใช่การยืนยันตัวโมเดลเบื้องหลัง ทดสอบสองแนวคิดหลังแก้ต่อโมเดล จึงยังไม่ใช่ข้อสรุปคุณภาพการเขียนโรลยาวหรือความเสถียรระยะยาว

พรีเซ็ตที่นำเข้ายังคงอยู่ระหว่างทดสอบ งานข้อมูลผ่าน native `generateRawData` ของ ST และพบข้อความ system/user สองรายการ แยกจากข้อความบรรยายในพรีเซ็ต รูปแบบ `<planning>...</planning>` ตามภาพที่ผู้ใช้ส่งได้รับการตรวจด้วย ไม่จำเป็นต้องปิด Auto-Parse หรือ Show Hidden เพื่อให้ฟอร์มทำงาน

Main Chat ได้รับคำสั่งสร้างข้อมูลครบในอัปเดตนี้ แต่การเรียก API จริงข้างต้นวัดงาน NPC Management โดยตรง ไม่ใช่การทดสอบเล่นเรื่องยาวทุกระบบ

## การตรวจสอบเพิ่มเติม

- `npm test`: 2,192 ผ่าน
- `npm run check` และ `git diff --check`: ผ่าน
- NPC workspace browser: สร้าง/ซ่อม/เก็บร่างเมื่อผิดพลาด, stale response, รูปอ้างอิง, บันทึก Chat/Character และค่าสถานะ
- SillyTavern จริง: ทุกโมเดลส่งค่าลงฟอร์มครบ, ไม่เพิ่ม NPC ก่อนผู้ใช้บันทึก, เก็บ MP 0, ไม่เปลี่ยนเป็นเคยพบเอง, เซฟและโหลดกลับครบ
- หลายภาพอ้างอิง: ผ่านทั้ง desktop และ mobile emulation โดยใช้คำตอบควบคุมเพื่อเช็กการเชื่อมต่อข้อมูลและการเก็บรูปลักษณ์
- มือถือใช้ Chromium touch emulation ไม่ใช่ iPhone/Safari เครื่องจริง

การทดสอบเสริม `npc-alternates.browser.mjs` ยังมีปัญหา fixture เดิม: launcher ใน Settings ถูก navigator ซ่อน และเมื่อข้ามจุดนั้นแล้ว assertion ภาพ portrait ที่สืบทอดใน alternate draft ล้มเหลว อาการหลังนี้ทำซ้ำได้บน baseline `6057d81` ด้วย workaround ของ launcher แบบเดียวกัน จึงไม่ใช่ regression จากตัวแก้งาน API นี้ และไม่ได้รวมการทดสอบดังกล่าวไว้ในรายการผ่านข้างต้น
