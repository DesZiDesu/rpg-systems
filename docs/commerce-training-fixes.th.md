# RoleForge v0.53.1 — ข้อมูลซื้อ การต่อโรล และการฝึก

## สิ่งที่พบและแก้

| ปัญหา | จุดที่พบในโค้ด | การแก้ |
| --- | --- | --- |
| รายการซื้อเรียก AI เพิ่มและเงื่อนไขไม่ครบ | คำสั่งสิทธิ์ซื้อใหม่ขัดกับตัวอย่างซื้อแบบเก่า ทั้ง main reply และ opening recovery ยังมีตัวอย่างที่ให้ส่งเพียงชื่อและราคา เส้นทางประมวลผลคำตอบซื้อยังเรียก recovery อัตโนมัติเมื่อ payload ขาด | เปลี่ยนตัวอย่างและคำสั่งให้ตรงกัน รายการทุกตัวมีรายละเอียดและ `terms` ใน `tretaresia_patch` ของคำตอบปกติเดียวกัน รวมถึง Swipe/Regenerate คำตอบซื้อ/ขายที่ขาดรายการจะไม่เรียก API เติมอัตโนมัติ |
| พักหนึ่งคืนกลายเป็นซื้อห้องถาวร | legacy default ใช้ `permanent` และตัวตรวจรายการที่ต้องมีเงื่อนไขไม่ครอบคลุมชื่อ “ห้องส่วนตัวชั้นบน” หรือ “ห้องกว้างหน่อย” | ครอบคลุมชื่อเหล่านี้และปฏิเสธการตีความราคาต่อคืนเป็นกรรมสิทธิ์ถาวร เงื่อนไขที่ขาดจะแสดงว่ายังไม่ยืนยันและปิดการซื้อ ไม่แสดงว่าเป็นเจ้าของตลอดไป |
| ต่อโรลหลังซื้อเป็น plain text | commerce prompt ใช้คำว่า `optional tr markup` และรับ prose ได้โดยไม่จัดรูปแบบ | บังคับ `<tr-narrative>` สำหรับการกระทำ และ `<tr-dialogue name="...">` สำหรับคำพูด หาก provider ยังส่ง prose หรือส่งแท็กสลับกับ prose จะครอบข้อความส่วนที่ขาดแท็กในเครื่อง โดยไม่เรียก AI อีกครั้ง |
| ปุ่มฝึกล้นขอบขวา | grid ใช้ `1fr 1fr` ซึ่งยังขยายตามความกว้างขั้นต่ำของข้อความ/ปุ่มจาก host | ใช้ `minmax(0,1fr)` และกำหนดขนาด/การตัดบรรทัดของปุ่มให้หดตามกรอบ หน้าจอแคบกว่า 350 px ใช้หนึ่งคอลัมน์ |
| แจ้งว่าอ่านผลฝึกไม่ได้ | การฝึกใช้ quiet prompt ที่อาจรับ preset แชตเข้ามา และ parser เดิมอ่านได้เฉพาะ JSON ตรงหรือ fence ที่หุ้มทั้งคำตอบ | ใช้ native task API พร้อม system prompt JSON แยกจาก preset เมื่อ host รองรับ เพิ่มงบคำตอบเป็น 2,048 tokens และอ่าน JSON สมบูรณ์หลัง thinking/fence หรือใน wrapper ที่รองรับ |

ภาพข้อผิดพลาดฝึกไม่มีคำตอบดิบ จึงยังระบุไม่ได้ว่า provider ส่ง prose, JSON มี wrapper หรือ JSON ไม่ครบในครั้งนั้น การแก้ครอบคลุมเส้นทางส่งและรูปแบบรับที่ตรวจพบ หากคำตอบไม่มีผลฝึกที่ใช้ได้หรือมีผลขัดแย้งกัน ระบบยังปฏิเสธอย่างถูกต้อง ไม่เพิ่ม Mastery ไม่เรียกซ้ำอัตโนมัติ และแสดงคำตอบดิบใน “ดูข้อมูลข้อผิดพลาด” เพื่อวินิจฉัยตรงจุด

## การทำงานหลังอัปเดต

1. AI ตอบฉากขาย พร้อมรายการทุกตัวและรายละเอียดใน invisible patch ของคำตอบเดียว หน้าต่างซื้อเปิดทันที ไม่มีงาน API สำหรับสร้างรายการตามหลัง
2. การพักห้องหนึ่งคืนเป็น `access` มีขอบเขต ระยะเวลาหรือเวลาสิ้นสุด สิ่งที่รวม มัดจำ และชื่อกุญแจที่ NPC แจ้งในเรื่อง กุญแจเข้า Inventory พร้อมสิทธิ์พัก ไม่ใช่กรรมสิทธิ์ถาวรของห้อง
3. รายการเลือกแต่ละตัวแสดงคำอธิบาย คุณสมบัติ และเงื่อนไขของตัวเองในรายละเอียดตะกร้า
4. กดเสนอ/ยืนยันยังเป็นคำขอให้ NPC ตัดสินผ่าน API หนึ่งครั้งตามเดิม พร้อมแจ้งเตือนก่อนเรียก ต่อโรลลงข้อความ AI เดิมด้วยรูปแบบ narrative/dialogue และตัดเงิน/ส่งมอบครั้งเดียว
5. กดฝึกเป็นคำขอประเมินหนึ่งครั้ง หากอ่านผลไม่ได้จะไม่เพิ่มความชำนาญ ปุ่มกลับมาให้เลือกใหม่ และดูรายละเอียดข้อผิดพลาดได้ ผลสำเร็จครั้งถัดไปจะล้างข้อมูลข้อผิดพลาดเก่า

ฟังก์ชัน recovery เดิมยังอยู่และได้รับ schema ใหม่ การแก้ครั้งนี้หยุดการเรียกเติมรายการซื้อ/ขายอัตโนมัติหลังคำตอบปกติ พฤติกรรม recovery ประมูลที่มีอยู่เดิมยังคงเดิม

## ตรวจสอบ

- 745 unit/host tests ผ่าน พร้อม syntax checks
- ทดสอบ production loader ที่ 320 / 390 / 1280 px: รายการห้องพร้อมเงื่อนไขเปิดจากคำตอบเดียวและไม่มี API เติมรายการ การยืนยันหนึ่งครั้งตัด 5 เงินและส่งกุญแจหนึ่งชิ้น/สิทธิ์พักหนึ่งรายการ ต่อโรลด้วยบล็อก narrative/dialogue บน DOM จริง และคำตอบที่ขาด catalog ไม่เรียก API เพิ่ม
- ฝึก Fire Ball และวิชาดาบผ่าน native task API พร้อมแจ้งก่อนเรียก รับผล JSON หลัง thinking/fence และ wrapper ได้ ตรวจปุ่มทั้งสี่ไม่ล้นกรอบแม้จำลอง host กำหนดความกว้างขั้นต่ำให้ปุ่ม
- ผลฝึกผิดรูปแบบไม่เพิ่ม Mastery และไม่ retry อัตโนมัติ ตรวจการยกเลิกระหว่างรอผล การ retry ที่ผู้ใช้กดเอง และการล้างข้อผิดพลาดหลังรับผลใหม่
- regression ซื้อ/ขาย/ประมูล/กระดานและสัญญาซื้อเดิม รวมถึงเงินต่างหน่วย การคืนมัดจำ สิทธิ์หมดอายุ และงานบริการ

คำตอบ provider ในการทดสอบเป็น fixtures เพื่อวัดจำนวน API การประมวลผลและ UI ไม่มีการทดสอบด้วยบัญชีโมเดลจริงของผู้ใช้
