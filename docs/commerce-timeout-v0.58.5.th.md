# ระบบซื้อ: timeout 524 และชื่อหนังสือไม่ตรง — 0.58.5

## รายงานล่าสุดบอกอะไร

`opening-api`, `generation:native-data`, `providerError:"Got response status 524"`, `rawResponse:null` หมายถึงคำขอเติมข้อเสนอไม่ได้รับข้อความคำตอบก่อนโฮสต์โยน error รอบนี้ไม่ใช่ JSON ที่ถูก story Regex ลบ หลังเปลี่ยนเส้นทางรับข้อมูลแล้วก็ยังมีปัญหา gateway/provider ได้

สำหรับ Cloudflare สถานะ [524](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/) คือการเชื่อมต่อ origin สำเร็จแต่การตอบกลับ/เขียนข้อมูลไม่ทันกำหนด รายงานนี้ไม่ได้ระบุ gateway URL หรือเวลา จึงยังบอกไม่ได้ว่า provider ตัวไหนช้า หรือใช้ timeout เท่าใด การแก้ extension ไม่สามารถรับรองว่าจะกำจัด timeout ฝั่ง provider ได้

ส่วน `invalid-data` / `item-not-public` เป็นอีกปัญหาหนึ่ง: JSON ใช้ชื่อเต็ม เช่น “คัมภีร์เวทศรวายุ” แต่บทพูด Barth ที่ผู้ใช้ให้ก่อนหน้านี้ใช้ “คัมภีร์ศรวายุ” รวมถึงชื่อคู่มือและบันทึกที่ต่างกัน ตัวตรวจข้อเสนอใช้ชื่อในบทพูดเป็นหลัก จึงไม่ยอมเปิดรายการจากชื่อที่ไม่ตรงกัน รายงาน error ล่าสุดและภาพไม่ได้มีบทพูดล่าสุดครบทั้งข้อความ การทดสอบชื่อสั้นใช้บทพูดฉบับเต็มที่ผู้ใช้ให้ก่อนหน้านี้

## เปลี่ยนอะไร

เพิ่มตัวอ่านรายการหนังสือภาษาไทยจากข้อเสนอที่แจกแจงชื่อ ราคาแต่ละเล่ม และยอดรวมครบ เช่น “ข้าคิดคัมภีร์ศรวายุสิบสามเหรียญเงิน คู่มือบาเรียแสงสิบแปดเหรียญเงิน และบันทึกกระแสออร่าเก้าเหรียญเงิน รวมกันเป็นสี่สิบเหรียญเงินพอดีเป๊ะ” ตัวอ่านตรวจว่ายอดรวมตรงกับผลบวกราคาสินค้า ใช้เฉพาะบทพูดสาธารณะของผู้ขายคนเดียว และไม่สร้าง stock หรือราคาต่อเล่มจากยอดรวมล้วน

กรณีมี inline data ที่ไม่ผ่านตรวจ ผู้ใช้กด **“เติมรายการจากบทพูด NPC”** ได้ถ้าข้อเสนออยู่ในรูปแบบที่อ่านได้ ระบบสร้างรายการใหม่จากชื่อที่ NPC พูดจริง โดยไม่ใช้ชื่อหรือคุณสมบัติของ inline object ที่ถูกปฏิเสธ และไม่เรียก API สำหรับการเติมครั้งนี้ หน้าจอแจ้งว่ารายละเอียดวิชาที่ไม่ได้ระบุยังเป็นไม่ทราบ การเติมไม่หักเงิน ไม่เพิ่ม Inventory หรือวิชา และยังต้องยืนยันซื้อแยกต่างหาก

ข้อเสนอใหม่ที่ไม่มี inline object ใช้ตัวอ่านนี้ในเส้นทางอ่าน catalog ตามปกติด้วย ส่วน inline object ที่ขัดกับบทพูดยังคงถูกปฏิเสธ ไม่เปิดอัตโนมัติด้วยการจับคู่ชื่อแบบคล้ายกัน

สำหรับข้อเสนอที่ยังต้องให้ AI เติม ลด response budget ของรายการเล็กจาก 8,192 เป็น 4,096 โทเคน และกำชับให้รายละเอียดกระชับ รายการใหญ่ยังมีงบ 8,192 ตามเดิม และเคารพขีดจำกัดที่อ่านได้จาก host settings การลดงบช่วยจำกัดขนาดคำตอบ แต่ไม่ได้พิสูจน์ว่า timeout เดิมเกิดจากจำนวนโทเคน

ตัวกลางอ่าน HTTP status จาก exception ที่มีเพียงข้อความ เช่น “Got response status 524” ได้ด้วย หน้าจอเติมข้อเสนอจะแจ้ง timeout 524 พร้อมแนะนำลองใหม่ภายหลังหรือเลือกการเชื่อมต่อที่ตอบเร็วขึ้น ไม่มีการเรียก API ซ้ำอัตโนมัติ

## ผลตรวจ

- Unit/host tests **1,037/1,037 ผ่าน** ไม่มี failure หรือ skipped tests และ syntax checks ผ่าน
- ทดสอบรายการหนังสือสามเล่ม ชื่อที่พูดจริง ราคาปัจจุบัน 13/18/9 ตะกร้าอย่างละหนึ่งรวม 40 การเติมโดยไม่เรียก API และการกดซ้ำโดยไม่บันทึกซ้ำ
- ทดสอบว่าเงิน Inventory และวิชาไม่เปลี่ยนระหว่างเติม และไม่แต่ง learning definition จากชื่อหนังสือ
- ปฏิเสธยอดรวมผิด สกุลเงินปน ชื่อซ้ำ ข้อเสนออนาคต planning ยอดรวมล้วน และข้อความที่ถอนความจริงของข้อเสนอ
- ทดสอบ error 524 ว่าเรียกครั้งเดียว เก็บ status และไม่บันทึกธุรกรรม พร้อมตรวจงบคำตอบของรายการเล็ก/ใหญ่

ไม่มี Chromium จึงไม่ได้รัน browser suites ของรุ่นนี้ และไม่ได้เรียก provider ของผู้ใช้ ผลจึงไม่ได้รับรองว่า API เดิมจะตอบสำเร็จหลังอัปเดต

## ใช้หลังอัปเดต

อัปเดตจาก main แล้วโหลดหน้าใหม่ให้เป็น **0.58.5** หากบทพูดล่าสุดมีชื่อและราคาแจกแจงครบตามรูปแบบนี้ จะมีปุ่ม **“เติมรายการจากบทพูด NPC”** ให้ตรวจชื่อสินค้าและยอดรวมก่อนยืนยัน ส่วนปุ่ม **“ให้ AI เติมข้อมูลรายการ”** ยังใช้ API หากพบ 524 ให้ตรวจการเชื่อมต่อ/provider หรือทดลองภายหลัง หากบทพูดล่าสุดต่างจากตัวอย่างและยังขึ้น `item-not-public` ต้องใช้บทพูดล่าสุดทั้งข้อความเพื่อวินิจฉัยต่อ ไม่สามารถพิสูจน์ความหมายของชื่อที่ต่างกันจากชื่อใน error เพียงอย่างเดียวได้
