# Memory Summaries — คู่มือ RoleForge v0.46.3

ระบบนี้เก็บข้อความต้นฉบับ สรุปเหตุการณ์เป็นบท และค้นประวัติที่เกี่ยวข้องเพื่อประกอบคำตอบในแชตใหม่ ใช้ร่วมกับ Story Memory และ Continuity โดยไม่เพิ่มเงิน ของ หรือเปลี่ยนสถานะเควสต์จากข้อความสรุป

## เริ่มใช้

1. อัปเดต RoleForge และโหลดหน้าใหม่หนึ่งครั้ง ไม่ต้องรีเซ็ตข้อมูล RPG
2. ใน **Extension Settings → RoleForge → Optional systems** เปิด **Memory Summaries** แล้วเปิดหน้าต่าง RPG → **Memory Summaries / สรุปความจำ** การตั้งค่าเปิดระบบที่บันทึกไว้แล้วคงอยู่
3. เปิด **ขนาดชุดสรุป API และงบ context** เลือกจำนวนข้อความต่อคำขอ ผู้ใช้ใหม่เริ่มต้น **5 ข้อความ** ปรับได้ **1–100 ข้อความ** มีปุ่มเลือก 5 / 10 / 20 / 50 แล้วกด **บันทึกการตั้งค่า** ขนาดชุดที่ผู้ใช้เดิมบันทึกไว้คงเดิม
4. ใน **API / โมเดลสำหรับสรุป** เลือก **แชตหลัก: API และโมเดลปัจจุบันของ SillyTavern** หรือโปรไฟล์ที่สร้างไว้ใน SillyTavern Connection Manager เมื่อต้องการใช้โมเดลอื่น ค่าเริ่มต้นเปิดสรุปอัตโนมัติเมื่อมี 15 คำตอบตัวละครที่ยังไม่สรุป ปรับเกณฑ์ได้ 5–100 คำตอบ หรือปิดเพื่อกดสรุปเอง จำนวนนี้เป็นเกณฑ์เริ่มงาน ส่วนขนาดชุดกำหนดจำนวนข้อความผู้เล่นและตัวละครรวมกันต่อคำขอ
5. การเปิดแชตเก่าจะเก็บข้อความที่โหลดอยู่เข้าคลังในเครื่อง แต่ยังไม่เรียก AI ย้อนหลังเองตอนเปิดหน้า กด **สรุปข้อความที่ยังเหลือ** เมื่อต้องการสรุปประวัติเดิม
6. หากต้องการนำความจำไปใช้ในคำตอบ เปิด **ส่งความจำที่เลือกเข้า prompt เนื้อเรื่อง** และเชื่อมต่อ API สำหรับเล่นเรื่องตามปกติ

ในส่วนตั้งค่าเดียวกัน มี **เวลารอ API ต่อคำขอ (วินาที)** เริ่มต้น **240 วินาที** ปรับได้ **60–600 วินาที** เป็นเวลารอของแต่ละชุด ไม่ใช่เวลารวมทั้งงาน เพิ่มเวลาได้สำหรับโมเดลช้า แต่ไม่ได้เพิ่มความเร็วของโมเดล

ตัวเลือกแชตหลักใช้เส้นทาง `generateRaw()` ของ SillyTavern พร้อม API โมเดล และการตั้งค่าเจนปัจจุบัน คล้ายกับโหมด Raw ของส่วนเสริม Summarize ที่มากับ SillyTavern เป็นคำขอสรุปแยกที่ไม่เพิ่มข้อความลงในเรื่อง หากอยากให้สรุปเร็วขึ้น เลือกโปรไฟล์โมเดลที่ตอบเร็วได้ โดยไม่ต้องเปลี่ยนโมเดลเล่นเรื่อง

คำขอสรุปตั้งเป้าคำตอบกระชับประมาณ 1,600 โทเคน และขอ output สูงสุด 2,400 โทเคน มีเหตุการณ์พร้อมหลักฐานไม่เกินแปดรายการต่อชุด ข้อความต้นฉบับยังอยู่ครบในคลังและค้นย้อนหลังได้ แม้รายละเอียดบางอย่างไม่ได้อยู่ในสรุป การสรุปใช้ input/output tokens ของผู้ให้บริการที่ตั้งค่าไว้ ไม่ต้องใส่ API key ใน RoleForge

## Workflow: กดสรุปขณะคำตอบหลักยังสร้างอยู่

1. กด **สรุปข้อความที่ยังเหลือ** ได้แม้คำตอบเนื้อเรื่องกำลังสร้าง
2. ระบบตรวจสถานะเจนจริงของ SillyTavern ถ้ายังทำงานอยู่ งานสรุปเข้าสถานะ **สรุปอยู่ในคิว รอคำตอบเนื้อเรื่องสร้างเสร็จ** โดยไม่ส่ง API สรุปและไม่เริ่มจับเวลาหมดอายุของคำขอสรุป
3. ดูสถานะคิวได้ในหน้า Memory Summaries และแถบเหนือช่องพิมพ์ใน Main Chat บทที่บันทึกสำเร็จก่อนหน้านี้ยังอยู่
4. เมื่อคำตอบหลักจบ งานสรุปเริ่มเองทันที ไม่ต้องกดทำต่อและไม่ต้องหยุดคำตอบหลัก
5. ถ้าไม่ต้องการทำแล้ว กด **ยกเลิกคิวสรุป** คำตอบเนื้อเรื่องยังทำงานต่อได้ตามปกติ

ในรุ่นก่อน สถานะ Start บางครั้งค้างแม้คำตอบหลักจบแล้ว ทำให้ขึ้น `MEMORY_GENERATION_WAIT_TIMEOUT` โดยยังไม่ได้เรียก API สรุป รุ่นนี้อ่านสถานะจริงแทน หากข้อความผิดพลาดเดิมยังแสดงอยู่ หลังอัปเดตและโหลดหน้าใหม่ให้กด **ลองใหม่ / ทำต่อ**

## ข้อมูลสามระดับ

| ระดับ | เนื้อหา | เมื่อใดเข้าโมเดล |
|---|---|---|
| คลังต้นฉบับ | ข้อความผู้เล่นและตัวละครที่โหลดอยู่ รวมข้อความก่อนแก้หรือเปลี่ยน swipe ที่ระบบเคยเก็บ | ส่งเฉพาะช่วงที่สรุปหรือค้นมาใช้ |
| บทสรุปและดัชนี | เหตุการณ์ บุคคล สถานที่ คำสำคัญ หลักฐาน และภาพรวมต่อเนื่อง | ใช้สร้างภาพรวมและค้นตามบริบท |
| ความจำใน prompt | ภาพรวมและข้อความอ้างอิงที่เลือก ภายในงบโทเคน | แนบกับคำขอคำตอบหลัก |

คลังไม่คัดลอกข้อความต้นฉบับทั้งหมดเข้า RPG state หรือทุก turn checkpoint ข้อมูลขนาดใหญ่เก็บแยกใน IndexedDB ของเบราว์เซอร์นี้ ส่วน Continuity ส่งต่อจุดเชื่อมประวัติและสถานะ RPG

## Workflow: คืนที่ตกปลาแล้วพบคอร่า

1. เรื่องเล่าว่าผู้เล่นออกไปตกปลาที่แม่น้ำตอนกลางคืน แล้วพบคอร่าเป็นครั้งแรก
2. เมื่อคำตอบจบ ระบบเก็บข้อความต้นฉบับ หากมีข้อมูลฉากที่ยืนยันแล้ว จะเก็บวัน เวลา และสถานที่ประกอบ
3. เมื่อถึงช่วงสรุปหรือกดสรุปเอง API อ่านข้อความที่ยังไม่สรุป พร้อมภาพรวมก่อนหน้าและข้อมูล RPG ปัจจุบันที่เกี่ยวข้อง
4. AI ส่งเหตุการณ์ เช่น “พบคอร่าที่แม่น้ำเป็นครั้งแรก” พร้อมบุคคล สถานที่ คำค้น และคำพูดตรงจากข้อความต้นทาง
5. ระบบตรวจรูปแบบ หมายเลขข้อความ และคำอ้างอิง หากหลักฐานไม่ตรง จะไม่รับผลสรุปชุดนั้น เก็บบทก่อนหน้าไว้ และแจ้งปัญหา
6. ค้น **คอร่า / แม่น้ำ / ตกปลา / กลางคืน** ในหน้า Memory Summaries เพื่อดูเหตุการณ์และต้นฉบับได้ หาก AI ไม่เก็บเป็นเหตุการณ์ ด้านข้อความต้นฉบับยังค้นได้
7. กดหมายเลขข้อความเพื่อดูหลักฐาน หรือกด **เลือกใช้ประกอบคำตอบ** เพื่อจัดรายการนั้นไว้ก่อนภายในงบความจำที่ค้นได้
8. เมื่อบทสนทนาพูดถึงคอร่าหรือแม่น้ำ ระบบค้นในประวัติที่เชื่อมไว้และเลือกข้อมูลไปให้ AI ก่อนตอบ การค้นปกติเป็นการค้นชื่อ คำ และข้อความในเครื่อง ไม่เรียก embedding API เพิ่ม

คำค้นที่ต่างจากต้นฉบับมากอาจค้นไม่พบ ให้ลองชื่อเดิม ชื่ออื่นที่มีในเรื่อง หรือสถานที่ การเลือกใช้ประกอบคำตอบไม่ขยาย context เกินงบที่ตั้งไว้ หากรายการใหญ่เกินงบ ให้เพิ่มงบหรือแก้สรุปให้กระชับ

## Workflow: ย้ายไปเล่นแชตใหม่

1. ในแชตต้นทาง เปิดระบบ Memory Summaries และตรวจว่าเชื่อมต่อ API สำหรับสรุปแล้ว
2. เปิด Memory Summaries แล้วกด **เตรียมความจำสำหรับแชตใหม่**
3. ระบบสรุปช่วงที่ยังเหลือทั้งในแชตปัจจุบันและประวัติต้นทางที่เชื่อมไว้ งานแชตยาวอาจมีหลายคำขอ API ระบบทำทีละชุดและแสดงความคืบหน้า
4. รอข้อความ **เตรียมความจำสำหรับแชตใหม่สำเร็จแล้ว** และตรวจว่าข้อความรอสรุปรวมประวัติที่เชื่อมไว้เป็น 0 ถ้ามีคำเตือนเตรียม prompt ไม่สำเร็จ ให้แก้ตัวนับโทเคนหรืองบความจำก่อนเล่นต่อ สรุปที่บันทึกแล้วคงอยู่ แต่ยังไม่ถือว่าความจำพร้อมแนบคำตอบ
5. ตรวจ **คลังบทสรุปและรุ่นแก้ไข** และ **รุ่นความจำที่เตรียมย้ายแชต** หากเนื้อหาผิด ให้แก้ภาพรวม/บทสรุป แล้วเตรียมใหม่
6. ในการตั้งค่า Continuity เปิด **Carry this character into new chats automatically** แล้วใช้คำสั่ง New Chat ตามปกติ
7. Continuity นำสถานะ RPG ล่าสุดและจุดเชื่อมประวัติเข้าแชตใหม่ สรุปไม่ได้คำนวณเงินหรือของใหม่
8. เล่นต่อจากฉากล่าสุด เมื่อกำลังสร้างคำตอบ ระบบเตรียมภาพรวมและค้นประวัติตามข้อความล่าสุดก่อนส่งให้ AI โดยระบุว่าเป็นเรื่องที่เกิดไปแล้ว ไม่ใช่เหตุการณ์ใหม่ให้จ่ายรางวัลซ้ำ

ถ้าเปลี่ยนแชตก่อนเตรียมเสร็จ ระบบยกเลิกรับผลคำขอเดิม บทที่บันทึกสำเร็จยังอยู่ แต่ไม่ควรถือว่าประวัติครบ ให้กลับมาทำต่อหรือเตรียมจากแชตใหม่ที่เชื่อมประวัติเดิมไว้

หากไม่เปิด Continuity ให้ใช้ **เลือกประวัติที่จะใช้ในแชตนี้ → นำประวัตินี้มาใช้** เพื่อเชื่อมคลังเรื่องเอง การเชื่อมความจำอย่างเดียวไม่คัดลอกสถานะ RPG ต้องจัดการสถานะผ่าน Continuity หรือ Import state แยกกัน

## Workflow: สรุปแชตยาวทีละ 5–10 ข้อความ

1. เปิด **ขนาดชุดสรุป API และงบ context** เลือก 5 หรือ 10 ข้อความ แล้วบันทึก หาก API เร็วและงบเพียงพอ เพิ่มได้สูงสุด 100 ข้อความ
2. กด **สรุปข้อความที่ยังเหลือ** ระบบนับข้อความต้นฉบับที่ยังมีส่วนรอสรุป แล้วเลือกชุดแรกตามขนาดที่ตั้งไว้
3. ถ้าคำตอบหลักกำลังสร้าง ระบบรอคิวและเริ่มเองเมื่อจบ ก่อนส่ง API ระบบนับโทเคนรวมคำสั่ง ภาพรวม และข้อความชุดนั้น หากตัวนับค้างเกินสองวินาที ใช้ค่าประมาณแบบเผื่อ หากเกินงบ input จะลดชุดลงอีก
4. API สรุปเฉพาะชุดนี้ ระบบตรวจหลักฐานและบันทึกบทสรุปลง IndexedDB ให้สำเร็จ **ก่อนเริ่มคำขอชุดถัดไป**
5. หน้าจอแสดงข้อความรอสรุป ข้อความที่สรุปและบันทึกในงานนี้ ชุดที่บันทึกแล้ว ชุดปัจจุบันโดยประมาณ และเวลาที่ใช้ แถบงานนอกหน้าต่างยังแจ้งว่าระบบกำลังทำขั้นตอนไหน
6. หากมี 23 ข้อความและตั้งชุดละ 10 โดยข้อความไม่ยาวเกินงบ จะเป็น **10 → บันทึก → 10 → บันทึก → 3 → บันทึก** ไม่ต้องรอทุกคำขอจบก่อนจึงเก็บผล
7. หากยกเลิก โหลดหน้าใหม่ เปลี่ยนแชต หรือคำขอชุดหลังล้มเหลว ชุดที่บันทึกก่อนหน้านั้นยังอยู่ กด **ลองใหม่ / ทำต่อ** หรือกดสรุปอีกครั้งเพื่อทำเฉพาะส่วนที่เหลือ ไม่ต้องสรุปชุดที่บันทึกแล้วซ้ำ
8. งานจะสำเร็จเมื่อสรุปส่วนที่เหลือตามขอบเขตงานเสร็จ หากยังมีประวัติที่เชื่อมไว้รอสรุป ให้ใช้ **เตรียมความจำสำหรับแชตใหม่** เพื่อทำรวมประวัตินั้นด้วย

**ข้อความกับช่วงข้อความต่างกันอย่างไร:** ข้อความยาวหนึ่งข้อความอาจถูกแบ่งเป็นหลายช่วงเพื่อให้อยู่ในงบ API ดังนั้น 96 ข้อความอาจมี 115 ช่วง ไม่ใช่ข้อความเพิ่มหรือคำขอ 115 ครั้ง หน้าจอใช้จำนวน **ข้อความต้นฉบับรอสรุป** เป็นตัวหลัก และแสดงจำนวนช่วงเพื่ออธิบายเฉพาะเมื่อไม่ตรงกัน ข้อความยาวมากอาจใช้หลายคำขอ และนับเป็นข้อความที่สรุปเสร็จเมื่อทุกช่วงของข้อความนั้นบันทึกครบ บทสรุปของช่วงที่ทำแล้วจะเก็บไว้ก่อนเช่นกัน จำนวนชุดที่แสดงจึงเป็นค่าประมาณและปรับได้เมื่อจัดให้อยู่ในงบจริง

ขนาด 5–10 ทำให้แต่ละคำขอสั้นลง แต่เวลารวมยังขึ้นกับความยาวข้อความ โมเดล และความเร็วผู้ให้บริการ การแบ่งชุดเพิ่มจำนวนคำขอและมีค่าใช้จ่ายคำสั่ง/ภาพรวมซ้ำ ไม่รับประกันว่าค่าโทเคนรวมจะลดลง

## Workflow: สรุปอัตโนมัติและสรุปเอง

- **สรุปอัตโนมัติ:** ตรวจจำนวนคำตอบตัวละครที่ยังไม่สรุปหลังคำตอบจบ เมื่อถึงช่วงที่กำหนด เรียกสรุปหนึ่งชุด หากข้อความยาวมาก อาจยังมีส่วนรอสรุปอยู่
- **สรุปข้อความที่ยังเหลือ:** ประมวลผลข้อความที่ยังไม่สรุปในแชตปัจจุบันจนหมดทีละชุด เหมาะกับประวัติแชตเก่าหรือจบบทเอง
- **เตรียมความจำสำหรับแชตใหม่:** ทำประวัติที่ยังเหลือในแชตและต้นทางที่เชื่อมไว้ทั้งหมด แล้วบันทึกรุ่นส่งต่อและจุดเชื่อม
- **หลังงานอัตโนมัติล้มเหลว:** ระบบไม่เรียกซ้ำทุกครั้งที่เปิดหน้าต่าง กด **ลองใหม่ / ทำต่อ** ได้ หากเล่นต่อจนมีข้อความค้างเพิ่มครบอีกช่วง ระบบจึงลองอัตโนมัติใหม่
- หากคำตอบหลักกำลังสร้าง งานสรุปเข้าคิวและเริ่มเองเมื่อคำตอบจบ ไม่มี Timeout ของ API สรุประหว่างรอคิว

## สถานะและ Notifications

มีสถานะในหน้า Memory Summaries และแถบงานที่ช่องพิมพ์ในแชตหลัก แม้ปิดหน้าต่าง RoleForge ก็ยังดูได้ว่ารอคำตอบหลัก ตรวจโทเคน เรียก AI สรุป หรือบันทึกอยู่ แถบแสดงความคืบหน้า จำนวนชุดที่บันทึกแล้ว และเวลาที่ใช้ พร้อมปุ่มเปิดรายละเอียด สถานะงานยังแสดงแม้ปิดการแจ้งรางวัล RPG

เมื่อกำลังเรียก AI สรุปและแชตหลักไม่ได้สร้างคำตอบ มีปุ่มหยุดสรุปในบริเวณปุ่มส่งข้อความ กดแล้วหยุดงานสรุปเท่านั้น ปุ่มและระบบส่ง/หยุดคำตอบหลักของ SillyTavern ยังเก็บไว้และกลับมาใช้งานตามเดิม เมื่อแชตหลักกำลังสร้างคำตอบ ปุ่มหยุดของแชตหลักทำงานกับคำตอบหลักตามปกติ งานสรุปมีตัวควบคุมของตัวเองในแถบสถานะ

ช่องพิมพ์และข้อความที่ยังไม่ส่งไม่ถูกเปลี่ยนหรือปิดใช้งาน เมื่อสำเร็จหรือยกเลิก แถบแสดงผลต่ออีก 8 วินาทีแล้วซ่อนเอง ถ้ามีปัญหา แถบยังอยู่ให้กด **รายละเอียด / ลองใหม่ / ซ่อน** ได้ ปุ่มส่งข้อความกลับมาใช้งานทันทีเมื่อหยุดงานสรุป

| งานก่อนหน้าหยุดกลางทาง | โหลดหน้าใหม่ระหว่างทำงาน กดลองใหม่เพื่อทำช่วงที่เหลือ |

### Workflow: API สรุปหมดเวลารอ

1. ระบบรอแต่ละคำขอตาม **เวลารอ API ต่อคำขอ** ที่ตั้งไว้ ค่าเริ่มต้น 240 วินาที
2. ถ้า AI ยังส่งผลไม่ครบเมื่อหมดเวลา งานหยุดพร้อมรหัส **`MEMORY_API_TIMEOUT`** ไม่บันทึกผลที่ยังไม่ครบหรือผลที่กลับมาช้าหลังหยุด
3. บทที่บันทึกก่อนหน้าอยู่ครบ ข้อความที่ยังไม่สำเร็จยังอยู่ในจำนวนรอสรุป เปิด **รายละเอียดปัญหา** เพื่อดูขั้นตอนที่หยุด รหัสปัญหา และเวลาที่รอในขั้นตอนนั้น
4. ระบบเสนอให้คำขอถัดไปสั้นลง โดยลดจำนวนข้อความของชุดที่หมดเวลาเหลือประมาณครึ่งหนึ่ง ขั้นต่ำหนึ่งข้อความ ข้อความเดียวที่ยาวมากยังลดจำนวนอักขระต่อคำขอได้
5. กด **ลองใหม่ / ทำต่อ** จึงเริ่มเรียก API อีกครั้งด้วยขนาดที่แนะนำ การตั้งค่าขนาดชุดเดิมยังคงอยู่ ไม่มีการลองเรียก API เสียโควต้าใหม่เองหลังหมดเวลา
6. ระบบทำเฉพาะต้นทางที่ยังเหลือ บันทึกทันทีทุกชุดเช่นเดิม หากต้องการใช้ขนาดที่ตั้งไว้แทนขนาดลดลง ให้กด **สรุปข้อความที่ยังเหลือ** หรือแก้การตั้งค่า/เลือกโปรไฟล์ที่เร็วขึ้นก่อนเริ่มงานใหม่

การหมดเวลาบอกได้ว่า API ส่งผลไม่ทัน แต่บอกไม่ได้แน่ชัดว่าเป็นเพราะโมเดลช้า การเชื่อมต่อ หรือคำตอบยาว การยกเลิกส่งสัญญาณหยุดคำขอผ่าน API ที่รองรับ บางผู้ให้บริการยังประมวลผลต่อได้แม้ RoleForge หยุดรับผลแล้ว และอาจคิดโควต้า/โทเคนของคำขอที่ส่งไปแล้ว

### แยกประเภทปัญหา

| รหัส | ความหมาย / วิธีทำต่อ |
|---|---|
| `MEMORY_API_TIMEOUT` | โมเดลสรุปส่งผลไม่ทันเวลาของคำขอ กดทำต่อด้วยชุดเล็กลง เพิ่มเวลารอ หรือเลือกโปรไฟล์อื่น |
| `MEMORY_API_REQUEST_FAILED` | API ปฏิเสธคำขอหรือการเชื่อมต่อล้มเหลว ตรวจ API โมเดล และโควต้าก่อนลองใหม่ |
| `MEMORY_TOKEN_COUNT_TIMEOUT` | ตัวนับโทเคนตอบไม่ทัน ไม่ใช่การเรียก AI สรุป ส่วนการแนบความจำเข้า prompt หลักจะหยุดไว้จนตัวนับกลับมา |
| `MEMORY_GENERATION_WAIT_TIMEOUT` | ปัญหาจากสถานะรอของรุ่นก่อน อัปเดต โหลดหน้าใหม่ และกดทำต่อ รุ่นนี้รอเป็นคิวโดยไม่มี Timeout ของ API สรุประหว่างรอ |
| `MEMORY_INVALID_SUMMARY` | AI ส่งสรุปไม่ครบตามรูปแบบ เช่น JSON ไม่สมบูรณ์ ลองใหม่หรือเลือกโมเดลอื่น |
| `MEMORY_UNSUPPORTED_EVIDENCE` | เหตุการณ์ที่ AI สรุปไม่มีคำอ้างอิงตรงกับต้นทาง จึงไม่รับสรุปชุดนั้น |

งานสรุปที่ตัวนับโทเคนค้างเกิน **สองวินาที** หรือใช้งานไม่ได้ จะใช้จำนวน UTF-8 bytes เป็นค่าประมาณแบบเผื่อสำหรับจัดงบและแสดงคำเตือน ทำให้บันทึกคำตอบสรุปที่ตรวจรูปแบบและหลักฐานผ่านแล้วได้ การแนบความจำเข้า prompt เนื้อเรื่องยังใช้การนับโทเคนตามปกติ หากขั้นตอนนั้นนับไม่ได้หรือเกินงบ จะล้าง prompt ความจำส่วนที่มีปัญหาและแจ้งคำเตือน **บันทึกสรุปแล้ว แต่ยังเตรียมความจำสำหรับแนบคำตอบเนื้อเรื่องไม่สำเร็จ** เมื่อแก้ปัญหาแล้ว ระบบสร้าง prompt ใหม่จากบทที่บันทึกไว้ ไม่ต้องเรียก AI สรุปบทเหล่านั้นอีก

## งบโทเคนและค่าใช้จ่าย

1. **งบ input tokens ของคำขอสรุป:** เริ่มที่ 12,000 รวมคำสั่งสรุป แหล่งข้อมูล ภาพรวมก่อนหน้า และข้อมูล RPG อ้างอิง ระบบจำกัดจำนวนข้อความตามขนาดชุดก่อน และลดจำนวนช่วงต่อคำขออีกเมื่อเกินงบ จึงอาจต้องเรียกหลายชุด
2. **งบโทเคนภาพรวม:** เริ่มที่ 1,200 ใช้กับภาพรวมประวัติที่แนบในคำตอบหลัก
3. **งบโทเคนความจำที่ค้นได้:** เริ่มที่ 1,000 ใช้กับเหตุการณ์/ต้นฉบับที่ค้นมา ระบบส่งรายการอ้างอิงที่เป็นระเบียนครบ ไม่ตัด JSON กลางรายการ
4. คำอธิบายและกรอบความจำมีโทเคนเพิ่มจากสองงบหลัง หน้าจอแสดงจำนวนข้อความความจำที่ส่งจริงรวมคำอธิบายด้วย
5. ใช้ tokenizer ของ SillyTavern เมื่อมี งานสรุปใช้จำนวน UTF-8 bytes เป็นค่าประมาณแบบเผื่อหากตัวนับไม่พร้อม ค้าง หรือผิดพลาด พร้อมแสดงคำเตือน หากโมเดลสรุปใช้โปรไฟล์อื่น จำนวนที่แสดงอาจต่างจากจำนวนเรียกเก็บของโมเดลนั้น
6. ดู input/output tokens ของคำขอสรุปล่าสุด และจำนวนคำขอส่วนเสริมใน session ได้ เป็นข้อมูลช่วยวางงบ ไม่ใช่ใบแจ้งราคาเงินของผู้ให้บริการ

ข้อความที่เก็บในคลังอย่างเดียวไม่ใช้โทเคนโมเดล แต่ข้อความที่ส่งสรุปหรือแนบคำตอบหลักใช้ input tokens จริง ทุกคำตอบที่แนบความจำอาจมีค่าใช้จ่ายซ้ำตามวิธีคิดของผู้ให้บริการ

ตัวอย่าง **90 ข้อความรอสรุป ชุดละ 5 ข้อความ = 18 API calls** หากแต่ละชุดพอดีงบและสำเร็จครั้งแรกทั้งหมด ข้อความยาวมากอาจแบ่งเพิ่มจนใช้มากกว่า 18 ครั้ง การกดทำต่อหลังคำขอล้มเหลวเพิ่มคำขอใหม่ และคำขอที่หมดเวลาหรือยกเลิกอาจถูกผู้ให้บริการนับแล้ว ระบบจึงไม่ลองเรียกใหม่โดยอัตโนมัติหลังปัญหา API

## แก้ข้อความ เปลี่ยน swipe และแก้สรุป

1. เมื่อข้อความต้นทางเปลี่ยน สรุปที่อ้างอิงข้อความนั้นและสรุปที่อาศัยภาพรวมต่อจากมันจะถูกกันออกจากการค้น/ส่ง prompt
2. กดสรุปใหม่เพื่อประมวลผลแหล่งข้อมูลที่เลือกใช้ล่าสุด ข้อความรุ่นเดิมยังอยู่ในคลัง แต่ไม่ถือเป็นเรื่องจริงปัจจุบัน
3. ในบทสรุปเก่า กดข้อความต้นทางเพื่อดูรุ่นที่บทนั้นอ้างอิงจริง มีป้าย **รุ่นก่อนแก้ไข** หากต่างจากข้อความปัจจุบัน
4. ใช้ **แก้ไขสรุป** เพื่อแก้บทนั้นและภาพรวมต่อเนื่อง ระบบเก็บข้อความสรุปก่อนแก้ไว้สูงสุด 20 รุ่นต่อบท บทถัดไปที่อ้างอิงรุ่นเดิมต้องสร้างใหม่
   เมื่อผู้เล่นแก้สรุป จะพักดัชนีเหตุการณ์ที่ AI ตีความในบทนั้นเพื่อไม่ให้ข้อมูลเดิมขัดกับการแก้ แต่ยังค้นต้นฉบับได้
5. การแก้สรุปไม่แก้เงิน ของ เควสต์ หรือข้อมูล NPC ใน RPG โดยตรง หากสถานะเหล่านั้นผิดให้แก้ในระบบของมัน

## แยกตัวละครและแขนงเรื่อง

- คลังแยกตามตัวละคร/กลุ่มที่ใช้ใน Continuity
- การค้นใช้เฉพาะแชตปัจจุบันและประวัติที่เชื่อมไว้ ไม่รวมทุกแชตของตัวละครเอง
- ใน **เลือกประวัติที่จะใช้ในแชตนี้** เพิ่มหรือเอาแชตต้นทางออกได้ เพื่อเลือกแขนงเรื่องอย่างชัดเจน
- ข้อมูลลับและข้อความที่โมเดลเห็นไม่ใช่หลักฐานว่า NPC ทุกคนรู้เรื่องนั้น prompt กำหนดให้เคารพสิ่งที่แต่ละคนเห็นหรือได้รับบอกจริง

## สำรองและย้ายอุปกรณ์

1. กด **ส่งออกคลังความจำทั้งหมด** เพื่อเก็บ JSON ที่มีต้นฉบับ บทสรุป รุ่นแก้ไข และรุ่นส่งต่อ
2. สำรอง **Export state** ของ RPG แยกด้วย หากต้องการย้ายเงิน ของ ตัวละคร และสถานะเกม
3. บนอุปกรณ์ใหม่ เปิดตัวละคร/กลุ่มเดิม แล้วนำเข้าคลังความจำและสถานะ RPG
4. เลือกประวัติที่จะใช้ในแชตปลายทาง แล้วตรวจภาพรวมก่อนเล่นต่อ
5. การนำเข้าคลังไม่เขียนทับแชตหรือบทสรุปที่มี ID เดียวกันในเครื่องแบบเงียบ ๆ และปฏิเสธไฟล์ของตัวละครอื่น

IndexedDB อยู่ในเบราว์เซอร์และ origin ของ SillyTavern นี้ ไม่ซิงก์ข้ามเครื่องเอง การล้าง site data อาจลบคลัง ต้องส่งออกสำรองก่อน หากพื้นที่เต็มจะขึ้นข้อผิดพลาดแทนการแจ้งว่าสำเร็จ

## สิ่งที่ระบบรับประกันได้และไม่ได้

เก็บข้อความผู้เล่น/ตัวละครที่โหลดเข้ามาและบันทึกสำเร็จได้ครบตามต้นฉบับ ไม่ได้ดึงแชตอื่นที่ยังไม่เปิด หรือประวัติที่โฮสต์ยังไม่ส่งมาใน context เอง รายละเอียดที่ AI ตัดจากสรุปยังค้นจากต้นฉบับได้

การตรวจหมายเลขข้อความและคำอ้างอิงช่วยกันหลักฐานปลอม แต่ไม่พิสูจน์ความหมายทุกประโยค AI ยังอาจตีความผิดได้ ต้องตรวจ/แก้สรุปเมื่อจำเป็น การค้นชื่อและคำอาจพลาดคำอ้างอิงอ้อม ๆ และ AI เห็นเฉพาะข้อมูลที่เลือกเข้า context ไม่ได้อ่านคลังทั้งหมดทุกคำตอบ
