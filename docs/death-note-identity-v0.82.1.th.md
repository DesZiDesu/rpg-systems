# Death Note — ชื่อ ใบหน้า และการจดไว้รอคำตอบถัดไป (0.82.1)

## สิ่งที่แก้

เดิมชื่อรับจากบทแนะนำตัวของเจ้าตัวเป็นหลัก และตัวตรวจการเขียนยังบังคับ `met=true` จึงปฏิเสธคนที่เห็นผ่านข่าวหรือภาพถ่าย แม้ในโรลจะบอกชื่อและแสดงใบหน้าชัดเจนแล้ว อีกกรณีคือ NPC ในคลังการ์ดที่ยังไม่อยู่ในชุดข้อมูลฉากปัจจุบัน ทำให้ระบบสมุดหาเจ้าของชื่อนั้นไม่เจอ

รุ่นนี้อ่านหลักฐานที่แสดงในโรลสำหรับชื่อและใบหน้าแยกกัน รองรับข่าว เอกสาร ป้ายชื่อ คำบอกชื่อที่มีหลักฐาน และความรู้ที่ผู้เล่นระบุว่าเกิดขึ้นแล้ว ภาพถ่ายใบหน้าชัดเจนนับเป็นการเห็นหน้าโดยไม่ต้องเปลี่ยน `met`, เปิดใช้งาน NPC หรือดึงคนคนนั้นเข้าฉาก ระบบโหลดข้อมูล NPC ที่เกี่ยวข้องจากคลังด้วย ID ของหลักฐานและรายการจดชื่อ

ข่าวที่ให้แค่ชื่อไม่ทำให้รู้ใบหน้า ภาพเบลอ หน้ากาก ความตั้งใจว่าจะดูภาพ และข้อมูลซ่อนใน reasoning/comment ไม่เป็นหลักฐานชื่อ/หน้า ชื่อที่ได้จากคำบอกหรือข่าวเก็บเป็นชื่อที่รับรู้ จึงอาจเป็นชื่อปลอมได้ และไม่แก้ชื่อจริงในคลัง สมุดยังตรวจชื่อจริงเป็นการภายใน

เมื่อเปิดแชทเดิม ระบบอ่านหลักฐานที่ชัดเจนจากข้อความในแชทนั้นอีกครั้ง ไม่จำเป็นต้องเริ่มแชทใหม่ การเล่าแบบกำกวมหรือไม่ระบุว่าเป็นใครยังต้องให้คำตอบถัดไปยืนยันด้วยข้อความและหลักฐานที่ผูกกับ NPC ได้

## ใช้งานแบบไม่ต้องยืนยัน

1. เขียนชื่อที่ต้องการบนบรรทัดของตัวเองในสมุดเต็มหน้าหรือสมุดเหนือ chatbar ใส่สาเหตุ/เงื่อนไขใต้ชื่อได้ตามเดิม
2. ปิดสมุดหรือพลิกหน้า แล้วส่งข้อความโรลของคุณตามปกติ
3. ก่อน SillyTavern ส่งคำขอนั้น RoleForge บันทึกรายการจดชื่อที่ใช้ได้จากทุกหน้าของสมุดที่ถืออยู่ และส่งเงื่อนไขไปกับคำตอบ AI ครั้งเดียวกัน
4. AI ตอบโรลและรายงานผลตามเวลาในเรื่อง ค่าเริ่มต้นคือ 40 วินาทีในเรื่อง ส่วนเวลาที่กำหนดไว้ภายหลังจะยังรอจนถึงเวลานั้น

การพิมพ์ชื่ออย่างเดียวไม่เรียก AI และไม่เริ่มนับเวลาจริง ปุ่มตัวเล็กมุมขวาล่างเปลี่ยนเป็น **ต่อเรื่อง / Continue story** สำหรับคนที่ต้องการเรียก Continue ทันที ทั้งสองทางไม่สร้างข้อความ User เอง

ข้อความธรรมดาที่ไม่ใช่ชื่อที่ผูกกับตัวละครได้ยังเป็นข้อความบนกระดาษ ชื่อที่ยังไม่มีใบหน้าจะยังไม่ถูกส่งไปทำงานและจะแสดงเหตุผลสั้น ๆ ในสมุด โดยไม่ขัดขวางการตอบโรลตามปกติ เมื่อมีหลักฐานใบหน้าในภายหลังจึงใช้ได้

## การเก็บข้อมูล

- ใช้ journal เดิมบนข้อความ assistant: กระดาษ `roleforge_death_note_paper`, รายการชื่อ `roleforge_death_note_inscriptions_preview`, ผล `roleforge_death_note_results_preview` และหลักฐานโลก `roleforge_death_note_world_preview` ไม่เปลี่ยน key เก่า
- การบันทึกรอคำตอบถัดไปเลือกข้อความ assistant ล่าสุด แม้ตอนนั้น SillyTavern จะเพิ่มข้อความ User ที่ผู้เล่นส่งจริงไปแล้ว จึงไม่ต้องแทรก User turn สำหรับสมุด
- รายการแบบรอคำตอบถัดไปและ snapshot กระดาษหลังส่งผูกกับ index และ hash ของข้อความ User ที่ส่งจริง ถ้า Branch ตัดก่อนข้อความนั้นหรือข้อความถูกแก้ รายการจากจุดอนาคตจะไม่ทำงาน และกระดาษย้อนกลับไปใช้ snapshot ก่อนส่ง
- รายการที่ส่งแล้วมีข้อมูลหน้ากระดาษ/ข้อความต้นทาง ป้องกันการจดซ้ำจากการขยับหมึก ปรับขนาด เปิดสมุดใหม่ หรือขอคำตอบอีกครั้งหลังเน็ตล้มเหลว
- ลบหรือแก้หมึกก่อนส่งโรลได้ ผลที่เกิดในเรื่องแล้วไม่ถูกล้างด้วยปุ่มล้างกระดาษ ข้อความที่อยู่คนละแชท คนละ swipe หรือหลังจุดตัด Branch ไม่ถูกใช้เป็นความรู้ของจุดก่อนหน้า

## ตรวจสอบ

ผ่าน unit/regression รวม 1,668 รายการด้วย `npm test`, ตรวจ syntax ด้วย `npm run check` และทดสอบใน SillyTavern 1.19.0 ผ่านหน้าจอจริง:

- desktop 1440×1000 ภาษาไทย และ Chromium mobile touch emulation 390×844 ภาษาอังกฤษ
- รับชื่อและภาพถ่ายจากข่าวโดยไม่เคยพบตัวจริง รวมถึง NPC ปิดใช้งานที่อยู่ในคลังการ์ด
- NPC Management ใช้ชื่อที่เรียนรู้ ไม่ติด `???`
- เขียนโดยไม่กดปุ่มต่อเรื่อง พลิกหน้า ปิดสมุด ส่งโรล แล้วบันทึกผลและ HP ในคำตอบเดียว
- สมุดเหนือ chatbar ใช้ข้อความชื่อ/ใบหน้าที่ผู้เล่นระบุในเทิร์นล่าสุดได้ และ Branch ก่อนข้อความส่งจริงไม่มีรายการจดจากอนาคต
- ไม่มีข้อความ User ที่ระบบสร้างเพิ่ม ไม่เรียก AI ตอนพิมพ์ ไม่จดซ้ำในคำตอบถัดไป และคงข้อมูลหลัง reload
- ปิด/ย่อสมุดระหว่างรอ Continue ได้ตามเดิม รวมกรณีคำขอล้มเหลวและเปลี่ยนแชท

คำตอบทดสอบใช้ SSE ที่ควบคุมผ่านทางเดิน generation จริงของ SillyTavern ไม่ได้ต่อโมเดลภายนอกจริง และ mobile เป็นการจำลอง touch บน Chromium ไม่ใช่ Safari บน iPhone จริง โมเดลที่ใช้งานต้องยังส่งข้อความยืนยันผลตามรูปแบบที่ส่วนเสริมอ่านได้
