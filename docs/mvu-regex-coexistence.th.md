# RoleForge ร่วมกับ MVU และ Regex

รวมใน RoleForge 0.61.0 ข้อมูล RoleForge และ MVU ยังคงแยกกัน ไม่มีการซิงก์ HP เงิน หรือคลังระหว่างสองระบบ

## สาเหตุที่ตรวจพบ

- โหมด Original สามารถแทนที่ DOM เมื่อข้อความมีแท็กเนื้อเรื่องของ RoleForge ซึ่งกระทบ iframe ที่ Tavern Helper สร้างไว้ โหมด Shared เดิมรักษาการ์ดขนาดใหญ่ที่ไม่มีขอบเขตเนื้อเรื่องอยู่แล้ว จึงไม่ใช่ทุกกรณีที่ RoleForge รื้อการ์ด MVU
- Tavern Helper มีโหมด streaming ที่คัดลอก HTML ไปอีกหน้าต่างหนึ่ง ปุ่ม RoleForge ที่ถูกคัดลอกมาสูญเสีย event handler และหน้าต่างต้นฉบับอาจถูกซ่อนอยู่
- RoleForge เคยซ่อน reasoning ก่อนขั้น Regex ทำให้ Regex ที่สร้าง thinking box ไม่เหลือข้อความให้แปลง นอกจากนี้ข้อความที่ Regex ตั้งใจซ่อนทั้งหมดอาจกลับมีหัวข้อหรือปุ่ม Voice ของ RoleForge
- การเติม `<UpdateVariable>` หลังคำตอบทำให้ตัวระบุคำตอบเปลี่ยนได้ หากถือว่าเป็นคำตอบใหม่อาจประมวลผลสถานะซ้ำ ข้อความอธิบายภายในข้อมูล MVU ต้องไม่ถูกใช้เป็นหลักฐานรางวัลหรือการสังหารของ RoleForge
- ทุกครั้งที่ข้อความท้ายแชทเปลี่ยน renderer เดิมอ่านข้อมูลประกอบของประวัติทุกแถว และ event หลายชนิดสามารถตั้งงานตรวจคำตอบเดียวกันซ้ำ
- เมื่อเปิด automatic tracking เส้นทางเดิมบางกรณีเรียก AI เพิ่มเพื่อเติม Loot หรือข้อเสนอประมูลหลังข้อความหลักออกแล้ว ทำให้ต้องรออีกคำขอหนึ่ง

Regex `Hide Far Chat` และ `HideStartText` ไม่ได้ลบข้อความดิบที่บันทึกไว้ เพียงตัดข้อมูลในขั้น display หรือ prompt ตามการตั้งค่า แต่ prompt-only ที่ซ่อนประวัติยังลดข้อมูลที่ AI เห็น จึงอาจทำให้ AI ส่งข้อมูลไม่ครบได้

## การแก้ไข

- เก็บ iframe, `.TH-render` และส่วนที่ frontend ภายนอกครอบแล้วไว้ที่เดิม รวมถึงเมื่อ iframe ถูกสร้างหลัง RoleForge mount แล้ว ใช้การแสดงผลร่วมกันโดยอัตโนมัติสำหรับส่วนเหล่านี้ แม้เลือก Original
- ทำปุ่ม RoleForge ใหม่ในหน้าต่าง streaming ที่มองเห็น และเอาเฉพาะ UI ที่ RoleForge เป็นเจ้าของออกจากหน้าต่างซ่อน ปุ่มโปรไฟล์และ Voice กลับใช้งานได้
- ให้ Regex อ่าน reasoning ก่อน แล้วซ่อนเฉพาะ reasoning ที่ยังไม่ได้แปลงเป็น UI เคารพผลลัพธ์ว่างหรือถูกซ่อน และไม่ประมวลผลโค้ดตัวอย่างเป็นคำสั่งสถานะ
- ข้อความที่มีข้อมูล MVU จะไม่ถูกเขียนทับใน `message.mes`, swipe หรือ display text การอ่านสถานะใช้สำเนาที่แยก protocol ของทั้งสองระบบออกจากกัน ไม่เขียนตัวแปร MVU
- ตัวระบุคำตอบไม่นับการเปลี่ยน bookkeeping ของ MVU และยังรวมข้อมูล patch ของ RoleForge ที่เปลี่ยนจริง เก็บ alias สำหรับรายการแชทเดิมที่มี checkpoint หรือประวัติอยู่แล้ว เพื่อรักษาการอ้างอิงเดิมโดยไม่เล่นผลสถานะซ้ำ การแก้ไขนี้ไม่ย้อนสร้างข้อมูลเก่าที่สูญหายไปก่อนหน้า
- ประมวลผลคำตอบเดียวกันครั้งละงาน รวม timer ที่ซ้ำ และทิ้งงานเมื่อเปลี่ยนแชท อ่านข้อมูลประกอบใหม่เฉพาะแถวที่เปลี่ยน
- การตรวจคำตอบปกติไม่เรียก AI เพิ่มเพื่อซ่อม Loot/ประมูล เมื่อบทล่าสุดมีเหตุการณ์ที่อาจให้ Loot แต่ขาดรายการ จะมีปุ่ม **ให้ AI ตรวจ Loot จากบทล่าสุด** เหนือ chatbar พร้อมคำแนะนำให้กดหลังต่อสู้ ค้นศพ เปิดหีบ หรือสำรวจ ปุ่มเรียก AI เพิ่มหนึ่งครั้ง และยังต้องยืนยันเก็บของเอง ระบบซื้อขายใช้ปุ่มซ่อมรายการที่มีอยู่แล้ว

แนะนำใช้ Chat rendering แบบ **Shared** เมื่อเล่นร่วมกับ Regex ระบบอื่น ข้อมูล item effects การใช้ไอเทม การเรียนสกิล และการเก็บ Loot ยังคงผ่านการตรวจและบันทึกของ RoleForge ตามเดิม

## ประเด็นข้อความออกแล้วแต่ UI อัปเดตช้า

ตัวเลือก automatic tracking ในภาพที่ได้รับไม่ได้เปิดอยู่ ดังนั้นการเรียก AI เติม Loot อัตโนมัติไม่ใช่คำอธิบายสำหรับภาพนั้น การอ่านประวัติซ้ำ การชน DOM และงาน event ซ้ำยังเกิดได้ขณะปิด tracking และเป็นส่วนที่แก้ในรอบนี้

การทดสอบ renderer ด้วยประวัติ 200 ข้อความ เมื่อเปลี่ยนเฉพาะคำตอบท้ายแชท จำนวนการอ่าน scene ลดจาก **200 เป็น 1 ครั้ง** ไม่มีวงจร MutationObserver ที่ทำให้ render ซ้ำไม่จบ ผลนี้วัดงานฝั่ง browser ไม่ใช่ระยะเวลา Proxy API หรือความเร็วโมเดล การส่ง current state เข้า prompt เพิ่มขนาดคำขอได้ แต่ไม่ได้เริ่มคำขอ AI ที่สองด้วยตัวมันเอง ระบบสรุปความจำเป็นงานแยกและยังทำตามการตั้งค่าของผู้ใช้

Browser tests ครอบคลุม iframe ที่เริ่มทำงานจริงและไม่ถูก remount, streaming clone, ปุ่มที่กดได้, thinking box, การซ่อนแชทลึก และการเปลี่ยนโหมดแสดงผลที่ 390/1280 พิกเซล ชุด Regex และไอเทมเพิ่มเติมครอบคลุม 320/390/1280 พิกเซล Unit tests ตรวจไม่ให้สถานะซ้ำ การเปลี่ยนแชทระหว่างรอ และการรักษาข้อความ/ตัวแปร/ประวัติเดิม

ผลตรวจ release 0.61.0 รวมการ์ดที่แนบมา: unit tests **1,178/1,178 ผ่าน**, syntax check ผ่าน, ชุด browser Regex/MVU ผ่านตามขนาดข้างต้น การใช้ไอเทม การเก็บ Loot การเรียนสกิล และปุ่มซ่อมรายการซื้อขายผ่านทั้ง 320/390/1280 พิกเซล รวมกรณีบันทึกล้มเหลวและป้องกันการยืนยันซ้ำ `git diff --check` ผ่าน และไม่มีรายการ merge conflict ใน workspace

คำสั่งตรวจ: `npm test`, `npm run check`, `npm run test:regex`, `npm run test:mvu`, `npm run test:items` Browser tests ต้องมี Playwright และ Chromium; fixture ของ upstream ดาวน์โหลดไว้ใน cache ชั่วคราว API ทดสอบเป็น mock ไม่ใช้คำขอที่คิดเงิน

ทดสอบ Tavern Helper ผ่าน adapter ที่จำลองสัญญา render/streaming ไม่ใช่การติดตั้ง MVU/Tavern Helper เต็มชุดในเครื่องเทสเตอร์ และไม่ได้วัด Proxy API ของผู้ใช้ จึงยังต้องลองกับการ์ดและชุด Regex จริงของเทสเตอร์ก่อนยืนยันกรณีเฉพาะทั้งหมด Regex ที่ตัดข้อมูลทิ้งหรือสร้าง HTML ไม่สมบูรณ์ยังทำให้ข้อมูลหรือ UI ขาดได้ตามกฎนั้นเอง
