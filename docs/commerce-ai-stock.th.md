# RoleForge 0.56.2 — สต็อกจาก AI และจำนวนซื้อที่ขอไว้ในโรล

คำตอบเปิดร้านครั้งแรกจะให้ AI กำหนดสต็อกตามร้านค้า สถานที่ ความหายาก การจัดหา และข้อมูลเดิมของโลก พร้อมข้อมูลและราคาสินค้าในข้อความเดียวกัน ไม่มีการสุ่มสต็อกเป็น 1 ในโค้ดและไม่มี API เพิ่มเพื่อสร้างจำนวนสินค้า

ตัวอย่าง: ร้านมีน้ำยาฟื้นฟู 12 ขวดและยาแก้พิษ 8 ขวด ผู้เล่นขออย่างละ 3 ขวด ตะกร้าจะเลือกทั้งสองรายการไว้ที่ 3/3 คิดราคาขวดละ 30/50 ทองแดง รวม 240 ทองแดง โดยแสดงสต็อก 12/8 แยกต่างหาก จำนวนในร้านแสดงในแถวสินค้าทุกชิ้น แม้ยังไม่เลือกซื้อ เมื่อยืนยันและบันทึกสำเร็จจะเพิ่มยาอย่างละ 3 ขวด ตัดเงิน 240 ครั้งเดียวและหักสต็อกเหลือ 9/5

ข้อมูลที่แยกกันมีสามส่วน:

- `stock` / `stockKnown`: จำนวนที่ร้านมีจริง AI สร้างในคำตอบเดียวกับข้อเสนอและ UI แสดงให้เห็น ไม่ใช้จำนวนซื้อเป็นสต็อก
- `quantity` คู่กับ `price`: จำนวนในชุดที่ราคานั้นครอบคลุม ราคาต่อขวดมีจำนวนในชุดเป็น 1 ได้ เพราะหมายถึงหน่วยราคา ไม่ใช่จำนวนขวดที่ร้านมี
- `selection:{evidence,items:[{itemId,quantity}]}`: ตะกร้าที่ผู้เล่นขอพร้อมหลักฐานจากข้อความผู้เล่น เช่น อย่างละ 3 ขวด ไม่ใช่ให้ AI เพิ่มจำนวนที่ผู้เล่นจะซื้อเอง

ระบบตรวจว่าหลักฐานตรงกับคำขอ มีจำนวนจริง อ้างถึงสินค้าในร้าน และไม่ซ้ำรายการ หาก AI ส่งจำนวนที่ไม่ได้ขอ จะไม่ใช้ค่านั้น ถ้าข้อความผู้เล่นระบุชื่อสินค้าตรงและจำนวนชัดเจน สามารถเติมตะกร้าจากคำขอจริงแทนได้ เช่น “ขอซื้อ A 2 ขวด และ B 4 ขวด” หรือ “ขอ A กับ B อย่างละสามขวด” การเติมตะกร้าไม่ตัดเงิน ไม่ถือว่า NPC รับราคา และไม่ถือว่าอนุญาตชำระแล้ว

เมื่อเป็นเพียงการดูร้านหรือยังไม่ระบุจำนวน จะไม่เลือกซื้อทั้งสต็อกที่ AI สร้างให้โดยอัตโนมัติ รายการเดิมที่ใช้ราคาต่อชิ้นยังสามารถเริ่มเลือกหนึ่งหน่วยตามรูปแบบเดิมได้ ผู้เล่นปรับจำนวนเองได้ก่อนเสนอราคา/ยืนยัน จำนวนร้านจะแสดงแยกชัดเจนและไม่ถูกตั้งเป็น 1 ตามจำนวนซื้อ

หลังซื้อ สต็อกคงเหลือพร้อมชื่อร้านและสินค้าเข้าสู่บริบท AI เพื่อใช้ต่อเมื่อกลับมาร้านเดิม คำสั่งกำชับไม่รีเซ็ตสต็อกทุกคำตอบ เว้นแต่มีการเติมสินค้าหรือการซื้อขายอื่นเกิดขึ้นจริง ตัวตรวจเงิน สต็อกไม่พอ และการชำระซ้ำยังทำงานตามเดิม

ถ้า AI ไม่ส่งข้อมูลระบบแต่ NPC กล่าวชื่อ ราคา และจำนวนสินค้าชัดเจน ตัวอ่านบทพูดจะใช้สต็อกที่เปิดเผยนั้นได้โดยไม่เรียก API เพิ่ม แต่ข้อมูลเก่าที่ไม่เปิดเผยจำนวนจะยังแสดงว่าไม่ระบุ ไม่สร้างสต็อกย้อนหลังเอง กรณีจงใจปิดบังจำนวนหรือข้อเท็จจริงกำกวมยังใช้ `stockKnown:false` และให้ NPC ตัดสินความพร้อมตอนยืนยัน

ตรวจผ่าน 869 unit/host tests และ syntax checks พร้อม browser production extension ที่ 320 / 390 / 1280 px สำหรับตะกร้าอัตโนมัติ ป้ายสต็อกของสินค้าที่ยังไม่เลือก การเสนอโดยไม่จ่าย การเปิดรายการที่บันทึกไว้ การชำระ 240 รับยา 6 ขวด สต็อกคงเหลือ และเคสเก่าไม่ระบุสต็อก ใช้คำตอบ AI ที่ควบคุมไว้ในการทดสอบ ไม่ใช้บัญชี AI ของผู้ใช้หรือ API ที่เสียเงิน
