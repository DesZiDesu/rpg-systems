# Character Forge: คำขอเริ่มเรื่องผ่าน Proxy API — อัปเดต 0.59.0

รวมเผยแพร่ในเวอร์ชัน `0.59.0` หลังผู้ใช้อนุมัติชุดอัปเดตทั้งหมด ฐานของชุดแก้คือ main `8c38e63` (v0.58.15) ข้อจำกัดเรื่อง Proxy จริงยังคงระบุไว้ด้านล่าง

## สิ่งที่ตรวจพบ

ปุ่ม BEGIN เรียกการเจนแชทหลักด้วย `generate('normal', {automatic_trigger:true})` จากแชทว่าง ข้อมูลตัวละครและคำสั่งเริ่มเรื่องเดิมถูกฉีดเป็น SYSTEM ส่วน `automatic_trigger` ของ SillyTavern ข้ามการส่งข้อความจากช่องพิมพ์ ดังนั้น RoleForge เดิมไม่ได้รับประกันว่าคำขอแรกจะมีคำสั่ง USER ที่ไม่ว่าง หรือจบด้วย USER เมื่อ preset เพิ่มคำสั่งระบบหรือ assistant prefill ไว้ท้ายคำขอ รูปแบบนี้มีโอกาสถูก adapter ของ Proxy ที่เข้มงวดปฏิเสธ

นี่เป็นจุดเสี่ยงที่ยืนยันได้จากเส้นทางโค้ด ไม่ใช่การยืนยันว่าสาเหตุ HTTP 400 ของ Proxy ผู้ใช้คือจุดนี้แน่นอน ข้อมูลที่ได้รับคือโมเดลที่เรียกว่า “3.8” ใช้ผ่าน Proxy API และโฮสต์แสดงเพียง “Bad Request”; ยังไม่มีชื่อโมเดลเต็มหรือรายละเอียดข้อผิดพลาดจาก Proxy ชื่อโมเดลหรือพารามิเตอร์ที่ Proxy ไม่รองรับยังแยกออกจากข้อความนี้ไม่ได้

การทดสอบยังพบว่าปุ่มใน iframe ไม่ล็อกทันทีเมื่อกด หากคำขอแรกล้มเหลวรวดเร็ว การกดติดกันอาจส่งคำขออีกครั้งหลัง lock ฝั่งโฮสต์ถูกปลดแล้ว

## การแก้

- ฉีดคำสั่งเริ่มเรื่องเป็น USER ชั่วคราว ผ่าน API extension prompt ของ SillyTavern โดยไม่บันทึกข้อความ User ปลอมลงแชท ข้อมูลตัวละครและขอบเขตการเขียนยังเป็น SYSTEM reference
- ใช้ event `CHAT_COMPLETION_SETTINGS_READY` ก่อนส่งคำขอ เฉพาะการกดเริ่ม Forge ที่กำลังทำงานในแชทเดียวกัน เพื่อนำคำสั่งเริ่มเรื่องไปท้ายข้อความและตัดข้อความว่าง ไม่มีการแก้ array ประวัติร่วมของโฮสต์หรือทิ้งข้อความ preset, media, tool calls และ signatures
- ไม่แก้ชื่อโมเดล, provider, sampling, reasoning, schema หรือค่าการเชื่อมต่อของผู้ใช้ ไม่มีการสลับโมเดลหรือ retry อัตโนมัติ
- ล็อกปุ่ม BEGIN และแสดงสถานะทำงานทันทีใน iframe ปลดล็อกเมื่อได้รับสถานะสำเร็จ/ล้มเหลว ป้องกันการกดซ้ำก่อนสถานะจากโฮสต์กลับมา
- ล้างคำสั่งชั่วคราวหลังสำเร็จ/ล้มเหลว และในงาน quiet/impersonate หรืองานสรุปความจำ ไม่ฉีดคำสั่งจาก session ที่ถูกขัดจังหวะและไม่มีคำขอทำงานจริง
- เก็บ draft และ loadout เมื่อล้มเหลว แสดง HTTP status และชื่อโมเดลเมื่อโฮสต์ให้ข้อมูล พร้อมสาเหตุที่ส่งกลับมา ปิดบังรูปแบบ API key/password/token ที่ตรวจจับได้ก่อนแสดงหรือเก็บ diagnostics; metadata คำขอมีเพียงชื่อโมเดล, source, จำนวนข้อความ/roles และผลปรับคำขอ ไม่มี prompt หรือ profile
- เมื่อโฮสต์ให้เพียง Bad Request แสดงชัดว่ายังไม่มีรายละเอียดสาเหตุ และข้อมูลตัวละครยังอยู่ สถานะ error ขึ้นบรรทัดใหม่และตัดคำยาวภายในกรอบมือถือ

## ผลตรวจ

- `npm test`: 1,118 tests ผ่านทั้งหมด รวมการบันทึก RPG state, Memory, commerce และกรณี Forge ใหม่
- `npm run check`: syntax ผ่านทั้งหมด รวมโมดูลคำขอเริ่มเรื่องใหม่
- `npm run test:forge-opening`: production loader + iframe + event hook ผ่านที่ 320, 390 และ 1280 px ทดสอบ strict Proxy จำลอง, HTTP 400, กดซ้ำ, retry เฉพาะเมื่อกด, draft คงอยู่, ไม่มีข้อความ User/ไอเทม/สกิลซ้ำ, cleanup และไม่แก้คำขอแชทปกติ/quiet
- `npm run test:forge`: ผ่านที่ 320, 390 และ 1280 px รวม fit/keyboard viewport, สีธีม, optional origin skill, Custom Preset, Arsenal, Party และเริ่มเรื่อง
