# RoleForge 0.56.0 — Loot และการใช้ไอเทม

เพิ่มรายการ Loot ให้เลือกก่อนเก็บ และแผงไอเทมเหนือช่องพิมพ์ตามแบบที่อนุมัติ: ดำ–เทา ขนาดกะทัดรัด หัวแผง ปุ่ม และพื้นผิวใช้รูปแบบเดียวกับหน้าต่างฝึกวิชา ปุ่มมีชื่อการกระทำชัดเจน ขยายรายละเอียด ย่อเหลือแถบ และปิดแผงได้ ดู [ภาพ UI ของรุ่นจริง](previews/items-v0560/index.html) และ [แบบทดลองที่อนุมัติ](previews/items-loot-design/index.html)

## วิธีใช้

1. อัปเดตส่วนเสริมเป็น 0.56.0 และรีโหลด SillyTavern เมื่อจบการเจนและเก็บข้อความร่างแล้ว ข้อมูลคลังและสิทธิ์เดิมยังใช้ต่อได้
2. เปิดการติดตามอัตโนมัติใน RoleForge เพื่อรับข้อมูล Loot/ไอเทมจากคำตอบหลักของ AI
3. เมื่อเรื่องยืนยันว่าพบของที่ยังไม่ได้เก็บ แผง **Loot** จะขึ้นเหนือช่องพิมพ์ กดเลือกของที่จะเก็บ แล้วเลือกชนิดและจำนวน เลือกบางส่วนได้ จำนวนที่เหลือยังอยู่ในแหล่งเดิม
4. ใน **คลังสิ่งของ** กด **เลือกไอเทม** แทนการลบ หน้าต่าง RoleForge จะปิดและเปิดแผง **ไอเทม** ในแชต กุญแจที่ผูกสิทธิ์มีปุ่มเลือกบนการ์ดสิทธิ์ด้วย
5. เลือกกิน/ดื่ม/ใช้ ทิ้ง หรือมอบให้ NPC ขยายข้อมูลเพื่อดูผล เงื่อนไข เป้าหมาย Cooldown และจำนวนครั้งที่ใช้ได้ ปุ่มที่ใช้ไม่ได้จะแสดงเหตุผล

## การทำงานแต่ละปุ่ม

| การกระทำ | สิ่งที่เกิดขึ้นเมื่อยืนยันผลสำเร็จ |
| --- | --- |
| เก็บ Loot | เพิ่มของที่เลือกเข้าคลังและลดจำนวนคงเหลือในแหล่งนั้นพร้อมกัน ไม่เก็บเพราะพบเฉย ๆ |
| กิน / ดื่ม | ลดจำนวนที่ใช้จริง ผลต่อ HP/MP/Stamina/ความหิว/กระหายต้องมีข้อมูลยืนยันจาก AI และไม่เกินค่าสูงสุด |
| ใช้ | ของใช้ซ้ำ เช่น ดาบ เครื่องมือ กุญแจ ไม่ลดจำนวน รองรับ Cooldown ตามเวลาในเรื่อง/เทิร์นและจำนวนครั้งที่ใช้ได้ |
| ทิ้ง | ย้ายจำนวนที่เลือกจากคลังไปอยู่ในสถานที่ปัจจุบัน เก็บกลับผ่าน Loot ได้ เป็นการกระทำในเรื่อง |
| มอบให้ NPC | เลือกได้เฉพาะ NPC ที่อยู่ในฉากและเปิดใช้งานอยู่ ถ้า NPC รับ จึงโอนจำนวนและเก็บประวัติผู้รับ ถ้าปฏิเสธ ของยังอยู่กับคุณ |
| ให้ AI เติมข้อมูลไอเทม | ตรวจรายการในคลังทั้งหมดแล้วเติมเฉพาะคำอธิบาย วิธีใช้ ผล เงื่อนไข เป้าหมาย หรือ Cooldown ที่ยังขาด ไม่เปลี่ยนจำนวนหรือสิทธิ์ |
| เตรียมโรลตรวจสอบ | เติมข้อความร่างในช่องพิมพ์ให้ตรวจสอบเอง ยังไม่ส่งและยังไม่เรียก AI |

ของใช้หมดจะลดจำนวนหลังยืนยันผลและบันทึกได้เท่านั้น ของชื่อเดียวกันแต่คุณสมบัติต่างกันจาก Loot จะไม่รวมกอง ข้อมูลวิธีใช้ที่ AI แก้ภายหลังจะไม่เติมจำนวนครั้งที่หมดแล้วหรือล้างเวลาใช้งานครั้งล่าสุด

กุญแจห้อง/สิทธิ์เช่ายังอิงสัญญาซื้อขายเดิม สิทธิ์หมดอายุใช้ไม่ได้ และไม่ทิ้ง/โอนของเช่าผ่านปุ่มทั่วไป สิทธิ์แบบตั๋วจำกัดจำนวนครั้งให้โรลกับผู้ให้บริการเพื่อยืนยันการใช้ตามระบบสิทธิ์เดิม ของที่กันไว้ขายต้องยกเลิกหรือลดรายการขายก่อนใช้จำนวนที่ถูกกันไว้

## ปุ่มให้ AI เติมข้อมูลไอเทม

ในแผงไอเทมเหนือช่องพิมพ์มีปุ่ม **ให้ AI เติมข้อมูลไอเทม** แสดงจำนวนรายการที่ยังขาดข้อมูลและจำนวนชุด API ที่จะเรียกก่อนกด AI ได้รับรายการไอเทมทั้งหมดและรายละเอียดของรายการที่ยังขาด ระบบเติมเฉพาะช่องว่าง ไม่เขียนทับข้อมูลที่มีแล้ว ไม่เติม Charges ที่ใช้ไป ไม่รีเซ็ต Cooldown และไม่แก้จำนวนของ เงิน ข้อความ AI หรือสัญญาเช่า

ทำครั้งละไม่เกิน 6 รายการเพื่อให้คำตอบครบ แสดงความคืบหน้าและแจ้งเตือนก่อนแต่ละ API บันทึกทีละชุด ถ้าหยุดหรือชุดหลังผิดพลาด ชุดที่บันทึกแล้วคงอยู่ ลองใหม่ด้วยปุ่มเองแล้วจะตรวจเฉพาะข้อมูลที่ยังขาด หากข้อมูลครบแล้วปุ่มจะกดไม่ได้และไม่เรียก API สำหรับของธรรมดาที่ระบุชัด AI อธิบายการใช้งานตามโลกโรลได้ แต่ไม่เพิ่มคุณสมบัติพิเศษหรือเวทที่ไม่มีใน canon สิ่งที่ไม่สามารถระบุได้ เช่น น้ำยาไม่มีฉลาก ยังคงแสดงว่าไม่ทราบ

ผลการเติมข้อมูลแสดงในแผงและรายละเอียดไอเทมโดยตรง งานนี้ไม่มีการกระทำของผู้เล่นในเรื่องและไม่ต่อเติมบทโรล ต่างจากปุ่มเก็บ/กิน/ดื่ม/ใช้/ทิ้ง/มอบ

## ตำแหน่งผล AI ตามที่ตกลง

- หากยังไม่มีโรลใหม่ ผลการกดไอเทมจะเป็น narrative/dialogue ต่อท้ายคำตอบ AI เดิม เก็บเนื้อหาเดิมไว้ครบ
- หากส่งโรลใหม่ไปแล้ว คำขอจะรอคำตอบถัดไปให้เจนและอ่านข้อมูลเสร็จก่อน แล้วต่อท้ายคำตอบนั้น ไม่ฉีดคำขอเข้า API ที่เริ่มทำงานไปแล้ว
- ระหว่างซื้อขาย ฝึกฝน หรือสรุปความจำกำลังทำงาน จะรอให้จบก่อน ไม่เรียกงานไอเทมชนกัน
- เมื่อเปลี่ยนฉาก รายการต้นทางถูกแก้/เปลี่ยน Swipe หรือเปลี่ยนแชตระหว่างรอ ระบบหยุดคำขอที่ไม่ตรงแล้ว ให้เลือกใหม่
- กดยกเลิกระหว่างรอผลได้ ช่วงสั้น ๆ ที่กำลังบันทึกผล ปุ่มหยุดจะกดไม่ได้เพื่อให้การบันทึกจบครบ ผลที่ส่งกลับมาหลังยกเลิกจะไม่เปลี่ยนข้อความหรือคลัง การยกเลิกรับผลไม่รับประกันว่าผู้ให้บริการจะคืนค่า API ที่ส่งไปแล้ว

## API และหน้าต่างหลายระบบ

ข้อมูล Loot และการพิมพ์ใช้/เก็บ/ทิ้ง/มอบของเองใช้ข้อมูลจากคำตอบหลัก ไม่มี API แยกเพื่อสร้างรายการ Loot การเปิดคลัง เลือกรายการ จำนวน เป้าหมาย ผู้รับ และรายละเอียดทำในเครื่อง

เมื่อกดให้ดำเนินการเก็บ/ใช้/ทิ้ง/มอบ จะมีแจ้งเตือน **กำลังเรียก API เพิ่ม** แล้วเรียกงาน AI หนึ่งครั้งผ่านการเชื่อมต่อข้อความของ SillyTavern เพื่อพิจารณาผลและเขียนต่อ ไม่ใช้ ElevenLabs ในงานไอเทม และไม่เรียก AI ตรวจซ้ำอัตโนมัติ หากคำตอบไม่ครบหรือบันทึกไม่ได้ มีปุ่มลองคำขอเดิมอีกครั้งให้กดเอง

แผง Loot และไอเทมแยกจากซื้อขาย ฝึกฝน และวิชา/ทักษะ เมื่อเปิดพร้อมกัน ใช้ Tabs ของแผงเหนือช่องพิมพ์เดิมเพื่อไม่ให้ซ้อนทับ ปุ่ม **ย่อ** พับเหลือแถบบางโดยเก็บสถานะ ปุ่ม **ปิด** ซ่อนแผงนั้น การปิดแผงระหว่างรอไม่ได้ยกเลิกคำขอ ให้กดปุ่มยกเลิกคำขอหากต้องการหยุดรับผล

## ข้อมูลและการป้องกันรายการซ้ำ

- เพิ่ม `itemSystem` ใน metadata ของแชต: แหล่ง Loot/จำนวนคงเหลือ ประวัติโอนให้ NPC และใบรับผลแต่ละคำขอ
- เพิ่ม `usage` ในไอเทม: วิธีใช้ ของใช้หมด/ใช้ซ้ำ ผล เงื่อนไข เป้าหมาย Cooldown และจำนวนครั้ง ไอเทมเก่าประเภทอาหาร/กุญแจ/อาวุธ/เครื่องมือใช้ต่อได้ น้ำยาที่ไม่มีข้อมูลจริงจะไม่ถูกเดาว่าดื่มได้
- คำตอบหลักส่ง `loot` และ `itemEvents` ใน `tretaresia_patch` เดียวกับข้อมูลอื่น ตัวอ่านรองรับ patch ที่มีแต่ Loot หรือแต่เหตุการณ์ไอเทมด้วย ไม่อ่านคำสัญญาใน Thinking ว่าเป็นผลจริง
- การพิมพ์โรลเองใช้แกนยืนยันและใบรับผลเดียวกับปุ่ม พร้อมหลักฐานจากคำขอผู้เล่นและผลในเรื่อง ไม่หักซ้ำถ้า AI ส่งทั้งเหตุการณ์และคำสั่งคลังสำหรับของเดียวกัน
- การเก็บจากแหล่ง Loot ที่รู้จักต้องอ้าง pool/entry ID และ revision ที่ส่งให้ AI ส่วนของที่ได้รับโดยตรงจากเหตุการณ์อื่นใช้คำสั่งคลังเดิม ไม่สร้างรายการให้เก็บซ้ำ
- ไม่เปลี่ยนคลังเมื่อ AI ส่งข้อความล้วน ข้อมูลไม่ตรง หลักฐานไม่ครบ ฉากเปลี่ยน หรือบันทึกไม่สำเร็จ ข้อความและ metadata ถูกคืนกลับเมื่อการบันทึกล้มเหลว สำหรับการเติมข้อมูลหลายชุด จะคืนกลับเฉพาะชุดที่ล้มเหลวและเก็บชุดก่อนที่บันทึกสำเร็จแล้ว
- แหล่ง Loot มีขอบเขต 120 แหล่ง ในกรณีเต็มจะเอาแหล่งที่เก็บหมดแล้วออกก่อน ถ้ายังมีของทุกแหล่งจะแจ้งว่าเต็ม ไม่ลบของที่ยังไม่ได้เก็บเพื่อรับรายการใหม่

## การตรวจสอบรุ่นนี้

ทดสอบผ่าน loader และ DOM จริงของส่วนเสริมในโฮสต์ SillyTavern จำลองที่ 320/390/1280px: ข้อมูล Loot จากคำตอบหลักโดยไม่มี API เพิ่ม เก็บบางส่วน กิน/ดื่มและตัวชี้วัด ของใช้ซ้ำ มอบสำเร็จ/ปฏิเสธ ทิ้งแล้วเก็บกลับ ข้อมูลไม่ครบ การเติมรายละเอียดทั้งคลังแบบหลายชุด/รักษาข้อมูลเดิม/ล้มเหลวหลังบันทึกบางชุดและลองใหม่ กุญแจสิทธิ์ การรอคำตอบใหม่ ยกเลิกผล เปลี่ยนฉาก ย่อ/Tabs คำตอบผิดรูปแบบ ลองใหม่ และการบันทึกล้มเหลว ตรวจซื้อขายส่วนลด 190 ทองแดงกับกุญแจห้อง และหน้าต่างฝึกฝนเดิมด้วย

การทดสอบ AI ใช้คำตอบจำลองที่ควบคุมได้ ไม่ได้เรียกบัญชีหรือ API แบบเสียเงินจริง ความครบถ้วนของข้อมูลในเกมยังขึ้นกับโมเดลที่เลือก ระบบตรวจข้อมูลและคงคลังเดิมเมื่อคำตอบยืนยันไม่ได้
