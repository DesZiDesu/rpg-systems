# Loot และการใช้ไอเทม — แบบที่เสนอ

ชุดนี้เป็น Preview กดทดลองได้ด้วยข้อมูลจำลอง ยังไม่ได้เชื่อม AI หรือเปลี่ยนคลังจริง ไม่มีการเรียก AI จาก Preview

## สิ่งที่ผู้ใช้เลือกแล้ว

- Loot ที่เพียงพบจะขึ้นรายการให้เลือกเก็บก่อน ไม่เพิ่มเข้าคลังเพราะพบเฉย ๆ
- หากโรลยืนยันว่าหยิบหรือได้รับของแล้ว บันทึกเข้าคลังโดยไม่ต้องกดเก็บซ้ำ
- ถ้าไม่มีโรลใหม่ ให้ AI ต่อเติมท้ายคำตอบเดิมที่เป็นต้นทาง เก็บข้อความเดิมไว้ครบ
- ถ้าผู้เล่นส่งโรลใหม่แล้ว ให้ผลไอเทมอยู่กับคำตอบถัดไป
- ใช้คลังเดียวกันทั้งปุ่มและการพิมพ์โรล

## หน้าตาและการกด

1. Loot เริ่มเป็นสรุปเตี้ย มีชื่อแหล่งที่พบ จำนวนรายการ และปุ่มเลือกของที่จะเก็บ
2. ขยายแล้วเลือกเป็นรายการ เลือกจำนวนได้ และกดเก็บที่เลือก ข้อมูลไม่ทราบระบุว่าไม่ทราบ
3. กดเลือกไอเทมจากคลัง จะปิดหน้าคลังกลับมาหน้าแชตพร้อมแผงไอเทม
4. แผงไอเทมเริ่มเตี้ย มีชื่อ จำนวน ปุ่มกิน/ดื่ม/ใช้ตามชนิด ปุ่มทิ้ง และมอบให้ NPC
5. กดดูข้อมูลเพื่อขยายการทำงาน เงื่อนไข เป้าหมาย และ Cooldown ไม่เรียกเพิ่มเพื่อเปิดอ่าน
6. ทิ้งเปิดการยืนยันชื่อ จำนวน และสถานที่ โดยเป็นการวางของในเรื่อง ไม่ใช่ปุ่มลบคลัง
7. มอบให้ NPC แสดงเฉพาะผู้รับในฉาก ไม่มีผู้รับจะปิดปุ่มพร้อมเหตุผล
8. แผงหลายระบบเปิดร่วมกันได้ ใช้ Tab เมื่อมีหลายแผง ปุ่มย่อยุบเป็นแถบบาง ปุ่มกากบาทปิดเฉพาะแผงไอเทม

## การเรียก AI และตำแหน่งผล

รายการ Loot และรายละเอียดมาพร้อมคำตอบหลัก ไม่เรียก AI แยกเพียงเพื่อเปิด UI การย่อ ขยาย เลือกจำนวน และเลือกผู้รับไม่เรียก AI เช่นกัน

เมื่อกดทำรายการจริง จะมีแจ้งเตือน RoleForge ก่อนการเรียก API เพิ่มเพื่อประเมินเหตุการณ์ เลือกข้อความต้นทางด้วย chat/message/swipe ID ไม่ใช้เพียงตำแหน่งข้อความบนจอ

- ไม่มีโรลใหม่: งานต่อเติมอ่านคำตอบเดิมและคำขอไอเทม ส่งกลับเฉพาะเหตุการณ์ต่อท้ายและข้อมูลคลังที่ยืนยัน ผลต่อท้ายคำตอบเดิม ไม่เขียนทับข้อความเดิม และไม่ใช้ข้อความ plain text นอก narrative/dialogue
- มีโรลใหม่: ผูกคำขอกับคำตอบถัดไป หาก request หลักถูกส่งไปแล้ว จะไม่อ้างว่าสามารถแทรกข้อมูลย้อนหลังใน request ที่กำลังทำงานได้ ต้องรอคำตอบนั้นจบแล้วจึงต่อเติมผลไอเทมที่ท้ายคำตอบนั้น ด้วยแจ้งเตือน API ก่อนงานเพิ่ม
- ถ้าคำตอบหลักยังอยู่ขั้นเตรียม request และรวมคำขอได้ ให้ AI ตอบเหตุการณ์ไอเทมในคำตอบนั้นโดยไม่เปิดงานซ้ำ
- งานไอเทมถูกพักระหว่างการเจนหลักและการเปลี่ยน chat/swipe เพื่อป้องกันผลไปลงผิดข้อความ ถ้าข้อความต้นทางถูกลบหรือเปลี่ยน ต้องไม่ฝืนบันทึกผลลงปลายทางอื่น

## ข้อมูลคลังและความถูกต้องที่ต้องทำเมื่อพัฒนาจริง

ข้อมูลไอเทมเดิมยังคงอยู่ เพิ่มข้อมูลชนิดการใช้ ผล เงื่อนไข เป้าหมาย ใช้แล้วหมด/ใช้ซ้ำ จำนวนครั้ง และ Cooldown เฉพาะที่มี ไม่เดาว่าของเหลวไม่ทราบชนิดเป็นยาดื่ม ไม่มีการใส่ Mastery ให้ไอเทมโดยอัตโนมัติ

คำขอแต่ละรายการมี ID และสถานะ รอผล / สำเร็จ / ไม่สำเร็จ บันทึกผลและข้อความต่อเติมเป็นเหตุการณ์เดียวกัน ป้องกันการกดซ้ำ การยืนยันซ้ำ และการเพิ่ม Loot ซ้ำใน swipe เดิม จำนวนไม่เกินของที่มีและไม่มีจำนวนติดลบ

- กิน/ดื่ม/ของใช้หมด: ลดตามจำนวนที่ยืนยันว่าใช้จริง
- ดาบ/เครื่องมือ/กุญแจ: ใช้แล้วไม่ลดจำนวน เพียงการใช้ไม่เท่ากับทำของหายหรือทำลาย
- ทิ้ง: ย้ายจำนวนไปอยู่ในรายการของที่สถานที่นั้น หยิบกลับได้เมื่อเรื่องยืนยันว่ายังอยู่
- มอบ: โอนเมื่อผู้รับรับไว้จริง ถ้าปฏิเสธหรือถูกขัดขวางยังอยู่กับผู้เล่น ต้องเก็บประวัติผู้รับเพื่อป้องกันสูญหายระหว่างระบบ
- ของเช่า/สิทธิ์บริการ: เคารพ commerceRightId และเงื่อนไขเดิม ไม่โอนกรรมสิทธิ์หรือหักของที่อยู่กับผู้ให้บริการเพราะกดปุ่มทั่วไป
- ข้อมูลไม่ครบ/ผลตอบกลับอ่านไม่ได้: คงคลังเดิม แสดงเหตุผลและให้ลองใหม่เฉพาะคำขอที่ยังไม่สำเร็จ
- การพิมพ์โรลกับการกดปุ่มยืนยันเหตุการณ์เดียวกันต้องไม่หักซ้ำ
- ไอเทมชื่อเหมือนกันแต่คุณสมบัติ/สิทธิ์ต่างกันไม่รวมกอง

## ขอบเขต Preview

มี 16 หน้าตัวอย่าง ทั้งสรุป Loot รายการเก็บ รายละเอียด การดื่ม กิน ใช้กุญแจ ทิ้ง มอบ ไม่มี NPC ข้อมูลไม่ครบ รอผลจากข้อความเดิม รอคำตอบใหม่ ผลสำเร็จ ผลปฏิเสธ คลัง และย่อแบน ข้อความรอผลและใบรับผลเป็นการจำลองให้ดูตำแหน่ง UI ไม่ใช่ผลจาก AI จริง

ตรวจแผงไม่ล้นบนจอ 320, 390 และ 1280 พิกเซล ทดลองจำนวน Loot การเลือกผู้รับ ปุ่มใช้ของที่ไม่ทราบข้อมูล กุญแจที่ห้ามทิ้ง การเปิด/ย่อ/ปิด และกลับจากคลังสู่แชต
