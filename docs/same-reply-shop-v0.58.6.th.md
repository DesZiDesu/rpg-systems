# สร้างรายการไอเทมพร้อมคำตอบโรล — RoleForge 0.58.6

## พฤติกรรมหลังแก้

เมื่อ NPC เสนอสินค้าหรือราคาในแชตปกติ AI ต้องเขียนบทพูดและข้อมูลสินค้าครบใน **คำตอบเดียวกัน** ข้อมูลอยู่ใน `marketplace` ภายใน comment `tretaresia_patch` ของคำตอบนั้น แผงซื้ออ่าน comment นี้เมื่อคำตอบเสร็จ ไม่ต้องเริ่มคำขอ AI รอบที่สองเพื่อเปิดรายการ

สินค้าทุกชิ้นมีชื่อเดียวกับที่ NPC พูด ราคา สกุลเงิน จำนวนและสถานะ stock รายละเอียด คุณสมบัติ ความหายาก วิธีใช้ เงื่อนไข cooldown charges ผลสเตตัส และวิชา/เทคนิคที่มอบให้ หนังสือที่มอบวิชามี learning และ ability definition ครบตั้งแต่ข้อเสนอ การซื้อเพียงเพิ่มหนังสือใน Inventory หลังยืนยัน การเรียนวิชายังต้องใช้หนังสือตามเงื่อนไข

## จุดที่แก้

คำสั่งเดิมบอกให้ส่งรายการพร้อมบทโรลอยู่แล้ว แต่รูปตัวอย่าง BUY/SHOP และ literal comment ใน prompt ท้ายแชตเป็น schema ย่อที่ไม่มี `usage`, `stats`, `learns` และ learning definition การแก้รอบนี้ทำให้รูปตัวอย่างและคำสั่งของเส้นทางเดียวกันตรงกัน พร้อมตัวอย่างหนังสือที่มี ability metadata จริงตาม schema ที่ระบบอ่านได้

เพิ่มคำสั่งให้ใช้ `itemName` ตรงกับชื่อในบทพูดทุกตัว และกล่าวชื่อเต็มซ้ำเมื่อเสนอราคาหรือต่อรอง ไม่ใช้ชื่อสั้นในบทพูดแล้วขยายเป็นอีกชื่อใน JSON ให้สร้างรายละเอียดที่ยังขาดให้สอดคล้องกับ canon ในคำตอบนี้ รักษาคุณสมบัติที่เคยยืนยันไว้ และย่อคำบรรยายตกแต่งก่อนตัดข้อมูลสินค้าเมื่อพื้นที่คำตอบไม่พอ

คำขอดู/เลือกตำรา หนังสือ คัมภีร์ และคู่มือภาษาไทยได้รับตัวอย่างรายการซื้อที่เหมาะสมด้วย การอ่านหรือศึกษาหนังสือเฉย ๆ ไม่ถูกเปลี่ยนเป็นคำขอซื้อ และ `commerceIntent.kind="none"` ยังปิดการเปิดร้านเมื่อบริบทจริงไม่ใช่การค้า

## ราคาลดแบบเหมาชุดในคำตอบเดียว

เพิ่ม `marketplace.basketQuote:{amount,denomination,evidence}` สำหรับการซื้อสินค้าทั้งรายการอย่างละหนึ่ง โดยคงราคาที่เสนอจริงของแต่ละชิ้น เช่นหนังสือราคา 15/20/10 แต่ NPC ลดทั้งชุดเหลือ 40: แผงแสดงยอด 40 โดยไม่ต้องสร้างราคาต่อเล่มขึ้นใหม่ หรือส่งคำขอ AI เพื่อคำนวณส่วนลด

ยอดเหมาชุดต้องอยู่ในบทพูดราคาปัจจุบันของผู้ขายคนเดียวกัน ตรงกับตัวเลขและสกุลเงินที่พูดจริง และผูกกับตะกร้าครบชุดที่ผู้ใช้เลือก ตัวอ่านสามารถรับยอดรวมที่แจกแจงชัดเจนในบทพูดได้เองหากโมเดลละ field นี้ การเปลี่ยนตะกร้าเป็นบางรายการหรือเปลี่ยนจำนวนยกเลิกยอดเหมาชุดเดิมและคำนวณจากราคาสินค้าแทน เงื่อนไขนี้ครอบคลุมสินค้าทั่วไป ไม่ขยายไปยังห้องพัก สิทธิ์บริการ หรือรายการที่มีมัดจำ

ยอดที่แต่งขึ้น ราคาก่อนลด สกุลเงินผิด หลักฐานจาก planning ผู้ขายคนอื่น ข้อเสนออนาคต/ที่ถูกปฏิเสธ และสินค้าที่ไม่ได้กล่าวในบทพูดยังถูกปฏิเสธ ไม่เปลี่ยนเงินหรือคลัง

## การตรวจสอบ

Unit/host tests **1,051/1,051 ผ่าน** และ syntax checks ผ่าน กรณีใหม่ครอบคลุม:

- ตัวอย่าง output contract ของหนังสือมี usage และ learning definition ที่ผ่านตัวตรวจจริง
- ข้อเสนอเดียวเปิดหนังสือครบสามเล่มพร้อมยอดเหมาชุดและรายละเอียดเดิมที่โมเดลส่งมา
- Host integration อ่านบทพูดและ inline patch จริง เปิดแผงได้ และไม่มีการเรียก `generateRaw`, `generateRawData` หรือ `generateQuietPrompt` เพิ่มเพื่อสร้างรายการ
- โหลดรายการซ้ำยังรักษายอดและรายละเอียด เงิน คลัง และวิชาไม่เปลี่ยนระหว่างเปิดข้อเสนอ
- หลังยืนยันซื้อ หนังสือพร้อม learning metadata เข้าคลังครบ แต่ยังไม่เรียนวิชาโดยอัตโนมัติ
- JSON ข้อเสนอที่ผิดยังคง pending โดยไม่แอบเรียก AI รอบใหม่
- ส่วนลดผิด การเปลี่ยนตะกร้า การปิดระบบ และ routing ของ interaction ที่มีอยู่แล้ว

ไม่มี Chromium และไม่ได้ทดสอบกับ provider/preset ของผู้ใช้จริง Prompt ที่ครบขึ้นไม่ได้รับรองว่าโมเดลทุกตัวจะสร้าง JSON ถูกต้องทุกครั้งหรือว่าคำตอบจะไม่ถูกตัด หากคำตอบผิด/ไม่ครบ ระบบยังไม่ใช้ข้อมูลที่ตรวจไม่ผ่าน ปุ่มกู้ข้อเสนอแบบเดิมยังมีสำหรับข้อความเก่าหรือคำตอบที่ไม่ครบ แต่ไม่ใช่ขั้นตอนสร้างรายการตามปกติ

## หลังอัปเดต

อัปเดตจาก main แล้วโหลดหน้าใหม่ให้เป็น **0.58.6** เปิด Auto Track และ Negotiated Marketplace ตามเดิม แล้วโรลขอดูสินค้า/ขอซื้อกับ NPC ได้เลย ให้โมเดลส่งคำตอบจนจบเพื่ออ่านข้อมูลรายการ สำหรับข้อความเก่าที่ขาดข้อมูลไอเทม ให้ Regenerate ข้อเสนอหลังอัปเดตเพื่อให้ใช้ output contract ใหม่ การอัปเดตไม่เติม learning definition ที่โมเดลไม่เคยส่งในข้อความเก่าให้เอง
