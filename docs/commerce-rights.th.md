# ซื้อถาวร เช่า สิทธิ์ใช้งาน และบริการ — v0.53.0

ใช้รายการซื้อเดิมเหนือช่องพิมพ์ เลือกหลายรายการได้ และระบุประเภทของแต่ละรายการให้ชัด ข้อมูลรายการและเงื่อนไขมาจากคำตอบปกติของ AI พร้อมเนื้อเรื่อง เปิดดูรายละเอียด เลือกรายการ ย่อหน้าต่าง และดู Inventory ไม่เรียก API เพิ่ม ปุ่มเสนอราคา/ยืนยัน/ยกเลิกยังเป็นงาน API ตามระบบซื้อเดิมและมีแจ้งเตือนก่อนเรียก ผู้เล่นโรลเสนอราคาหรือยืนยันในแชตแทนปุ่มได้

## ประเภทที่รองรับ

| ประเภท | ได้รับอะไร | สิ้นสุดอย่างไร |
|---|---|---|
| ซื้อถาวร | สิ่งของเป็นกรรมสิทธิ์ผู้เล่น เข้ากระเป๋าตามเดิม | ไม่มีวันหมดสิทธิ์ ขายหรือใช้ตามระบบปกติ |
| เช่า | สิ่งของที่ยืมใช้และสัญญาที่ระบุเจ้าของ | ครบกำหนดหรือคืนจริง ของไม่หายเพียงเพราะเวลาผ่าน |
| สิทธิ์ใช้งาน | สิทธิ์ตามสถานที่/บริการ อาจมีบัตรหรือกุญแจประกอบ | ตามเวลา จำนวนครั้ง หรือเป็นสิทธิ์ถาวร |
| งานบริการ | รายการงานที่ชำระแล้ว เช่น ซ่อม สั่งทำ ฝากดูแล หรือบทเรียน | ผู้ให้บริการยืนยันว่าเสร็จจริง จึงปิดงานและส่งสิ่งของที่ตกลงไว้ |

ตัวอย่าง: ห้องพักหนึ่งคืนพร้อมกุญแจ เช่าม้าหนึ่งวัน ตั๋วเรือเที่ยวเดียว บัตรเข้าใช้สนามฝึกหลายครั้ง สมาชิกห้องสมุดถาวร สั่งตีดาบ และซ่อมอุปกรณ์ที่มีอยู่ งานที่ไม่มีสิ่งของส่งมอบไม่สร้างไอเทมปลอม การจ่ายค่าบทเรียนไม่เพิ่ม Mastery หรือทำให้เรียนจบเอง ต้องเกิดการเรียน/ฝึกจริงผ่านระบบทักษะและฝึกเดิม

## เวลา สิ่งของ และเงิน

- กำหนดเวลาตาม `worldClock.day/time` ภายในเรื่อง ไม่ใช่นาฬิกาจริง รองรับกำหนดวัน/เวลา ระยะเวลาเป็นนาที จำนวนครั้ง และสิทธิ์ถาวร ถ้าไม่มีเวลาเริ่มที่ยืนยันได้ ระบบไม่สร้างระยะเวลาขึ้นเอง
- เมื่อสิทธิ์พักหมด กุญแจยังอยู่ในกระเป๋า แต่แสดงหมดสิทธิ์ เมื่อผู้เล่นโรลคืนและผู้ให้บริการยืนยันรับจริง กุญแจจึงออกจากกระเป๋า
- ของเช่า บัตร/กุญแจที่ผูกกับสิทธิ์ และของที่ส่งให้ช่างทำงาน ไม่เป็นสินค้าที่นำไปขายเองได้ ของที่ฝากงานยังแสดงอยู่แต่ถูกกันไว้จนงานเสร็จ
- ตั๋ว/บัตรหลายครั้งลดจำนวนหลังผู้เล่นใช้จริงและ NPC ที่ได้รับอนุญาตยืนยันรับตรวจ ไม่ลดจากการเปิดหน้าต่างหรือเพียงกล่าวถึงตั๋ว บัตรที่ใช้ครบแสดงสถานะใช้ครบแล้ว
- มัดจำแสดงเพิ่มจากราคาก่อนยืนยัน เป็นเงินที่จ่ายจริง ไม่ใช่เงินกันไว้แบบประมูล การต่อรองเปลี่ยนราคาสินค้า/บริการ ไม่เปลี่ยนมัดจำที่แจ้งไว้
- คืนมัดจำเต็มหรือบางส่วนเมื่อ NPC ยืนยันจำนวนที่คืนจริง ไม่คืนเองเมื่อเวลาเดิน ไม่คิดค่าปรับ ริบมัดจำ หรือต่ออายุหักเงินเอง สามารถคืนของก่อน แล้วรับมัดจำในคำตอบถัดไปได้
- ธุรกรรมและการคืนมีรหัส/รุ่นข้อมูล ตรวจการทำซ้ำ บันทึกเงินและของร่วมกัน และย้อนกลับเมื่อบันทึกโฮสต์ไม่สำเร็จ คำตอบที่ส่งทั้ง lifecycle event และ ops หัก/เพิ่มซ้ำใช้ผลจาก event เพียงครั้งเดียว

การเปลี่ยนราคา ต่อเวลา หรือซื้อช่วงใหม่ต้องมีข้อเสนอใหม่และความยินยอมซื้อ ไม่แก้สัญญาที่จ่ายไปแล้วด้วย ops ระบบนี้เป็นตัวบันทึกสิทธิ์และงานที่ยืนยันในเรื่อง ไม่สร้างฐานข้อมูลห้องว่างของ NPC ทั้งเมือง ตารางเดินเรือ หรือผลการรักษา/คุณภาพงานเอง สิ่งเหล่านั้นยังเป็นข้อเท็จจริงที่ AI ต้องดำเนินเรื่องตามโลกและตัวละคร

## ข้อมูลที่ AI ส่งในคำตอบเดียว

รายการแต่ละชิ้นของ `marketplace.kind="npcShop"` เพิ่ม `terms` ได้ โดยราคาและสกุลเงินยังอยู่ในรายการเดิม:

```json
{
  "id": "room-203",
  "itemName": "ห้องเดี่ยว",
  "price": 5,
  "terms": {
    "mode": "access",
    "scope": "ห้อง 203 Oakland Inn",
    "validUntil": {"day": 2, "time": "10:00"},
    "delivery": {"name": "กุญแจห้อง 203"},
    "deposit": 3,
    "includes": ["อาหารเช้า", "น้ำอุ่น 1 ถัง"],
    "conditions": "คืนกุญแจตอนเช็กเอาต์"
  }
}
```

ใช้ `mode:"permanent"` สำหรับสินค้าถาวร, `rental` สำหรับของเช่า, `access` สำหรับสิทธิ์ และ `service` สำหรับงานบริการ ใช้ `durationMinutes` แทนกำหนดสิ้นสุด หรือ `uses` สำหรับจำนวนครั้ง หรือ `permanent:true` สำหรับสิทธิ์ถาวร หากผู้รับตรวจตั๋วเป็นคนอื่น ใช้ `redeemers` ระบุชื่อ NPC ที่ยืนยันไว้จริง งานบริการที่รับอุปกรณ์ผู้เล่นไปทำใช้ `targetItemId` ของอุปกรณ์ที่มีอยู่หนึ่งชิ้น งานที่สร้างสิ่งของใหม่ระบุ `delivery` แต่ไม่ส่งของตอนรับเงิน

การคืน ใช้สิทธิ์ ส่งมอบงาน หรือคืนมัดจำ ใช้ `commerceRights` ระดับบนของ patch พร้อมรหัส/รุ่นสิทธิ์จากข้อมูลอ้างอิง และคำยืนยัน NPC ที่ปรากฏจริงในคำตอบ:

```json
{
  "commerceRights": [{
    "id": "canonical saved right id",
    "revision": 0,
    "action": "return",
    "evidence": "ข้ารับคืนกุญแจห้อง 203 แล้ว นี่เงินมัดจำคืน 3 เงิน",
    "userEvidence": "ฉันคืนกุญแจห้อง 203 ให้ Garrick",
    "refundAmount": 3
  }],
  "ops": []
}
```

ใช้ `action:"use"` ลดสิทธิ์หนึ่งครั้ง, `complete` ปิดงานบริการและส่งผลผลิตที่ตกลงไว้ และ `refund` คืนมัดจำภายหลังคืนของแล้ว ไม่เพิ่มเงินหรือของซ้ำผ่าน ops ไม่ยืนยันเหตุการณ์สมมุติ คำปฏิเสธ หรือเหตุการณ์อนาคต

## อัปเดตและตรวจสอบ

อัปเดตส่วนเสริมและ Reload หน้า เปิด Marketplace และ Auto tracking ตามเดิม สำหรับคำตอบเก่าที่ยังไม่ส่งประเภท/เงื่อนไขให้ Swipe หรือ Regenerate ข้อมูลสิ่งของและใบเสร็จเก่ายังคงอยู่ ไม่มีการเดาว่ารายการห้องพักเก่าเป็นสัญญาใหม่หรือสร้างกำหนดหมดอายุย้อนหลัง รายการห้อง/บริการเก่าที่ไม่มีประเภทเปิดอ่านหรือยกเลิกได้ แต่ไม่ยืนยันซื้อจนกว่าจะมีคำตอบครบ

ทดสอบแกนสัญญา เงินต่างหน่วย มัดจำ ของที่ผูกกับสิทธิ์ เวลาในเรื่อง จำนวนครั้งและงานบริการ รวมการป้องกันการโอนซ้ำ ทดสอบ loader จริงที่ 320/390/1280px กับคำตอบผู้ให้บริการที่ควบคุมไว้ และตรวจระบบซื้อขาย/ประมูล/กระดานเดิมด้วย Browser regression การทดสอบนี้ไม่ได้เรียกผู้ให้บริการโมเดลภายนอก
