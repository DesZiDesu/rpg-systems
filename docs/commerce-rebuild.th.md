# RoleForge 0.51.0 — ซื้อขาย/ต่อรองและประมูลใหม่

> เอกสารการรื้อระบบในรุ่น 0.51.0 — รุ่น 0.51.1 เพิ่มการโรลร่วมกับปุ่ม ดู [Flow ปัจจุบัน](commerce-roleplay.th.md)

รื้อเส้นทางใช้งานซื้อขายและประมูลเดิมออกจาก Main Chat แล้วใช้ `commerce-runtime`, `commerce-engine` และ `commerce-composer` ชุดใหม่ร่วมกัน ไม่มีปุ่มที่เรียกตัวจำลองผู้ซื้อเดิมหรือเครื่องเสนอราคาประมูลเดิมอีก ข้อมูลเก่ายังอ่านเพื่อย้ายยอดเงิน ไอเทม ภาระราคาที่เสนอไว้ และใบรับผลที่จ่ายแล้ว โดยไม่จ่ายซ้ำ

## สาเหตุที่หน้าจอเดิมดูเหมือนไม่ทำงาน

- Scene Tracker และเงิน/ไอเทมมีเส้นทางบันทึกของตัวเอง การเห็นสองส่วนนี้ไม่ได้หมายความว่าคำตอบส่งรายการร้านค้า ประมูล หรือกระดานมาด้วย
- ร้านค้าเดิมรอ object ที่มีสินค้า/ราคาใน patch และใช้การส่งข้อความผู้เล่นใหม่ ส่วนประมูลมีตัวจำลองราคากับการนับปิดรายการในเครื่อง จึงไม่ได้ให้ NPC คิดผ่าน API ทุกครั้งตาม flow ที่ต้องการ
- เรื่องสำคัญ นัดหมาย และเช็กลิสต์เก็บอยู่ในหน้าจัดการ จึงไม่มีหลักฐานบน Main Chat ว่ารอบนั้นบันทึกอะไร คำเชิญมี renderer แต่ไม่ได้ถูกนำมาแสดง
- พบเพิ่มเติมระหว่างทดสอบ: ร้านที่กู้รายการจากข้อความได้แต่ไม่มีการเปลี่ยนค่า ต้องสั่ง refresh แถบหลังจบการอ่านเทิร์นด้วย ข้อมูล Household ที่ยังไม่มี ID ใช้ ID สุ่มทุกครั้งที่อ่าน จึงทำให้ตัวตรวจแชตที่เปลี่ยนระหว่างรอเข้าใจผิด แก้ค่าเริ่มต้นให้คงที่ และไม่นับ timestamp ที่เกิดจาก normalization เป็นการเปลี่ยนเกม

## Flow ใหม่

1. คำตอบหลักแสดงสินค้า/ข้อเสนอ/ประมูล และส่งข้อมูลเปิดรายการใน patch เดียวกัน ไม่มี API แอบเรียกเพื่อสร้างแถบ หากร้านแสดงรายการชื่อและราคาอย่างชัดเจนพร้อมผู้ขายคนเดียว สามารถอ่านเป็นรายการได้ในเครื่อง
2. แถบเล็กเหนือช่องพิมพ์แสดงชื่อสินค้า ราคา และปุ่ม กดหัวแถบเพื่อขยายรายละเอียด รายการร้านค้า และเงินคงเหลือของผู้เข้าประมูล การขยาย/ยุบ/เลือกสินค้าไม่เรียก API
3. ทุกการกระทำเกมที่ผ่านการตรวจข้อมูล เช่น เข้าร่วม Bid รอ ออก เสนอราคา ยืนยัน และยกเลิก เรียก `generateQuietPrompt` ของ SillyTavern **หนึ่งครั้ง** ผ่าน API/card/preset ที่ใช้อยู่ ไม่มีคำตอบสำเร็จรูป ไม่มีข้อความคำสั่งผู้เล่นใหม่
4. AI ส่งปฏิกิริยา NPC สั้น ๆ และผลการตัดสินใจ ระบบต่อท้าย **assistant message เดิม** และแก้ active swipe เดิม เช่น กำลังอยู่ #3 ก็ยังเป็น #3 คงเนื้อหาเก่าทั้งหมด
5. ซื้อขาย: การรับข้อเสนอเป็นเพียงราคาตกลง ต้องกดยืนยันจึงจ่ายเงิน/ส่งของ หาก AI เปลี่ยนราคา ถือเป็น counter และต้องรอผู้เล่นยืนยันราคาใหม่ ห้ามถือว่าผู้เล่นยอมจ่ายราคาที่เพิ่มเอง
6. ประมูล: AI เลือก Bid/ผ่าน/ถอนตัวจากนิสัย ความต้องการ ราคาปัจจุบัน และเงินที่เหลือ จะกระโดดราคา ทุ่มทั้งหมด หรือเลิกสู้เร็วก็ได้ ไม่มีเพดานความเต็มใจ ไม่มีบังคับผู้เล่นชนะ และไม่ต้องนับสามรอบ AI ต้องให้เหตุผลสั้นของผู้ประมูลที่ยังมีสิทธิ์ตอบทุกคน ไม่ส่งกระบวนการคิดส่วนตัว
7. เมื่อจบ/ยกเลิกรายการ แถบหาย รายการเก่าที่ผู้เล่นยังไม่เคยเปิดจะไม่เด้งกลับมา ส่วนเงินกับของมีใบรับผลและ ledger ที่ข้อความต้นทาง

งบ NPC เป็นเงินจริงทั้งหมดของงานเดียวกัน ใช้ร่วมกันทุก lot และลดเมื่อซื้อสำเร็จ AI เพิ่มเงินเองไม่ได้ การเสนอราคาฝั่งผู้เล่นใช้ได้เฉพาะเงินที่ไม่ถูกกันไว้ ค่าเข้าหักครั้งเดียว มัดจำกันไว้และปล่อยคืนเมื่อจบ ไม่หักมัดจำเป็นค่าใช้จ่าย

## การบันทึกและข้อผิดพลาด

คำตอบที่ใช้ไม่ได้ การจ่ายเกินงบ ราคาที่ไม่ตรงกับความยินยอม แชตเปลี่ยน/แก้ข้อความ/สลับ swipe/เพิ่มเทิร์น/หยุด generation/ปิดระบบระหว่างรอ จะไม่ใช้ผลลัพธ์นั้น กดซ้ำระหว่างรอไม่เพิ่ม request ไม่ลอง API ซ้ำอัตโนมัติ

ข้อความ เงิน ของ ใบรับผล และ checkpoint อยู่ในการบันทึก chat เดียวกัน หากโฮสต์รายงานการบันทึกล้มเหลว ระบบคืนค่าก่อนหน้า การกู้การบันทึกไม่ได้เรียก AI เพิ่ม ทั้งนี้ SillyTavern บางรุ่นกลืนข้อผิดพลาดการ save ภายใน API ของโฮสต์เอง จึงรับประกันได้เฉพาะความผิดพลาดที่โฮสต์ส่งกลับให้ extension

## หน้าตาทุกระบบ

เปิด [Main Chat gallery](previews/main-chat-systems.html) ผ่าน static HTTP server ของ repository ได้ มีฉาก/NPC ซื้อ ขาย ประมูล กระดานภารกิจ กระดานปาร์ตี้/กิลด์ คำเชิญ บันทึกเรื่อง/นัดหมาย/เช็กลิสต์ เงิน/ไอเทม และแถบ Summary ใช้ UI จริงและระบุชัดว่าข้อมูล/คำตอบในตัวอย่างเป็นข้อมูลจำลอง ไม่มี live API request

บันทึกเรื่อง นัดหมาย และเป้าหมายเควสแสดงเป็นกล่องพับได้ใต้ข้อความที่เป็นต้นทาง เปิดรายละเอียดใน Main Chat ได้ ปิดสวิตช์แล้วซ่อน UI โดยเก็บข้อมูลเดิมไว้ Summary ยังคงใช้คลังความจำและการตั้งค่า API ของระบบนั้นตามเดิม ไม่เริ่มงานสรุปใหม่จาก event ของการกดซื้อขาย

## ตรวจสอบ

- `npm run check` — ตรวจ syntax ของ runtime และโมดูลใหม่
- `npm test` — ผ่าน 529 เคส ทดสอบงบ/การตัดสินใจ/ความยินยอม/ย้ายข้อมูล/จ่ายครั้งเดียว/rollback/การตอบล่าช้า รวมกับชุดเดิม
- `npm run test:chat` — loader จริง, DOM จริง, event generation/receive, persistence และ UI ที่ 320/390/1280 px โดยจำลองคำตอบ provider ทดสอบหนึ่ง request ต่อปุ่มและต่อข้อความเดิม NPC ทุ่มงบแล้วชนะ การขาย การยืนยัน การพัก/เปิดระบบกลับ และกระดาน/บันทึกทั้งหมด
- `CHROMIUM_EXECUTABLE=/usr/bin/chromium node tests/story-systems.browser.mjs` — การบันทึกเรื่อง นัดหมาย เช็กลิสต์ และ once-only rewards
- `CHROMIUM_EXECUTABLE=/usr/bin/chromium node tests/regex-compat.browser.mjs` — native HTML/regex และ editor ยังทำงานที่ 320/390/1280 px
- `npm run preview:chat` — ผ่านการอยู่ร่วมกันของแถบซื้อขายกับ Summary ทั้ง fixed และ native flow พร้อมภาพมือถือ/เดสก์ท็อปของทุกระบบ และไฟล์รวมภาพ HTML/PDF

ยังไม่ได้เรียก provider จริงของผู้ใช้ เพราะ workspace นี้ไม่มี SillyTavern connection/preset ของผู้ใช้ การเรียกจริงใช้ connection ที่ตั้งไว้ใน SillyTavern ไม่ต้องสร้าง API setting อีกชุด

อัปเดต extension เป็น 0.51.0 แล้ว reload หนึ่งครั้ง ไม่ต้องล้างข้อมูล RPG เปิดสวิตช์ระบบที่ต้องการในศูนย์ควบคุม แล้วขอดูสินค้าหรือรายการประมูลจาก NPC อีกครั้ง
