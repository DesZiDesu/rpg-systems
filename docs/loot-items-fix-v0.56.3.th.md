# แก้ Loot และหน้าต่างไอเทม — RoleForge 0.56.3

ตรวจจาก `DesZiDesu/rpg-systems` main เดิม `f67b978475a990a8250a4707a99a95f1b5c47e64` วันที่ 5 ตุลาคม 2026

## สาเหตุและผลของการแก้

1. **Loot ที่พบแต่ยังไม่ได้เก็บถูกปฏิเสธผิด**: `ingestLoot` ใช้ regex ที่ปฏิเสธคำว่า “ยังไม่ได้เก็บ”, “ยังไม่หยิบ”, “ยังไม่ได้รับ” ทั้งที่เป็นสถานะปกติของ Loot จึงไม่มีแผง Loot และแสดงคำเตือนแบบภาพแรก แก้ให้ปฏิเสธการ *ไม่พบ* ของเท่านั้น พร้อมทดสอบไทย/อังกฤษ การเก็บยังต้องยืนยันแยกก่อนเข้าคลัง
2. **รายการเดียวไม่ครบทำให้ของที่ถูกต้องทั้งแหล่งหาย**: เดิมจำนวนรายการที่ผ่านต้องเท่ากับรายการที่ AI ส่งมา หากมี quantity ไม่ทราบหรือชื่อไม่ตรงหนึ่งรายการ แหล่งทั้งหมดถูกทิ้ง ตอนนี้เก็บเฉพาะรายการที่มีจำนวนเต็มบวกและชื่ออยู่ในคำยืนยันที่ปรากฏจริง รายการที่ไม่ผ่านถูกข้ามพร้อมแจ้งสาเหตุ ไม่เดาจำนวน ไม่สร้างคุณสมบัติ และไม่ดึงชื่อจากส่วนอื่นของเรื่องที่ไม่ได้ยืนยันการพบ ชื่อแหล่งที่ขาดใช้ชื่อไอเทมแรกได้ แต่หลักฐานการพบยังจำเป็น
3. **แผงมือถือรับ `white-space: nowrap` จากช่องพิมพ์**: SillyTavern release กำหนดค่านี้ที่ `#form_sheld` เมื่อ dock แทรกก่อน `#send_form` แผงไอเทมจึงรับค่าที่ทำให้บางข้อความไม่ตัดบรรทัด ทำซ้ำได้ที่ 320px: พื้นที่แผงด้านใน 302px แต่เนื้อหากว้าง 571px สอดคล้องกับภาพสองที่เลื่อนไปทางขวาแล้วส่วนชื่อ/ปุ่มหาย แก้ขอบเขตความกว้างและการตัดบรรทัดเฉพาะแผงไอเทม รวมถึงคอลัมน์ปุ่มที่ย่อได้ ตรวจ `scrollWidth` ของแผงด้านในโดยตรง ไม่ใช้กรอบนอกที่ซ่อน overflow ซึ่งเคยทำให้ test เดิมไม่เห็นปัญหา
4. **ข้อมูลไม่ทราบแสดงเหมือนใช้ซ้ำได้**: ค่าเริ่มต้น `consumable:false` ถูกนำไปแสดง “ใช้ซ้ำ · ไม่ลดจำนวน” ทั้งที่ action ยัง unknown ตอนนี้แสดงว่ายังไม่ทราบการใช้และการลดจำนวน ปุ่มใช้ยังปิดไว้จนมีข้อมูลยืนยัน ปุ่มเตรียมโรลตรวจสอบและเติมรายละเอียดทำงานตามเดิม การไม่มีวิธีใช้ไม่ใช่ข้อผิดพลาดของคลัง และจะไม่เปลี่ยนยาที่ไม่รู้จักเป็นยาดื่มเอง
5. **Loot ไม่ผ่านยังกัน inventory op ออก**: เดิมเอาชื่อจาก payload ที่ยังไม่ตรวจไปกันรายการเข้าคลัง ทำให้รายการรับของที่ถูกต้องหายได้ ตอนนี้กันเฉพาะชื่อใน Loot ที่ตรวจผ่านแล้ว มี host test ทั้งกรณีถูกต้อง/ไม่ถูกต้อง และเรียกซ้ำเพื่อกันของเข้าซ้ำ

คำเตือน Loot เดิมไม่ได้ระบุว่าขาดอะไร รุ่นนี้แจ้งสาเหตุของรายการที่ข้าม เช่น คำยืนยันไม่ตรง ชื่อ/จำนวนไม่ถูกต้อง หรือเต็มขีดจำกัด ไม่แก้ข้อมูลเสียด้วยการเดา จากภาพอย่างเดียวไม่สามารถทราบ payload ของคำตอบจริงได้ทุกช่อง แต่สาเหตุข้างต้นทำซ้ำจากโค้ดและ host fixture ได้

## การป้องกันผลกระทบ

- ใช้ schema เดิม ไม่ต้องย้ายข้อมูลหรือรีเซ็ตคลัง/แชต
- เก็บหลักฐานการพบ จำนวนจริง revision และ receipt ที่กันการใช้/เก็บซ้ำ
- เก็บข้อจำกัดของขาย ของเช่า NPC ในฉาก cooldown และ charges
- เพิ่ม release เป็น 0.56.3 และปรับ cache query ของ runtime imports/CSS ให้ตรงกัน เพื่อให้มือถือโหลดโค้ดและรูปแบบใหม่หลังอัปเดต
- เปลี่ยน CSS เฉพาะแผงไอเทม ไม่เปลี่ยนรูปแบบของระบบซื้อขายหรือช่องพิมพ์ทั้งหมด

## การใช้งานหลังอัปเดต

อัปเดต RoleForge จาก main แล้วใช้ Apply update หรือโหลดหน้าใหม่หลังคำตอบเสร็จและบันทึกข้อความร่าง โดยไม่ต้องล้างข้อมูล Safari ไอเทมเดิมที่ยังไม่ทราบวิธีใช้ยังต้องโรลตรวจสอบหรือเติมรายละเอียด คำตอบเก่าที่เคยถูกปฏิเสธไม่ได้ถูกย้อนนำเข้าคลังอัตโนมัติ; ให้ regenerate คำตอบนั้นหากต้องการสร้าง Loot จากหลักฐานเดิมอีกครั้ง
