# ระบบประมูล — RoleForge v0.45.2

ระบบประมูลแสดงเป็นการ์ดใน Main Chat เมื่อเนื้อเรื่องยืนยันว่าผู้เล่นเดินถึงสถานที่ประมูลแล้ว หน้าตาใช้พื้นดำ กรอบทอง ปุ่มทรงเหลี่ยม และฟอนต์ Orbitron / Chakra Petch ของส่วนเสริม รองรับ UI ไทยและอังกฤษ

## 1. พบสถานที่ประมูลและดูสินค้า

1. เปิด **Auto tracking** ของ RoleForge แล้วเล่นตามเนื้อเรื่อง เช่น “ฉันเดินเข้าหอประมูลและไปดูสินค้า”
2. AI เขียนฉากที่ยืนยันการมาถึง พร้อมข้อมูลประมูลใน Patch ที่ซ่อนท้ายคำตอบเดียวกัน
3. ส่วนเสริมตรวจว่าหลักฐานเป็นข้อความที่อยู่ในคำตอบจริง และสถานที่ตรงกับฉากปัจจุบัน แค่พูดถึงงานประมูล วางแผนไปพรุ่งนี้ หรือถามแบบ OOC จะไม่สร้างการ์ด
4. การ์ดแสดงชื่อสถานที่ รายการแรก ราคาเปิด จำนวนสินค้า และสกุลเงินที่ใช้
5. กด **รายละเอียดไอเทม** เพื่ออ่านข้อมูลที่เปิดเผย หรือเปิด **ประวัติราคาและรายการทั้งหมด** เพื่ออ่านสินค้าอื่นก่อนตัดสินใจ
6. การอ่านหรือย่อการ์ดยังไม่รับสินค้าและยังไม่เสียเงิน

งานหนึ่งมีสินค้า 1–8 รายการ เปิดประมูลทีละรายการ ข้อมูลคุณสมบัติแสดงเฉพาะที่เปิดเผยในเรื่อง ไม่มีการเดาพลังลับของไอเทม

## 2. เข้าร่วมและกันวงเงิน

1. อ่าน **ค่าเข้าร่วม** และ **มัดจำ** ที่การ์ดแสดงก่อนกดปุ่ม
2. กด **เข้าร่วมการประมูล**
3. ส่วนเสริมตรวจเงินที่ใช้ได้ หากไม่พอจะเข้าร่วมไม่ได้
4. ค่าเข้าร่วมถูกหักครั้งเดียวและลง Transaction History ค่านี้ไม่คืนเมื่อออกจากงาน
5. มัดจำเป็นวงเงินที่กันไว้ ยอดเงินรวมใน Wallet ยังเท่าเดิม แต่เงินส่วนนี้ใช้ซื้อของหรือประมูลอย่างอื่นไม่ได้
6. หลังบันทึกสำเร็จมี notification ยืนยัน และเปิดปุ่มเสนอราคาของรายการแรก

ค่าเข้าร่วมและมัดจำเป็น 0 หากไม่มีข้อมูลว่าต้องจ่ายในเรื่อง เข้าร่วมได้ครั้งละหนึ่งงาน เพื่อไม่ให้เกิดวงเงินผูกพันหลายงานซ้อนกัน

ตัวอย่าง: มี 60 ทอง ค่าเข้า 2 ทอง มัดจำ 5 ทอง → ยอดเงินรวมเหลือ 58 ทอง ใช้ได้ 53 ทอง กันไว้ 5 ทอง

## 3. เสนอราคาและแข่งกับ NPC

1. ใช้ปุ่ม **เสนอราคา …** เพื่อเสนอราคาขั้นต่ำที่ถูกต้อง หรือกรอกจำนวนแล้วกด **ยืนยันราคา**
2. ราคาต้องเป็นจำนวนเต็ม ไม่ต่ำกว่าราคาเปิด/ราคาปัจจุบันบวกขั้นต่ำ และไม่เกินเงินที่ใช้ได้
3. หากคุณนำอยู่ เงินเท่าราคาที่เสนอจะถูกกันเพิ่ม ยังไม่หักออกจากยอดเงินรวม
4. ระบบตรวจผู้ร่วมประมูลที่มีวงเงินถึงราคาถัดไป หากมีจะให้หนึ่งคนเสนอราคาทับในรอบนั้น พร้อมแจ้งเตือน
5. เมื่อถูกทับ วงเงินเสนอราคาของคุณถูกปล่อยทันที มัดจำงานยังกันไว้
6. คุณเลือกเสนอใหม่ในราคาขั้นต่ำหรือราคาที่สูงกว่าได้เอง

AI สร้างสินค้าและผู้ร่วมประมูลจากฉากครั้งแรก ส่วนเสริมคำนวณราคาและใช้เพดานของ NPC ที่ถูกกำหนดไว้ตอนเริ่มงาน เพดานนี้ไม่แสดงให้ผู้เล่นและไม่ส่งเป็นความรู้ของตัวละคร ปุ่มประมูลไม่เรียก API เพิ่ม

ตัวอย่าง: มี 58 ทอง มัดจำ 5 ทอง เสนอ 20 ทองแล้วนำอยู่ → ใช้ได้ 33 ทอง กันไว้ 25 ทอง หาก NPC ทับ → ใช้ได้กลับเป็น 53 ทอง กันไว้เฉพาะมัดจำ 5 ทอง

## 4. รอและนับ 1–3

1. กด **รอ / ให้ผู้ดำเนินงานนับราคา**
2. ถ้า NPC คนอื่นยังเสนอราคาต่อได้ ระบบจะเพิ่มราคาหนึ่งครั้ง แล้วเริ่มนับใหม่จาก 0
3. ถ้าไม่มีคนเสนอเพิ่ม ผู้ดำเนินงานนับ 1
4. กดรออีกครั้งเพื่อนับ 2 และอีกครั้งเพื่อนับ 3
5. เมื่อนับถึง 3 รายการจบ: ผู้เสนอราคาสูงสุดชนะ หรือเป็น “ไม่มีผู้ซื้อ” หากยังไม่มีราคาเลย

ไม่มีนาฬิกานับถอยหลังจริง ไม่มีการเดินรอบเองเมื่อปิดหน้าต่าง ย่อการ์ด หรือโหลดหน้าใหม่ ระหว่างคุณนำอยู่จะเสนอราคาทับตัวเองและออกจากงานไม่ได้ เพราะราคานั้นเป็นข้อผูกพันแล้ว

## 5. ชนะ จ่ายเงิน และรับของ

1. ระบบตรวจว่ารายการนี้ยังไม่เคยบันทึกผล
2. ถ้าคุณชนะ จะหักราคาสุดท้ายครั้งเดียว ลง Transaction History และเพิ่มจำนวนสินค้าเข้า Inventory
3. หากมีไอเทมชื่อเดียวกันอยู่แล้ว จะเพิ่มจำนวนในรายการเดิมโดยเก็บ ID เดิม
4. บันทึกผลพร้อม receipt ของงานและรายการนั้น เพื่อกันจ่ายหรือรับของซ้ำ
5. เมื่อบันทึกสำเร็จจึงแจ้ง **ชนะการประมูล**, **ชำระราคาประมูลแล้ว** และ **ได้รับไอเทมจากการประมูล**
6. หาก NPC ชนะ จะบันทึกชื่อผู้ชนะและราคา โดยไม่หักเงินหรือให้ของแก่ผู้เล่น

ตัวอย่าง: มี 58 ทอง ชนะที่ 20 ทอง → เหลือ 38 ทอง และได้รับสินค้า ถ้างานยังมีรายการถัดไป มัดจำ 5 ทองยังกันไว้ จึงใช้ได้ 33 ทอง

หาก Inventory เต็มหรือจำนวนไอเทมเกินขีดจำกัด ระบบยังไม่หักเงินและไม่ปิดรายการ ให้จัดพื้นที่แล้วกดรออีกครั้ง

## 6. รายการถัดไป จบงาน หรือออกจากงาน

1. หลังรายการจบ กด **รายการถัดไป** เพื่อเปิดสินค้าใหม่ ไม่มีการข้ามหรือเสนอราคาแทนคุณโดยอัตโนมัติ
2. ค่าเข้าร่วมไม่ถูกคิดใหม่ มัดจำเดิมใช้ต่อจนงานจบ
3. เมื่อรายการสุดท้ายจบ ระบบปิดงานและคืนวงเงินมัดจำให้ใช้ได้ตามปกติ
4. หากไม่เป็นผู้เสนอราคาสูงสุดในรายการที่ยังเปิดอยู่ คุณกด **ออกจากการประมูล** ได้ มัดจำถูกปล่อย แต่ค่าเข้าร่วมไม่คืน
5. งานที่จบหรือออกแล้วเปิดอ่านผลย้อนหลังได้ การกลับไปดูงานเดิมไม่เริ่มคิดค่าเข้าหรือรับของใหม่

การ “คืนมัดจำ” คือปล่อยเงินที่กันไว้ ไม่ใช่เพิ่มเงินใหม่ เพราะระบบไม่ได้หักมัดจำออกจากยอด Wallet ตั้งแต่แรก

## 7. ย้ายสถานที่ โหลดใหม่ และย้ายแชต

1. ถ้าเดินออกจากสถานที่ ปุ่มเข้าร่วม/เสนอราคาใหม่/เปิดรายการถัดไปจะถูกปิดจนกลับมาที่สถานที่นั้น
2. รายการที่ผูกพันไว้ยังจบได้ด้วยปุ่มรอ เพื่อไม่ให้เงินติดค้าง คุณยังออกจากงานได้หากไม่ได้เป็นผู้นำ
3. โหลด SillyTavern ใหม่แล้ว ราคา ผู้เสนอสูงสุด รอบนับ มัดจำ และผลที่บันทึกไว้ยังอยู่
4. หากหาการ์ดต้นทางไม่พบ ให้เปิด RoleForge → **Ranks & Progression → Auctions** เพื่อดูหรือทำรายการต่อ
5. การย้ายแชตผ่าน Continuity ของ RoleForge หรือส่งออก/นำเข้า RPG state จะพาสถานะประมูลไปด้วย แชตใหม่ที่ไม่ได้เชื่อมความต่อเนื่องเป็นอีกชุดข้อมูล
6. การ swipe/ย้อนคำตอบใช้ checkpoint ของแชตเช่นเดียวกับระบบ RPG อื่น ผลจากปุ่มถูกบันทึกลงคำตอบล่าสุดด้วย หากย้อนเนื้อเรื่องจะได้สถานะของเวอร์ชันนั้น ไม่ได้บวกของจากทั้งสองเวอร์ชันรวมกัน

## 8. การบันทึกและการป้องกันเงินซ้ำ

1. ระหว่างดำเนินการ การ์ดแสดง **กำลังบันทึกการประมูล…** และปิดปุ่มกันกดซ้ำ
2. เมื่อเซิร์ฟเวอร์บันทึกสำเร็จจึงแสดงผลและแจ้งเตือน
3. หากบันทึกไม่สำเร็จ จะคืนราคา รอบนับ วงเงิน เงิน ไอเทม receipt และ checkpoint เป็นก่อนกด พร้อมข้อความให้ลองอีกครั้ง
4. งานบันทึก metadata อื่นรอให้รายการประมูลเสร็จก่อน เพื่อไม่บันทึกสถานะที่ยังไม่ยืนยันค้างลงเซิร์ฟเวอร์
5. ปุ่มจากการ์ดเก่า แชตอื่น หรือราคาที่เปลี่ยนไปแล้วทำรายการไม่ได้
6. AI ใช้ผลประมูลที่บันทึกแล้วเพื่อเล่าเรื่องต่อ ระบบปฏิเสธ Patch เงิน/ไอเทมที่ระบุว่าเป็นผลประมูล จึงไม่จ่ายซ้ำเพียงเพราะ AI บรรยายผลอีกครั้ง
7. เงินที่กันไว้ใช้จ่ายอย่างอื่นหรือก่อตั้งกิลด์ไม่ได้ การซื้อที่ถูกปฏิเสธเพราะใช้วงเงินกันไว้จะไม่ให้ไอเทมซื้อฟรี เงินส่วนที่เหลือยังใช้งานปกติ

การแจ้งเตือนผลสำเร็จใช้สวิตช์ notifications เดิมของ RoleForge ส่วนการชำระเงินและรับไอเทมใช้หมวด Currency และ Inventory ข้อความกำลังบันทึก/ผิดพลาดในตัวการ์ดยังแสดงแม้ปิด notification

## 9. ขอบเขตและการตรวจสอบ

- หนึ่งงานใช้หนึ่งหน่วย เช่น ทอง หรือเงิน ตามเนื้อเรื่อง ไม่มีอัตราแลกเปลี่ยนอัตโนมัติ และเปลี่ยนชื่อสกุลเงินระหว่างงานไม่ได้
- ทดสอบด้วย production loader, chat events และ UI จริงบน Chromium ที่ความกว้าง 320 / 390 / 1280 พิกเซล รวมถึงโหลดใหม่ กดซ้ำ การบันทึกล้มเหลวตอนจ่ายเงิน และการแยกแชต
- การทดสอบไม่เรียกโมเดลจริง AI ที่ใช้ใน SillyTavern ต้องส่งข้อมูล Auction Patch ตามคำสั่ง หากเดินถึงแล้วไม่มีการ์ด ให้ตรวจว่าเปิด Auto tracking อยู่และ AI ส่ง Patch สมบูรณ์
- ระบบ NPC ประมูลใช้ข้อมูลผู้ร่วมงานที่สร้างไว้ ไม่ได้ยืนยันหรือหักกระเป๋าเงินลับของ NPC จาก dossier โดยไม่มีข้อมูลในเรื่อง

ดูโครงสร้างและข้อกำหนด Patch ได้ใน [auction-core.js](../src/auction-core.js)
