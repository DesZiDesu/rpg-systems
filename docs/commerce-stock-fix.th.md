# RoleForge 0.56.1 — ซื้อหลายขวดเมื่อร้านยังไม่ระบุสต็อก

กรณีที่รายงาน: เลือกน้ำยาฟื้นฟู 3 ขวด ราคา 90 ทองแดง และยาแก้พิษ 3 ขวด ราคา 150 ทองแดง รวม 240 ทองแดง แต่หน้าต่างขึ้น “สินค้าไม่พร้อมหรือจำนวนไม่พอ” ก่อนเรียก API ยืนยัน

## สาเหตุและการแก้

ข้อมูลร้านที่ยังไม่ทราบสต็อกมี `stockKnown:false` แต่เก็บค่าเริ่มต้น `stock:1` ไว้ด้วย ระบบเดิมเอาค่านั้นไปตรวจจำนวนและใช้เป็นเพดานของช่องจำนวนโดยไม่ดู `stockKnown` จึงปฏิเสธตะกร้า 3 ขวด แม้ NPC จะตอบรับแล้ว ทดสอบกับ engine 0.56.0 ได้ `error:"inventory"` ตรงกับอาการ

ตอนนี้ตัวตรวจและช่องจำนวนใช้เกณฑ์เดียวกัน: ตรวจเพดานเฉพาะเมื่อมีสต็อกที่ระบุจริง ไม่ใช้จำนวนเริ่มต้นหรือจำนวนที่ผู้เล่นเลือกแทนสต็อก เมื่อไม่ทราบจำนวนในร้าน จะแสดงข้อความให้ NPC ตรวจความพร้อมตอนยืนยัน และส่ง `stock:null,stockKnown:false` ให้ AI แทนค่าเริ่มต้น 1 คำสั่งสร้างข้อมูลร้านย้ำให้แยกสต็อกจริงออกจากจำนวนที่เสนอขายหรือขอซื้อ

ถ้าข้อมูลร้านไม่ส่งสต็อก ส่งค่าที่ใช้ไม่ได้ หรือส่งเพียง `stockKnown:true` โดยไม่มีจำนวน จะถือว่ายังไม่ทราบจำนวน สต็อกที่ระบุเป็นศูนย์จะคงเป็นศูนย์และบล็อกการซื้อ ส่วนสต็อกที่ทราบจริงจะถูกหักเฉพาะเมื่อจ่ายสำเร็จ จำนวนที่ไม่ทราบจะไม่ถูกหักจนกลายเป็นค่าติดลบ

## การทำงานหลังอัปเดต

1. เลือกยา 2 ชนิด อย่างละ 3 ขวด หน้าต่างแสดง 90 + 150 = 240 ทองแดง ทั้งหมด 6 ขวด ถ้าราคาในข้อมูลเป็นยอดรวมสำหรับ 3 ขวดอยู่แล้ว จะไม่คูณยอดนั้นซ้ำ
2. เสนอ 240 ทองแดงและ NPC ยอมรับ: บันทึกราคาที่ตกลง แต่เงินและไอเทมยังไม่เปลี่ยน
3. กดยืนยัน: เรียก API ตามขั้นตอนเดิมหนึ่งครั้ง เมื่อผลตอบรับผ่านการตรวจ จะตัดเงิน 240 ทองแดง เพิ่มยาชนิดละ 3 ขวด และออกใบเสร็จหนึ่งรายการ
4. เปิดรายการที่บันทึกไว้กลับมา: รักษาจำนวนและราคาที่ตกลง รวมถึงราคาที่ต่อรองไว้ ไม่ต้องสร้างร้านใหม่สำหรับรายการที่ระบุว่าสต็อกยังไม่ทราบ

ใช้ตัวตรวจเดียวกันทั้งปุ่มและผลซื้อขายในโรล คำตอบใน planning หรือบทบรรยายว่า NPC รับเงินแล้วไม่ใช่ใบเสร็จหรือหลักฐานว่าระบบตัดเงินสำเร็จ การชำระยังต้องผ่านเจตนาผู้เล่น ผลตัดสิน และการบันทึกตามเดิม ไม่มีการเรียก API เพิ่มเพื่อกู้สต็อกหรือเพิ่มของแถมจากบทพูดเอง

ยังตรวจเงินไม่พอ สต็อกที่ทราบจริงไม่พอ การปฏิเสธของ NPC การยืนยันซ้ำ เงื่อนไขสิทธิ์เช่า/กุญแจ และการกันไอเทมเพื่อขายตามเดิม หากข้อมูลเก่าระบุสต็อกเป็นจำนวนที่ทราบจริง ระบบจะยังเคารพค่านั้น ไม่เปลี่ยนให้เป็นจำนวนไม่จำกัด

## ตรวจสอบ

- 862 unit/host tests และ syntax checks ผ่าน รวม regression ใหม่ 8 เคสสำหรับสต็อก จำนวน ราคารวม รายการที่บันทึกไว้ และการยืนยันผ่านโรล
- Browser โหลด production extension ที่ 320 / 390 / 1280 px: เลือก 3+3 เสนอโดยไม่จ่าย เปิดรายการเดิมหลัง reload แล้วชำระ 240 ทองแดง เพิ่มไอเทมครบ หักครั้งเดียว และไม่มีหน้าต่างล้น
- ทดสอบสต็อกจริงมีเพียง 2 ขวด: เลือกเกินจำนวนแล้วปฏิเสธก่อนเรียก API เงินและของไม่เปลี่ยน
- เคสห้องพักต่อรองสำเร็จที่ 190 ทองแดงยังผ่านบนทั้งสามขนาดจอ พร้อมสิทธิ์ กุญแจ และ UI คลังเดิม

การทดสอบใช้คำตอบ AI ที่ควบคุมไว้ ไม่เรียกบัญชี AI ของผู้ใช้หรือ API ที่มีค่าใช้จ่าย [ภาพหน้าต่างจริง](previews/commerce-stock-v0561/index.html)
