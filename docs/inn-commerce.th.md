# ราคาห้องพักและสกิลที่มีอยู่แล้ว · v0.52.3

## สาเหตุ

รายงาน v0.52.2 แสดงว่าระบบเข้าเส้นทาง `recover-opening` หลังคำตอบหลักยังไม่มีรายการซื้อที่ใช้ได้ แล้วปฏิเสธข้อมูลที่ได้กลับมาเป็น `opening-data`

JSON ในรายงานมีรูปแบบถูกต้อง รวมถึงการห่อด้วย Markdown code fence ภาษา JSON ซึ่ง parser รองรับอยู่แล้ว จุดที่ทำให้ไม่ผ่านคือ evidence เริ่มด้วย **“ถ้าเป็นห้องพักธรรมดา…”** ตัวตรวจเหตุการณ์เดิมปฏิเสธประโยคที่มี “ถ้า/หาก/if” เพื่อกันเหตุการณ์สมมุติ จึงปฏิเสธตัวเลือกราคาในปัจจุบันไปด้วย เมื่อนำ quote เดียวกันมาทดสอบกับ v0.52.2 ได้ `null`; หลังแก้ได้รับรายการ 5 และ 10 silver

## สิ่งที่แก้

ยอมรับเงื่อนไขเลือกรายการในเมนูราคาปัจจุบัน เช่น “ถ้าเป็นห้องพักธรรมดา คืนละห้าเหรียญเงิน” หรือ “If you want the single room, 5 silver” เฉพาะกรณีที่ตรวจชื่อ NPC ผู้พูด ข้อความอ้างอิง ชื่อแต่ละรายการ และราคากับหน่วยเงินที่อยู่ในส่วนของตัวเลือกนั้นได้ การสลับราคา 5/10 ระหว่างห้องก็ไม่ผ่าน

ข้อความประเภทห้องเต็ม ไม่มีห้องว่าง ข่าวลือ พรุ่งนี้ สมมุติว่าอาจมีห้อง หรือคำถามสมมุติ/OOC ไม่ได้สิทธิ์เปิดรายการจากข้อยกเว้นนี้ ไม่ได้เปลี่ยนตัวตรวจเหตุการณ์ทั่วไปของประมูลหรือกระดานอื่น

เพิ่ม instruction เฉพาะ **ห้องพัก การเช่า และบริการที่มีราคา** ในคำตอบหลัก ให้ส่ง `marketplace.kind:"npcShop"` พร้อมตัวเลือกทั้งหมด ราคาเป็นตัวเลข และรายละเอียดที่ NPC ระบุ ใน `tretaresia_patch` เดียวกับเนื้อเรื่อง การถามว่าผู้เล่นจะเลือกห้องไหนไม่ใช่เหตุผลให้ละรายการ เพิ่มคำเตือนบังคับรายการซื้อใน output contract ที่ส่งตอน normal reply, Swipe และ Regenerate ด้วย

ถ้าคำตอบส่งรายการมาใน patch ที่ถูกต้อง ระบบเปิดรายการนั้นทันทีโดยไม่เรียก API เพิ่ม เส้นทางกู้ข้อมูลเดิมยังอยู่สำหรับกรณีที่ provider ละ payload; JSON แบบที่ส่งมาในรายงานรับได้แล้ว รายการที่เปิดเพียงอย่างเดียวไม่จ่ายเงิน จองสำเร็จ หรือเพิ่มของโดยอัตโนมัติ จำนวนคงเหลือและการต่อรองที่ไม่ทราบยังเป็น unknown

## เพิ่มสกิลจากโรลได้ไหม

ได้ เมื่อเปิด **Auto tracking** และ AI ยืนยันในคำตอบว่าเป็นความสามารถที่ตัวละครมีจริงตามเรื่อง เช่น:

> ฉันมีสกิลดวงตามารอยู่แล้ว จึงใช้มองร่องรอยพลังเวทบนประตู

AI สามารถส่ง `upsert skills` พร้อมข้อมูล ability ในคำตอบเดียวกันได้ ไม่ต้องกดเพิ่มเองหรือเรียก API เพิ่ม วิชาใช้ `proficiencies.techniques` กำชับเพิ่มว่าทำได้ทั้งความสามารถที่เพิ่งเรียนและความสามารถเดิมที่เพิ่งเปิดเผย แม้ตั้งค่า loadout เริ่มต้นเสร็จแล้ว ให้เก็บ ID และ Mastery เดิม ไม่มีการให้ 100% เพียงเพราะเอ่ยชื่อสกิล

คำว่า “อยากมี/จะเรียนสกิลนี้” เป็นความตั้งใจ ไม่ใช่ได้เรียนแล้ว ความสามารถที่ขัดกับข้อเท็จจริงในโลกยังต้องให้ AI พิจารณา การปิดหน้าต่าง Incantation ซ่อนเฉพาะหน้าต่าง ไม่ปิดการเก็บสกิลหรือกฎบทร่าย

## ใช้งานหลังอัปเดต

อัปเดตส่วนเสริมแล้วรีโหลดหนึ่งครั้ง สำหรับคำตอบเดิมที่ไม่ครบ ให้ Swipe หรือ Regenerate เพื่อใช้ instruction ใหม่ ไม่ต้องล้างเงิน ไอเทม หรือข้อมูลตัวละคร

## การตรวจสอบ

- 702 unit/host tests และ syntax checks
- production loader ที่จอ 320/390/1280 px: quote ห้องพักจริงในรายงาน → รายการสองห้องจากคำตอบหลัก, ไม่มี API เพิ่ม, เงินและ inventory ไม่เปลี่ยน
- ทดสอบ raw response แบบ JSON fence ในเส้นทางกู้เดิม, Swipe/Regenerate contract และเพิ่มสกิลเดิมหลัง loadout เสร็จในคำตอบเดียวกันโดยรักษา Mastery
- regression ซื้อ/ขายหลายรายการ ประมูล การต่อโรล การยืนยันชำระเงิน การกู้รายการ และกระดานใน Main Chat

คำตอบ provider ในการทดสอบเบราว์เซอร์เป็นข้อมูลจำลอง ไม่มีการเรียกบริการ AI ภายนอก การเพิ่ม instruction ไม่ใช่การรับประกันว่า provider ทุกตัวจะส่ง payload ครบทุกครั้ง
