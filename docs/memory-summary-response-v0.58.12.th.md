# Memory Summaries — 0.58.12

ภาพรายงาน `MEMORY_INVALID_SUMMARY` ขณะตรวจหลักฐานต้นทาง โดยยังไม่มีบทที่บันทึก และ output แสดง 0 แม้ API ส่งคำตอบกลับมาแล้ว รายงานเดิมไม่มีคำตอบดิบหรือชื่อช่องที่ผิด จึงระบุไม่ได้ว่าโมเดลของผู้ใช้ส่งข้อมูลผิดช่องใด

## สาเหตุที่พบในโค้ด

- โหมด preset เรียก `generateQuietPrompt` เป็นข้อความแชตธรรมดา คำตอบจึงผ่านการจัดรูปแบบ/regex สำหรับเนื้อเรื่อง ทั้งที่งาน Memory ต้องใช้ JSON ข้อกำหนดรูปแบบเนื้อเรื่องจาก preset/WI ยังสามารถแข่งกับคำสั่งสรุปได้
- ตัวอ่าน JSON ของโฮสต์เลือก object แรกในคำตอบได้ ขณะที่ตัวล้าง Memory ไม่รองรับ `<planning>` จึงอาจเลือกข้อมูลใน planning หรือ object อื่นแทนผลสรุป
- ดัชนี `events` ที่หายหรือเป็น null ทำให้ทิ้งทั้งบท แม้ `summary` และ `recap` เป็นข้อความครบ ดัชนีเป็นข้อมูลค้นหาเสริมและไม่ควรทำให้สูญเสียสรุปที่สมบูรณ์
- ระบบนับ output หลังตรวจรูปแบบสำเร็จเท่านั้น และซ่อนข้อผิดพลาดทั้งหมดเป็นข้อความเดียว ทำให้คำตอบผิดรูปแบบดูเหมือนไม่ได้รับ output

## การแก้ไข

โหมด preset บน Chat Completion ใช้ JSON schema ของ SillyTavern เพื่อดึง JSON ก่อนการจัดรูปแบบข้อความเนื้อเรื่อง โดยยังใช้การเชื่อมต่อ preset และ WI/AN ที่เลือก ไม่สลับบัญชี ไม่เพิ่มข้อความเข้าแชต และไม่ยิงคำขอซ่อมอัตโนมัติ Text Completion คงเส้นทางข้อความเดิม เพราะตัวดึง JSON ของโฮสต์รองรับ Chat Completion เท่านั้น ส่วน Compact ยังคงใช้ native data/task ของโฮสต์

คำสั่งสรุประบุรูปแบบงานข้อมูลอย่างชัดเจน ตัวอ่านข้าม reasoning/planning ที่ปิดครบ เลือก object ผลสรุปแทน object อื่นที่อยู่ก่อนหน้า และรักษาแท็ก เครื่องหมายคำพูด และวงเล็บที่เป็นข้อความใน JSON ไม่ดึงผลสรุปจาก reasoning ที่ยังไม่ปิด ไม่เติมวงเล็บเพื่อซ่อม JSON ที่ถูกตัด และไม่ดึง object ภายใน wrapper ที่ยังไม่ครบ

ถ้า summary และ recap สมบูรณ์แต่ไม่มี events ระบบบันทึกสรุปและต้นฉบับ พร้อมแจ้งว่าดัชนีเหตุการณ์ขาด ไม่สร้างเหตุการณ์หรือหลักฐานขึ้นเอง หาก summary/recap หาย ว่าง ไม่ใช่ข้อความ หรือ JSON ยังไม่ครบ ระบบยังไม่บันทึกบท และคงข้อความเหล่านั้นไว้ให้ทำต่อ

รายละเอียดปัญหาแสดงช่องที่ผิด ความยาวคำตอบที่ได้รับ และนับ output ก่อนตรวจรูปแบบ API ที่รายงานว่าถึงขีดจำกัด output จะแสดง `MEMORY_RESPONSE_TRUNCATED` พร้อมสาเหตุหยุด และให้ทำต่อด้วยชุดเล็กลงโดยไม่เปลี่ยนค่าขนาดชุดเดิม ไม่ลบหรือสรุปข้อความที่บันทึกแล้วซ้ำ

## วิธีใช้

อัปเดตส่วนขยายและรีโหลดหน้า รอการเจนแชตหลักจบ จากนั้นกด “ลองใหม่ / ทำต่อ” ใน Memory Addons ไม่ต้องล้างข้อมูลเบราว์เซอร์หรือเริ่มคลังใหม่ หากยังผิดรูปแบบ ให้เปิดรายละเอียดปัญหาและดูช่องที่ผิด หากผู้ให้บริการไม่รองรับ structured generation ให้เลือก Compact ในการตั้งค่างานสรุปแล้วทำต่อ

## การตรวจสอบ

- ผ่าน 1,086 unit/host tests และ syntax checks
- ทดสอบ preset แบบ structured ที่คง WI/AN, Text Completion ที่ไม่เข้า JSON extractor, planning และ literal tags, object ที่ไม่ใช่สรุป, ดัชนีที่หาย/null, JSON ไม่ครบ, ช่อง recap/summary ผิด, output limit และไม่มีคำขอซ่อมอัตโนมัติ
- ทดสอบข้อความเดิม 101 ข้อความ: ล้มเหลวครั้งแรก แล้วทำต่อและโหลดหน้าใหม่โดยต้นฉบับอยู่ครบ ไม่มีข้อความค้าง และไม่มีการเรียก AI ซ้ำตอนเปิดคลัง
- ไม่ได้ทดสอบ API/โมเดลจริงของผู้ใช้หรือ Safari บน iPhone การผ่าน fixture ยืนยันพฤติกรรมส่วนขยาย แต่ไม่รับรองว่าทุกโมเดลจะส่ง JSON สมบูรณ์ทุกครั้ง

อ้างอิงเส้นทาง structured quiet generation ของโฮสต์: [SillyTavern public/script.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js) (`generateQuietPrompt`, `Generate.onSuccess`, `extractJsonFromData`) ตรวจสอบเมื่อ 6 ตุลาคม 2026
