# RoleForge 0.58.1 — แก้แผงซื้อขายหายเมื่อพูด “ซื้อ…แล้วกัน”

ปัญหานี้เป็นบัคของส่วนเสริม ผู้ใช้เปิด Negotiated Marketplace และพิมพ์ซื้อของตามปกติแล้ว แต่กฎตรวจธุรกรรมย้อนหลังตีความคำว่า “แล้วกัน” ผิดว่าเป็นการซื้อที่จบไปแล้ว จึงไม่แสดงแผงซื้อขายเหนือ ChatBar และไม่ส่งคำสั่งซื้อขายเฉพาะคำขอนี้เข้าสู่คำตอบหลัก

## สาเหตุที่ทำซ้ำได้

ข้อความจากเคสจริง:

> “ซื้อทั้งสามเล่มเลยแล้วกัน.. ช่วยลดให้หน่อยได้มั้ยครับ..? สักนิดก็ยังดี..”

ใน 0.58.0 กฎลบข้อความประวัติซื้อขายจับตั้งแต่ “ซื้อ” ถึง “แล้ว” และตัดคำขอนี้ออก ทำให้ `settledCommerceFollowup` เป็น `true` และ `requestedCommerceKind` เป็นค่าว่าง ทั้งแผงรอข้อมูลและคำสั่ง AI สำหรับเปิดข้อเสนอจึงถูกข้าม

ใน 0.58.1 ข้อความเดียวกันให้ `settledCommerceFollowup=false` และ `requestedCommerceKind=buy` ส่วน “ซื้อดาบมาแล้ว ขอเก็บใส่กระเป๋า” ยังคงเป็นการกล่าวถึงรายการเก่าที่จบแล้ว ไม่เปิดใบซื้อใหม่

คำตอบที่ผู้ใช้ส่งมามีข้อเสนอ 45 → 40 เหรียญเงิน แต่ไม่ได้ส่งข้อมูลรายการที่ระบบยืนยันได้ และกล่าวถึงหนังสือรวม ๆ โดยไม่ระบุรายชื่อในคำตอบปัจจุบัน การพูดราคาอย่างเดียวไม่เพียงพอสำหรับสร้างธุรกรรมที่ตรวจสอบได้ แม้กรณีนี้จะยังซื้อไม่ได้ แผงควรแสดงสถานะให้เห็น ซึ่งกฎที่ผิดทำให้แผงนั้นหายด้วย

## สิ่งที่แก้

- เก็บคำขอซื้อ/ขายที่ลงท้าย “แล้วกัน” รวมถึงรูปแบบเว้นวรรค และหยุดจับที่ “แล้ว” ตัวแรกเพื่อไม่ให้ข้ามไปกินประโยคย้อนหลังถัดไป
- ส่งคำสั่งรายการซื้อขายและข้อมูลไอเทมครบถ้วนเข้า normal reply contract สำหรับคำขอนี้อีกครั้ง
- แสดงสถานะเหนือ ChatBar ตั้งแต่รอ AI; หากคำตอบพูดราคาแล้วแต่ยังไม่มีรายการที่ยืนยันได้ แสดง “พบข้อเสนอราคา แต่ AI ยังส่งข้อมูลรายการไม่ครบ · เงินและของยังไม่เปลี่ยน”
- แชตเก่าของเคสนี้ที่ไม่มี marketplace/opening record กลับมาแสดงแผงสถานะได้หลังโหลดใหม่ โดยไม่เรียก AI เพิ่มหรือเล่นคำตอบเก่าซ้ำ
- ไม่ใช้ราคาหรือรายการจาก `<planning>` เป็นข้อเสนอจริง และคงการแยกข้อมูลคิดภายในออกจากข้อเสนอที่เผยแพร่ในบทสนทนา
- ปรับ manifest/package และ cache key ของไฟล์ใช้งานเป็น 0.58.1 พร้อมกัน

แผงสถานะไม่ได้สร้างหนังสือสามเล่มหรือรายละเอียดสกิลขึ้นจาก planning และยังไม่มีปุ่มจ่ายเงินจนกว่าจะมีข้อเสนอที่ผ่านการตรวจสอบ ข้อมูลไอเทมยังเป็นหน้าที่ของ AI ในคำตอบ ไม่ใช่ให้ผู้ใช้เขียน schema เอง คำตอบเก่าที่มีเพียงราคารวมจะมีแผงแจ้งข้อมูลไม่ครบ; คำตอบถัดไปที่ให้รายการครบจึงเปิดการซื้อขายได้

- `npm test`: ผ่าน 970/970 unit/host tests
- `npm run check`: ผ่าน syntax checks ของไฟล์ใช้งาน
- `tests/commerce-pending.browser.mjs`: ผ่าน 320/390/1280px โดยโหลด production extension loader และใช้เหตุการณ์ MESSAGE_SENT / GENERATION_STARTED / MESSAGE_RECEIVED / GENERATION_ENDED ของโฮสต์จำลอง ตรวจคำขอจริง, prompt สำหรับ AI, แผงระหว่างรอและหลังคำตอบไม่มี patch, ตำแหน่งเหนือ ChatBar, ไม่มีแนวนอนล้น, เปิดแชตเก่าที่ไม่มี record, เปิด/ปิดระบบ และข้อความเก็บของที่ซื้อเสร็จแล้ว

- `tests/commerce-rights.browser.mjs`: ผ่าน 320/390/1280px ตรวจซื้อถาวร เช่า สิทธิ์เข้าถึง บริการ มัดจำ กุญแจ การคืนเงิน และป้องกันการโอนซ้ำ
- `tests/optional-systems.browser.mjs`: ผ่าน 320/390/1280px ตรวจ live gates, ปิด prompt เมื่อปิดระบบ, pause/resume และข้อมูลที่บันทึกไว้
- `tests/commerce-openings.browser.mjs`: ผ่าน 320/390/1280px ตรวจการเปิดร้าน/ขาย/ห้องพักในคำตอบหลักและการชำระเดิมร่วมกับหน้าต่างอื่น รวมการเปิดหน้าต่างพากย์ขณะที่แผงซื้อขายยังเปิดอยู่ ปรับการเลื่อนในโฮสต์ทดสอบให้ปุ่มอยู่เหนือ dock ก่อนคลิกจริง พร้อมตรวจตำแหน่ง; ไม่ force click หรือซ่อนแผงเพื่อให้ผ่าน
- `git diff --check`: ผ่าน; ตรวจ main ต้นทางก่อนเผยแพร่ และอัปเดตแบบ fast-forward ไม่ force

การทดสอบใช้ Chromium และโฮสต์/คำตอบ API แบบ fixture ไม่ใช่การเข้าอุปกรณ์ผู้ใช้หรือยืนยันพฤติกรรมทุกโมเดล รายงาน 0.58.0 บันทึกข้อจำกัดของ combined chat fixture เดิมไว้แล้ว; รอบนี้ไม่อ้างว่าชุดนั้นผ่าน การแก้นี้ไม่รับประกันว่าโมเดลทุกตัวจะส่งข้อมูลครบทุกครั้ง แต่เคสที่ตรวจพบจะมีแผงสถานะ และจะไม่ทำรายการหากข้อมูลไม่ผ่าน

หลังอัปเดตส่วนเสริมเป็น 0.58.1 ให้รีโหลด SillyTavern แล้วเปิดแชตเดิม ระบบจะอ่านคำขอซื้อจากข้อความจริงและแสดงสถานะอีกครั้ง ไม่ต้องเปลี่ยนคำพูด “แล้วกัน”
