# Death Note · แก้สถานะสมุด ยมทูต และรายชื่อ — 0.82.2

อัปเดต RoleForge แล้ว reload SillyTavern เปิดแชทเดิมและหน้า Death Note ได้เลย ไม่ต้องลบประวัติหรือเริ่มเล่นใหม่ การ์ดฉบับไม่มีภาพรุ่น `1.0.1-no-portraits.2` ใช้กับแชทใหม่ได้จาก [JSON](../cards/death-note-rpg/build/Death-Note-RPG-No-Portraits.json) หรือ [PNG](../cards/death-note-rpg/build/Death-Note-RPG-No-Portraits.png) เลือกนำเข้าอย่างใดอย่างหนึ่ง

## สาเหตุและสิ่งที่แก้

- **ยมทูตเจ้าของเดิมไม่แสดง:** แชทเก่าบางแชทมีข้อมูล Ryuk และพบกันแล้ว แต่รายการลงทะเบียนสมุดไม่ได้ผูก `originalShinigamiId` ระบบอ่านคำพูดที่ระบุชัดว่าสมุดเล่มนี้เคยเป็นของยมทูต โดยอ้างอิง NPC id ใน dialogue จึงรองรับชื่อที่ใช้ในโรลต่างจากชื่ออังกฤษ หากมีสมุดหลายเล่มและระบุไม่ได้ว่าเป็นเล่มใด ระบบไม่เดาสุ่ม และไม่เขียนทับเจ้าของเดิมที่ผูกไว้แล้ว
- **มีสมุดในข้อความเปิดแต่ใช้ไม่ได้:** อ่านเฉพาะข้อความเปิดที่เลือกอยู่ ฉาก 5 และ 10 ของการ์ดไม่มีภาพแสดงสมุดที่ถืออยู่ทันทีเมื่อเปิด addon ฉาก 1 ที่สมุดยังอยู่บนพื้น และฉาก 2 ที่ Light เป็นผู้หยิบ ไม่ให้สมุดแก่ผู้เล่น การปัดไปฉากอื่นก่อนเริ่มเล่นจะเอาเฉพาะสมุดที่ระบบเตรียมจากฉากเปิดออก การให้ยืม วางทิ้ง หรือสละสิทธิ์ในภายหลังยังมีผลตามเดิม
- **ชื่อไทยไม่ผ่าน:** เพิ่มคำสะกดชื่อจริงแบบไทยและอังกฤษที่ผู้สร้างกำหนด เช่น `คุโร่ โอโตฮาราดะ`, `Kurou Otoharada` และ `Kuro Otoharada` ชื่อเล่น ชื่อบางส่วน หรือชื่อที่ NPC โกหกไม่ได้กลายเป็นชื่อจริง การเลือกเวอร์ชันที่มีชื่อจริงต่างกันยังแยกข้อมูลกัน
- **ชื่อกับเงื่อนไขอยู่บรรทัดเดียวกันแล้วไม่ถูกส่ง:** แยกชื่อเต็มที่ตรงกันออกจากเงื่อนไข เช่น `Kurou Otoharada ตายกระทันหัน` เก็บหมึก ตำแหน่ง และขนาดไว้ตามเดิม เขียนแล้วส่งโรลปกติได้ หรือใช้ลิงก์ต่อเรื่องในสมุดก็ได้ ไม่มีการสร้างข้อความผู้ใช้แทน
- **โรลยืนยันผลแต่หน้ารายชื่อไม่อัปเดต:** หาก AI ลืมส่ง footer ระบบยืนยันผลได้จากข้อความที่ระบุชื่อผู้ตายตรงกันและเวลาที่ผ่านไปในเรื่องชัดเจน ต้องครบเวลาตามคำสั่ง ชื่อผิด ข่าวปลอม สมมติฐาน คนที่เพียงเห็นผู้อื่นเสียชีวิต และข้อความในกฎปลอมไม่ยืนยันผล ผลที่ตรวจผ่านอัปเดตทั้งหน้ารายชื่อและ HP/activity ของ NPC

## แชทเดิม

รายการที่มีคำสั่งอยู่แล้วแต่ผลยังค้างจะถูกตรวจซ้ำเมื่อเปิดแชท โดยไม่ส่งข้อความผู้ใช้หรือเรียกโมเดลเพิ่ม

รุ่นเก่าบางกรณีบันทึกหมึกไว้ก่อนกด Send แต่ไม่ได้สร้างรายการคำสั่ง รุ่นนี้กู้รายการได้เมื่อหมึกผูกกับ User turn เดิม มีหลักฐานเห็นใบหน้าก่อนเขียน และคำตอบถัดไปยืนยันผลพร้อมเวลาที่ผ่านไปจริง ไม่สร้างผลจากข้อความเสียชีวิตที่ไม่มีหมึกบันทึกไว้

ความพยายามเก่าที่ไม่สำเร็จคงอยู่ตามประวัติ และแยกจากรายการใหม่ที่สำเร็จ หน้ารายชื่อเรียงรายการล่าสุดก่อน หากเวลาเขียนเดิมไม่ได้บันทึกไว้ จะแสดงว่าเป็นรายการกู้คืนแทนการแสดงเวลาเป็นข้อเท็จจริง การกู้คืนไม่แก้ข้อความโรล ไม่เลื่อนเวลาโลกเพิ่ม ไม่ทำรายการซ้ำเมื่อ reload และไม่ดึงคำสั่งจากอนาคตเข้ากิ่งแชทที่ตัดก่อน User turn นั้น

## การทดสอบ

- `npm test` — 1,683 ผ่าน รวมชื่อปลอม การแยกเวอร์ชัน กฎปลอม การครอบครอง ใบหน้า การส่งหมึก และขอบเขต branch/swipe
- `npm run check` — ผ่าน
- SillyTavern 1.19.0 จอคอม 1440 × 1000 และจอมือถือ 390 × 844 แบบ touch emulation ใช้ UI ไทยและอังกฤษ
- นำเข้าการ์ดไฟล์เดียว ปัดครบ 10 ข้อความเปิด ตรวจครอบครองทันที ผูก Ryuk และปัดกลับไปฉากไม่มีสมุด
- นำเข้าแชทที่รายงานปัญหาผ่าน API ปกติของ SillyTavern ตรวจการกู้รายการภาษาอังกฤษ แยกจากความพยายามภาษาไทยเก่า HP = 0 หมึกไม่หาย ข้อความโรลไม่เปลี่ยน และ reload ไม่มีรายการซ้ำ
- ส่งโรลใหม่ด้วยชื่อไทยกับเงื่อนไขบรรทัดเดียว รับคำตอบภาษาอังกฤษที่ไม่มี footer/HP patch ผ่าน SSE จำลอง ตรวจหนึ่งคำขอโมเดล หนึ่ง User turn ที่กดส่งจริง และผลตรงกันทั้งรายชื่อกับ HP

คำตอบโมเดลในการทดสอบใหม่เป็น SSE ที่ควบคุมไว้ ไม่ได้ทดสอบด้วยโมเดลสด มือถือเป็นการจำลอง touch ใน Chromium ไม่ใช่ Safari บนเครื่องจริง ไฟล์แชทส่วนตัวและภาพจากแชทนั้นไม่รวมใน repository
