# RoleForge 0.51.1 — โรลและปุ่มใช้รายการเดียวกัน

ซื้อ ขาย และประมูลรองรับข้อความโรลปกติร่วมกับปุ่มเหนือช่องพิมพ์ ไม่ต้องสร้างรายการใหม่หรือกดซ้ำหลังส่งโรล

- พิมพ์ “ผมเสนอ 2 เหรียญเงิน” → API ของคำตอบหลักพิจารณาปฏิกิริยา NPC และส่งสถานะกลับมาพร้อมคำตอบ หากรับราคา แถบแสดงราคาตกลง แต่ยังไม่จ่าย
- พิมพ์ “ตกลง ซื้อราคา 2 เหรียญเงิน” หรือกดยืนยัน → NPC พิจารณา หากรับราคาเดิมจึงจ่ายเงินและส่งของ หากเปลี่ยนราคาเป็นข้อเสนอใหม่ ต้องรอการยืนยันอีกครั้ง
- ถามสภาพสินค้า โน้มน้าว ข่มขู่ หรือคุยเรื่องอื่นได้ คำตอบของ NPC เป็นบริบทให้การตัดสินใจถัดไป การคุยไม่ได้บังคับให้ผู้ประมูลเดินราคาหรือเคาะขาย
- ระบุชื่อสินค้าในรายการเพื่อขอดูชิ้นอื่นได้ แถบเปลี่ยนสินค้าที่เลือกและแสดงราคาของชิ้นนั้น ไม่ใช้ราคาสินค้าก่อนหน้า
- โรลบิด รอ ออกประมูล เข้าร่วม หรือไป lot ถัดไปได้ การบิดครั้งแรกในงานที่ยังไม่เข้าร่วมหมายถึงเข้าและบิดในคำตอบเดียว ตรวจค่าเข้า/มัดจำก่อนและบันทึกพร้อมกัน หากผล NPC ไม่ถูกต้อง จะไม่หักแม้แต่ค่าเข้า
- แถบหายเมื่อจบ ซื้อขายสำเร็จ ปฏิเสธ หรือยกเลิก งานประมูลหลาย lot ยังมีแถบจนจบงาน/ออกจากงาน

## ลำดับข้อความและ API

ส่ง user ใหม่ → NPC ตอบเป็น assistant message ถัดจาก user ตามปกติ คำตอบเดียวกันส่ง `commerce` ใน hidden `tretaresia_patch`; ระบบอ่านผลโดยไม่เรียก API ซื้อขายเพิ่ม ส่วนปุ่มที่กดหลังคำตอบเสร็จใช้ quiet API หนึ่งครั้งและต่อข้อความในคำตอบ NPC ล่าสุด ไม่ย้อนเติมเหนือข้อความ user ใหม่

หากมีโรลใหม่เข้ามาระหว่างรอผลปุ่ม ผลปุ่มเก่าที่ล้าสมัยจะถูกทิ้ง และอ่านผลจากคำตอบหลักที่จบแล้วต่อโดยไม่เรียก AI เพิ่ม คำสั่ง Continue ของ NPC ไม่สามารถนำข้อเสนอ user เก่ามาจ่ายซ้ำได้

ระหว่างรอคำตอบหรือมีข้อความ user ที่ยังไม่มีคำตอบ ปุ่มธุรกรรมไม่พร้อมใช้งาน การขยายแถบและเลือกสินค้าไม่เรียก API บริบท NPC ยังมาจาก card/preset/lore และบุคลิกที่ใช้อยู่ ระบบ Summary ใช้การตั้งค่า API และ flow ของตัวเองตามเดิม

## ความยินยอมและธุรกรรม

AI อ่านเจตนาจากข้อความผู้เล่นล่าสุด แล้วส่ง session ID, revision, action, ราคา, item ID, สกุลเงิน, ข้อความอ้างอิงจากผู้เล่น และผลตัดสิน NPC ระบบตรวจข้อความอ้างอิง ราคาที่ผู้เล่นระบุ (รองรับเลขอารบิก เลขไทย และคำจำนวนไทย), ราคาปัจจุบัน งบจริง เงินที่กันไว้ และจำนวนของ ก่อนใช้ engine/ใบรับผลเดียวกับปุ่ม

“ถ้าลดเหลือ 2 เหรียญก็น่าสนใจ” ไม่ใช่คำยืนยันซื้อ หากเจตนาหรือราคาสินค้าไม่ชัด AI ควรถามให้ชัดแทนการซื้อ/บิดให้เอง ผลผิดงบ ผิดราคา ไม่มีข้อความผู้เล่นรองรับ สกุลเงินไม่ตรง หรือ revision เก่า แสดงแจ้งในแถบและไม่เปลี่ยนเงิน/ของ ไม่ลอง API ซ้ำอัตโนมัติ หาก provider ไม่ส่งข้อมูลการกระทำ ระบบติดตามตำแหน่งคำตอบล่าสุดได้ แต่ไม่เดาธุรกรรมจากร้อยแก้วเอง

ops เงิน/ของทั่วไปไม่สามารถจ่ายธุรกรรมที่เปิดอยู่อีกช่องทาง รางวัลเควสที่ระบุ canonical questId และ category quest-reward ยังผ่านตัวตรวจรางวัลครั้งเดียวตามเดิม ทุกผลจ่ายสำเร็จมี receipt, ledger และ checkpoint ของคำตอบนั้น Reload/อ่านคำตอบซ้ำไม่จ่ายซ้ำ; สลับคำตอบใช้ระบบคืนสถานะเทิร์นเดิม หากโฮสต์รายงาน save ล้มเหลว คืนค่า state และ patch ของคำตอบให้ลองบันทึกใหม่โดยไม่เรียก AI เพิ่ม ข้อจำกัดของโฮสต์ที่กลืน save error ยังคงตามเอกสารรุ่นก่อน

## ตรวจสอบ

`npm test` ผ่าน 550 เคส; `npm run check` ตรวจ syntax ผ่าน ทดสอบ engine, runtime, host parser/persistence และ browser DOM ผ่าน production loader กับ native generation events บน 320/390/1280 px ครอบคลุมโรลเสนอราคา → ปุ่มยืนยัน, โรลขายจบ, โรลบิดพร้อมเข้า, งบ NPC, คำยืนยันแบบมีเงื่อนไข, การเลือกสินค้า, save rollback, reload/replay และรางวัลเควสระหว่างคุยซื้อขาย คำตอบ provider ในชุดทดสอบเป็นข้อมูลจำลอง ไม่ใช่การทดสอบ connection จริงของผู้ใช้
