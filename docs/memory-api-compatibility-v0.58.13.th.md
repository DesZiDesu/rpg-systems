# Memory API compatibility — 0.58.13

ภาพรายงานรอบนี้เป็น `Bad Request` / `MEMORY_API_REQUEST_FAILED` ขณะเรียก API ไม่ใช่ตอนตรวจรูปแบบสรุป ยังไม่มี output หรือบทที่บันทึกจากคำขอนั้น ข้อความที่เหลือ 101 ข้อความยังอยู่ในคลัง

## จุดผิดในเวอร์ชันก่อน

0.58.12 ส่ง `jsonSchema` ให้ `generateQuietPrompt` ทุกครั้งที่โฮสต์ระบุ `mainApi: openai` แต่ค่านี้รวมทั้ง OpenAI, โมเดลจากผู้ให้บริการอื่น และ proxy ที่รองรับเพียงข้อความแชตธรรมดา การรองรับ Chat Completion ไม่ได้หมายถึงรองรับ JSON schema

SillyTavern แปลงพารามิเตอร์นี้เป็น `response_format`, schema หรือ forced tool ตามผู้ให้บริการ API ที่ไม่รองรับจึงปฏิเสธคำขอด้วย HTTP 400 ได้ การบังคับ schema กว้างเกินไปเป็นข้อผิดพลาดของส่วนขยาย รูปที่ส่งมายังไม่มีรายละเอียด body จากผู้ให้บริการ จึงยืนยันไม่ได้ว่า API ของผู้ใช้ปฏิเสธพารามิเตอร์ใดโดยเฉพาะ

ตัวแปลข้อผิดพลาดเดิมไม่รู้จักข้อความ `Bad Request` ที่ไม่มีเลข HTTP และไม่อ่าน message จาก `cause` ของ Connection Manager อย่างครบถ้วน จึงแสดงสาเหตุกว้างเกินไป คำแนะนำลดขนาดชุดจากการล้มเหลวก่อนหน้ายังอาจถูกนำมาใช้กับ HTTP 400 ครั้งถัดไป ทั้งที่การลดชุดไม่ได้แก้พารามิเตอร์ที่ไม่รองรับ

## การแก้ไข

- เอาการบังคับ schema ออกจาก Memory preset ทั้งหมด ไม่เพิ่ม `response_format` หรือบังคับ tools ให้ผู้ให้บริการ คำขอ preset ยังคงใช้ WI/AN และ preset ที่เลือก ส่วนตัวอ่านและการตรวจหลักฐานใน 0.58.12 ยังทำงานเหมือนเดิม
- เมื่อผู้ใช้กด “ลองใหม่ / ทำต่อ” หลัง Bad Request หรือ JSON ผิดรูปแบบ หากโฮสต์มี native raw data/task และไม่ได้เลือก Connection Manager profile งานรอบนั้นใช้ Compact prompt บน API/โมเดลเดิม อ่านคำตอบก่อน regex/การจัดรูปแบบเนื้อเรื่อง โดยไม่ส่ง schema เพิ่ม ไม่ยิงคำขอซ่อมอัตโนมัติ และไม่เปลี่ยนการตั้งค่าถาวร
- แสดงข้อความว่ารอบทำต่อใช้ Compact prompt: ส่งงานสรุปและแหล่งข้อมูลที่เลือก ไม่แนบ context เนื้อเรื่อง/preset ทั้งชุด แต่ใช้ API/โมเดลปัจจุบันและค่าการเจนของการเชื่อมต่อนั้น
- โปรไฟล์ Connection Manager ที่ผู้ใช้เลือกยังใช้โปรไฟล์เดิม ไม่สลับไป API ปัจจุบัน โฮสต์เก่าที่มีเพียง quiet API ใช้ preset แบบไม่บังคับ schema
- ไม่ใช้คำแนะนำย่อชุดเก่ากับข้อผิดพลาด API เช่น 400/401/403/429 ใช้การย่อชุดเฉพาะกรณีรูปแบบสรุปไม่ครบ คำตอบถูกตัด ข้อความว่าง หรือหมดเวลา ส่วนการจำกัด input ตามงบยังทำงานตามเดิม
- รู้จัก `Bad Request` เป็น HTTP 400 และอ่านสถานะ/ข้อความที่ซ้อนใน `cause` แสดงข้อความผิดพลาดจาก API ในรายละเอียด โดยปิดบังข้อมูลรับรองและ escape ข้อความก่อนแสดง ไม่ตีความ 400 ว่าโควต้าหมดโดยไม่มีหลักฐาน
- บทที่สำเร็จ ต้นฉบับ การค้นคืน และการทำต่อหลังโหลดหน้าใหม่ยังใช้คลังเดิม ห้ามบันทึกผลที่ยังไม่สมบูรณ์หรือเปลี่ยนแชตระหว่างคำขอ

## การใช้

อัปเดตเป็น 0.58.13 แล้วรีโหลด จากนั้นกด “ลองใหม่ / ทำต่อ” ใน Memory Addons ไม่ต้องล้างข้อมูลหรือสร้างคลังใหม่ งานเดิมที่แสดงรหัสกว้าง ๆ จาก 0.58.12 ก็ทำต่อด้วยคำขอแบบธรรมดาได้บนโฮสต์ที่รองรับ

หากยังล้มเหลว ให้ดู HTTP และ “ข้อความผิดพลาดจาก API” ซึ่งแยกรูปแบบคำขอ สิทธิ์ โควต้า context และการเชื่อมต่อได้ตามข้อมูลที่โฮสต์ส่งกลับ การเอา schema ออกไม่ได้แก้ทุกกรณี HTTP 400 เช่นชื่อโมเดลหรือค่าจาก preset/proxy ที่ไม่ถูกต้อง

## ผลตรวจสอบ

ผ่าน 1,093 unit/host tests, syntax checks และตรวจ whitespace

กรณีทดสอบเพิ่มครอบคลุมผู้ให้บริการที่ปฏิเสธ schema, Bad Request และข้อผิดพลาดซ้อนใน cause, การปิดบัง/escape ข้อมูลผิดพลาด, คำขอเดียวก่อนล้มเหลว, การทำต่อโดยไม่ย่อชุดเพราะคำแนะนำเก่า, การคง API/โปรไฟล์/การตั้งค่าเดิม และโฮสต์ quiet รุ่นเก่า

ทดสอบคลังเดิม 101 ข้อความพร้อมสถานะงานเก่าจาก 0.58.12: ทำต่อด้วย native data 7 ชุดตามขนาด 15 ข้อความ ไม่มี schema/tools เพิ่ม ไม่มี quiet request ซ้ำ ข้อความค้างเป็น 0 ต้นฉบับ แชตและเงินอยู่ครบ และโหลดหน้าใหม่ไม่ยิง API ซ้ำ

ไม่ได้ทดสอบ API จริงของผู้ใช้หรือ Safari บน iPhone การทดสอบใช้คำตอบควบคุมที่จำลอง provider rejection จึงยืนยันการแก้คำขอส่วนขยายและการเก็บข้อมูล ไม่รับรองค่าหรือความพร้อมของ API ภายนอก
