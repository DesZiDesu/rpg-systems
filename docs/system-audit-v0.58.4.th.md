# ตรวจระบบ RoleForge — 0.58.4

## ผลตรวจ

พบและแก้ปัญหาเพิ่มเติมสองกลุ่ม: งาน JSON หลายระบบยังผ่านตัวกรองข้อความบทโรล และคำขอ Memory บางโหมดเริ่มเรียก API ทั้งที่ถูกยกเลิกก่อนเริ่มแล้ว ส่งชุดแก้เข้า main เป็นรุ่น 0.58.4

ชุดทดสอบก่อนแก้ผ่าน 1,020 รายการ แต่ยังไม่มีกรณีจำลองปัญหาเหล่านี้ การเพิ่ม regression tests จึงทำให้เห็น failure ที่ชุดเดิมตรวจไม่ถึง หลังแก้ผ่าน **1,033/1,033 รายการ** ไม่มี failure, cancellation หรือ skipped tests และ `npm run check` ผ่าน ตรวจ relative imports ของไฟล์ runtime 100 ไฟล์ รวม 258 references ไม่พบไฟล์ปลายทางหาย

ผลนี้ยืนยันพฤติกรรมที่ชุดทดสอบครอบคลุม ไม่ใช่การรับรองทุกหน้าจอหรือทุก provider บน SillyTavern จริง

## สาเหตุและการแก้ไข

### 1. JSON เสียก่อนถึงระบบปลายทาง

ระบบซื้อได้รับการแก้ใน 0.58.3 แล้ว แต่การใช้ไอเทม เติมรายละเอียดไอเทม กู้ข้อมูล Loot ฝึกพลัง สร้าง NPC สรุป Memory แบบ compact เติม NPC baseline/H-Stats และ Manual Sync ยังเรียก API ที่นำข้อความผ่าน story cleanup/AI-output Regex ได้ หากตัวกรองลบหรือเปลี่ยน JSON ระบบปลายทางจึงได้ข้อความว่างหรือข้อมูลที่อ่านไม่ได้

0.58.4 รวมเส้นทางขอข้อมูลไว้ใน `src/task-generation.js` ใช้ `generateRawData` และ `extractMessageFromData` เมื่อโฮสต์รองรับ เพื่อรับข้อมูลก่อนตัวกรองบทโรล ระบบซื้อใช้ตัวกลางเดียวกันด้วย โฮสต์เก่ายังมี fallback ตาม API ที่รองรับ จึงอาจยังได้รับผลจากตัวกรองของโฮสต์เก่า

ตัวกลางแยกคำตอบว่าง คำตอบที่ครบขีดจำกัดโทเคน และ provider error พร้อมรักษา HTTP status ที่ provider ส่งมา เพื่อให้ Memory แนะนำการแก้ปัญหาได้ตรงขึ้น ปิดบังรูปแบบ API key ที่รู้จักในข้อความ error การล้มเหลวของ API ไม่ทำให้ส่งคำขอสำรองซ้ำอัตโนมัติ ส่วนการลองแก้ draft NPC ที่ผิดรูปแบบตามเงื่อนไขเดิมยังคงทำงาน

เพิ่มการตรวจว่าโฮสต์ซึ่งมีเฉพาะ native data API ก็ใช้งานเส้นทางเหล่านี้ได้ รองรับ adapter เก่าที่คืน parsed JSON object และคงงบคำตอบของ compact Memory แยกจากความยาวบทโรลตามเดิม

Memory โหมด preset และการอ่านภาพ NPC ยังใช้เส้นทางที่รองรับ preset/ภาพตามเดิม ไม่ได้เปลี่ยนเป็นคำขอข้อความข้อมูลทั่วไป

### 2. ยกเลิก Memory แล้วแต่ยังเริ่ม API

เดิมตรวจ signal ที่ถูกยกเลิกเฉพาะ Memory โหมด preset ทำให้ compact และ connection profile ที่เลือกยังส่งคำขอได้ แม้ signal ถูกยกเลิกก่อนเรียกฟังก์ชัน

เพิ่มการตรวจยกเลิกก่อนเลือกเส้นทาง API ทดสอบทั้ง compact และ profile ว่าไม่มีคำขอออกไป การแก้ครั้งนี้ไม่ได้รับรองว่าผู้ให้บริการทุกชนิดหยุดการประมวลผลที่เริ่มไปแล้วได้

## ระบบที่ตรวจด้วย unit/host tests

| ระบบ | ผลในชุดทดสอบรอบนี้ |
|---|---|
| ซื้อขาย ตะกร้า สกุลเงิน ห้องพัก สิทธิ์ใช้บริการ | ผ่าน รวมข้อเสนอ Barth และการยืนยันธุรกรรม |
| ไอเทม รายละเอียด ผลต่อสเตตัส การเรียนวิชา Loot | ผ่าน รวมการรับข้อมูลก่อน Regex และการไม่เปลี่ยน ownership ระหว่างตรวจ Loot |
| ฝึกพลัง ความชำนาญ Presets และทรัพยากรพลัง | ผ่าน รวมเส้นทาง API ฝึกพลัง |
| NPC ชื่อ บทพูด ขอบเขตข้อมูล Draft ภาพ และ H-Stats | ผ่าน รวม orchestration ของ draft ที่ได้รับ JSON ก่อน Regex |
| Memory สรุป ค้นหา ลบ Continuity และ Location memory | ผ่าน รวมการยกเลิกก่อนเริ่มและงบคำตอบ compact |
| ภารกิจ เป้าหมาย รางวัล Story agenda และบันทึกเรื่อง | ผ่านตามกรณีในชุดทดสอบ |
| ประมูล Mission board และ Group board | ผ่านตามกรณีในชุดทดสอบ |
| Lore นำเข้า/ส่งออก Character archive และ Forge | ผ่านตามกรณีในชุดทดสอบ |
| Main Chat, Manual Sync, scene tracking และ host lifecycle | ผ่านตามกรณีในชุดทดสอบ |
| Incantation, Voice, UI ภาษา และการแจ้งเตือน | ผ่านด้วย fixtures/mocks ที่ชุดทดสอบกำหนด |

ชุดทดสอบใหม่มี 13 รายการ ครอบคลุมการรับ JSON ของแต่ละเส้นทาง คำขอเดียวโดยไม่ผ่าน story cleanup, native data-only host, compatibility ของ parsed object, HTTP status/error redaction, งบ Memory, ยกเลิกก่อนเริ่ม และ NPC draft orchestration

## ข้อจำกัดที่ยังต้องตรวจบนเครื่องจริง

ลองเริ่ม production startup browser suite แล้ว แต่เปิด browser ไม่ได้เพราะไม่มี Chromium executable การติดตั้งในสภาพแวดล้อมนี้ไม่สำเร็จ จึงไม่ได้ทดสอบ browser suites ของรุ่นนี้ ไม่ได้เชื่อมต่อ provider ของผู้ใช้หรือทดสอบบน SillyTavern ที่ติดตั้งจริง Voice/audio, vision และ connection profiles ใช้ข้อมูลจำลองในการตรวจรอบนี้

README เดิมบันทึกว่า combined chat browser fixture มี baseline assertion failure อยู่แล้ว รอบนี้ยังรันยืนยันหรือแก้ fixture นั้นไม่ได้ จึงไม่ถือว่า browser suite ทั้งหมดผ่าน

หลังอัปเดตจาก main ให้โหลดหน้าใหม่และตรวจรุ่น 0.58.4 แล้วลองการซื้อ ใช้ไอเทม สร้าง NPC ฝึกพลัง และสรุป Memory ด้วย preset/provider ที่ใช้งานจริง หากมี error ให้เก็บ diagnostic ใหม่พร้อมรุ่น SillyTavern เพื่อแยกปัญหา provider/preset ออกจากข้อมูลผลลัพธ์ที่ผิดรูปแบบ
