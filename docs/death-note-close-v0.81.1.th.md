# Death Note 0.81.1 — ปิดสมุดระหว่างรอ AI

หลังจดชื่อและกดยืนยัน สามารถปิดสมุดหรือย่อหน้าต่างเหนือช่องพิมพ์เพื่ออ่านแชทได้ทันที AI จะต่อคำตอบเดิมและบันทึกผลในแชทเดิมต่อไป โดยไม่ส่งข้อความฝั่ง User

- ปุ่ม × ของสมุดเต็มหน้า ปุ่มย้ายไปเหนือ chatbar และปุ่มย่อ/ปิดของหน้าต่างเหนือ chatbar ใช้ได้ระหว่างรอคำตอบ
- เมื่อ AI ตอบเสร็จ สมุดที่ปิดไว้จะไม่เปิดกลับมาเอง หน้าต่างที่ย่อไว้ยังคงย่ออยู่
- หากเปิดสมุดกลับมาระหว่างรอ หน้าที่กำลังจดยังอ่านได้ แต่แก้ไขหรือยืนยันซ้ำไม่ได้จนกว่างานเดิมจะจบ
- ผลของชื่อที่จดบันทึกครั้งเดียว ข้อความที่พิมพ์ค้างไว้ในช่องแชทไม่ถูกส่ง และกระดาษกับผลที่ยืนยันแล้วอยู่ครบหลังรีโหลด
- หากคำขอ AI ล้มเหลวก่อนมีข้อความตอบ หมึกเดิมยังอยู่และสามารถยืนยันเพื่อลองใหม่ได้

อัปเดตส่วนเสริมเป็น **0.81.1** แล้วโหลดหน้า SillyTavern ใหม่เมื่อการเจนปัจจุบันจบ ไม่ต้องนำเข้าการ์ดใหม่หรือล้างแชท การปิดสมุดหมายถึงปิดหน้าต่างภายใน SillyTavern โดยยังเปิดหน้าแชทไว้

## สาเหตุและการแก้ไข

ตัวล็อก `working` เดิมครอบคลุมปุ่มทุกชนิด จึงกันปุ่มปิดและย่อพร้อมกับปุ่มจดชื่อ รุ่นนี้ประมวลผลปุ่มจัดการหน้าต่างก่อนตรวจตัวล็อก ส่วนการเขียนและบันทึกผลยังเป็นหน้าที่ของงานที่เริ่มไว้แล้ว จึงปิดหน้าต่างได้โดยไม่ยกเลิก Continue หรือสร้างคำขอซ้ำ

## การทดสอบ

ทดสอบผ่าน SillyTavern **1.19.0 / 06bde93** ธีม **Dark Lite** โดยใช้ระบบ Continue จริงและชะลอคำตอบ SSE จนกว่าจะตรวจว่าปิดสมุดได้ขณะ `working` ยังเป็นจริง ครอบคลุม desktop 1440 × 1000 และ Chromium mobile touch emulation 390 × 844

ตรวจการปิดเต็มหน้า ย้ายไปเหนือ chatbar ย่อและซ่อนหน้าต่าง เปิดกลับมาระหว่างรอ ป้องกันการยืนยันซ้ำ การคงข้อความแชทเดิมและร่างที่ยังไม่ส่ง การบันทึกผลครั้งเดียว การตอบผิดพลาด HTTP 503 แล้วลองใหม่ และการโหลดข้อมูลกลับจากแชทที่บันทึกไว้

ชุดทดสอบอัตโนมัติผ่าน **1,644 / 1,644** และ syntax check ผ่าน ชุด Death Note เดิมบน SillyTavern ผ่านทั้งสองขนาดหน้าจอ รวมการเขียนอิสระ ชื่อปลอม/ชื่อจริง ดวงตา การถือครองและสละสิทธิ์ กฎปลอม การรอเวลาในเรื่อง การแยกการ์ด และการบันทึกหลังรีโหลด

คำตอบโมเดลเป็น fixture ที่ควบคุมได้ ไม่ได้เรียกผู้ให้บริการ AI ภายนอก และการทดสอบมือถือเป็นการจำลองใน Chromium ไม่ใช่ Safari บน iPhone จริง
