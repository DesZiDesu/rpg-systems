## วิธีเปิดใช้

1. อัปเดตส่วนเสริมเป็น **0.79.0** แล้ว reload SillyTavern หลังบันทึกข้อความร่างเรียบร้อย
2. เปิด **Extensions → RoleForge → หน้าต่างเหนือ chatbar** แล้วเปิด **H-Stats** และเปิดการติดตามคำตอบ AI ตามปกติ
3. ใน RoleForge → H-Stats เลือก NPC ที่เคยพบและกดเพิ่มในรายชื่อ แสดงคู่แข่งที่เคยพบแล้วได้ด้วย โดยไม่ต้องเปลี่ยนให้เป็นมิตร
4. เหนือ chatbar เลือก H-Stats แตะชื่อโปรไฟล์เพื่อเลือกคนที่กำลังดู จากนั้นแตะปุ่มรูปคนเพื่อเลือกว่าจะดูความรู้สึกของเขาที่มีต่อใคร ค้นชื่อและเปลี่ยนหน้าได้โดยไม่ใช้ dropdown ของระบบ
5. เลือก **ภาพรวม / เหตุการณ์ / กติกา** ในส่วนสายสัมพันธ์ ปุ่มดินสอใช้แก้ค่าหรือสถานะของคู่นั้นเองได้ การเปิดดูและแก้มือไม่ส่งข้อความ User และไม่เรียกโมเดล

ข้อมูลร่างกาย ประวัติ และความชอบเดิมยังอยู่ในหมวด H-Stats การเปิดดูไม่สร้างโปรไฟล์ AI อัตโนมัติอีกแล้ว หากต้องการเติมช่องร่างกายที่ยังว่าง มีปุ่มให้สั่งเติมเองในหน้าหลัก และจะใช้การเชื่อมต่อ AI เดิมเมื่อกด

## ค่าที่ติดตาม

| ค่า | ความหมาย |
|---|---|
| Love / ความผูกพัน | ความผูกพันต่อบุคคลที่เลือก 0–100 |
| Interest / ความสนใจ | ความสนใจต่อบุคคลนั้น 0–100 แยกจากความผูกพันระยะยาว |
| Trust / ความเชื่อใจ | ความไว้ใจจากพฤติกรรมและสิ่งที่เจ้าตัวรับรู้ |
| Commitment / คำมั่น | ความตั้งใจรักษาความสัมพันธ์และข้อตกลง |
| Corruption / การเปลี่ยนหลักยึด | การเปลี่ยนหลักการของตัวละคร ไม่เพิ่มเพียงเพราะมีเหตุการณ์ใกล้ชิด |
| Resistance / แรงยึดเหนี่ยว | 0–100 ลดการเพิ่ม Corruption และความรู้สึกต่อคนที่สามเมื่อมีคู่แบบผูกขาดอยู่แล้ว |

**A → B ไม่ได้แปลว่า B → A** ความรู้สึกตอบกลับต้องมีข้อมูลของเจ้าตัวเอง ช่องผูกพันมากที่สุดและสนใจมากที่สุดจัดอันดับแยกกัน ถ้าคะแนนเท่ากันจะแสดงว่าเท่ากัน และช่องว่างยังหมายถึงไม่ทราบ

สถานะเพื่อน คบกัน คู่สมรส แยกทาง และข้อตกลงผูกขาด/ไม่ผูกขาด เก็บแยกจากคะแนน คะแนนสูงไม่ได้เปลี่ยนสถานะคู่รักหรือสร้างการนอกใจเอง และไม่มีการสลับเวอร์ชัน NPC ตามอันดับความรู้สึก

## พัฒนาการตามเหตุการณ์

- ค่าเริ่มต้น **Slow** เพิ่มความรู้สึกรวมไม่เกิน 3 จุดต่อคู่ต่อฉากต่อเนื่อง เหตุการณ์สำคัญที่มี milestone เพิ่มได้ไม่เกิน 6 จุด ไม่เติมงบใหม่เพียงเพราะ AI ส่งข้อความถัดไป
- Balanced ใช้ 6 / 10 จุด ส่วน Custom กำหนดเพดานเองได้ การแก้ด้วยดินสอเป็นสิทธิ์ผู้เล่น/ผู้สร้างและไม่อยู่ใต้เพดานการเติบโตจากเรื่อง
- งบฉากใช้วัน ช่วงเวลา 6 ชั่วโมง และสถานที่ ไม่ใช้เลขลำดับ Scene Tracker ซึ่งอาจเปลี่ยนทุกข้อความ เหตุการณ์ลักษณะเดิมซ้ำในฉากเดียวลดการเพิ่มลงอีก
- การเปิดใจ ความสนใจที่มีต่อกัน และการตกลงคบกันเป็น milestone ของความผูกพัน การทักทายหรือคำชมทั่วไปไม่ให้แต้มอัตโนมัติ
- เรื่องผิดข้อตกลงต้องมีคู่ที่คบ/สมรสแบบผูกขาดอยู่แล้ว คนที่สาม และหลักฐานเหตุการณ์จริง ปิดเส้นเรื่องนี้ได้ทั้งระดับแชตและราย NPC
- คู่ที่อยู่นอกฉากยังมีสถานะและคำมั่นในข้อมูลอ้างอิง AI โดยส่งเฉพาะชื่อ/ID และข้อมูลความสัมพันธ์ที่เกี่ยวข้อง ไม่โหลดประวัติเต็มทั้งคลัง
- ฝ่ายที่ยังไม่รู้เหตุการณ์จะไม่เสีย Trust เอง ต้องมีเหตุการณ์ที่เจ้าตัวรู้ความจริงหรือเห็นกับตา
- สถิติร่างกาย/ประวัติของเหตุการณ์ NPC สองคนเปลี่ยนเฉพาะผู้เกี่ยวข้อง ไม่เพิ่มสถิติของผู้เล่น ไม่เปลี่ยนพ่อของบุตรเป็นผู้เล่น และไม่เพิ่ม Love อัตโนมัติ
- เรื่องที่เป็นความฝัน ข่าวลือ เงื่อนไขสมมติ หรือยังไม่เกิดขึ้นไม่ถูกนับเป็นเหตุการณ์ที่ยืนยันแล้ว

การเปลี่ยนข้อมูลผูกกับคำตอบและ swipe ของ SillyTavern สลับคำตอบแล้วสถิติเหตุการณ์กลับตามเวอร์ชันนั้นได้ ส่วนค่าหรือกติกาที่ผู้ใช้ตั้งใจบันทึกทีหลังจะถูกเก็บไว้ โดยไม่ย้ายประวัติเต็มหรือเวอร์ชัน NPC กลับไปทับกัน

## แชตและการ์ดเดิม

Affection / Trust / Loyalty ที่มีอยู่ยังอ่านเป็นความผูกพัน ความเชื่อใจ และคำมั่นต่อผู้เล่นได้ ค่าจากเวอร์ชันที่เลือกยังใช้ได้โดยไม่แก้ดอสซิเยร์หลัก ตัวเลขหัวใจและ Stage เดิมยังอ่าน/แก้มือได้ใน “ข้อมูลเดิม” แต่ไม่ใช้ขับพัฒนาการหรือเป็นหลักฐานว่าเป็นคู่รัก

หากการ์ดเก่าไม่มีข้อมูลสถานะคู่และข้อตกลงแบบใหม่ ให้ตั้งในปุ่มดินสอของคู่นั้น หรือยืนยันผ่านเหตุการณ์ในเรื่อง ไม่ถือว่าหัวใจ 5 ดวงหมายถึงมีคู่แบบผูกขาด

NPC ที่ปิดการติดตามจะไม่ถูกเปลี่ยนค่าสถิติผ่านเหตุการณ์ AI การอ่านข้อมูลของ NPC อีกคนไม่เปลี่ยน `enabled`, `met`, Known Names การอยู่ในฉาก หรือเวอร์ชันที่ผู้ใช้เลือกไว้

## Preset และการ์ดไฟล์เดียว

- **กติกา → ส่งออก Preset** เก็บกติกา โปรไฟล์หลักยึด ค่าตั้งต้นของแต่ละคู่ และสถานะข้อตกลง ไม่มี receipts, budgets หรือรายการประวัติเหตุการณ์ทั้งชุด
- **นำเข้า Preset** ตรวจไฟล์ก่อนบันทึก เพิ่มคู่ที่ยังไม่มีและเปลี่ยนกติกา/นโยบาย โดยไม่ทับค่าคู่ที่เล่นไปแล้ว และเก็บ seed เหล่านี้ใน snapshot เดิมสำหรับการ swipe
- World Preset มีหมวด **สายสัมพันธ์และกติกา** ใช้ส่งออก/นำเข้าร่วมกับระบบอื่นได้
- ถ้าต้องการพ่วงไปกับบอท ให้กด **Presets และการ์ดตัวละคร → บันทึกชุดข้อมูลลงการ์ด** แล้ว Export การ์ดจาก SillyTavern ความสัมพันธ์ที่จัดไว้จะเป็นค่าเริ่มต้นของแชตใหม่ แชตเดิมของผู้รับไม่ถูก reset
- ข้อมูลใช้ stable NPC ID การย้าย Preset ไปอีกบอทต้องมี ID ของตัวละครที่ตรงกัน ชื่อเหมือนกันอย่างเดียวไม่ใช้รวมคน
- มีเฉพาะกราฟคู่ที่เกี่ยวข้อง ไม่สร้างตาราง NPC ทุกคนคูณกัน และการเลือกเป้าหมายใช้ดัชนีชื่อก่อนโหลดดอสซิเยร์เฉพาะที่เลือก

รูปแบบไฟล์แยก:

```json
{
  "format": "roleforge-relationship-preset",
  "version": 1,
  "name": "My relationships",
  "preset": {
    "version": 1,
    "config": {"enabled": true, "pace": "slow", "sceneGain": 3, "majorGain": 6, "allowInfidelity": true},
    "links": [{"actorId": "mira", "targetId": "kai", "love": 20, "interest": 30, "trust": 25, "commitment": null}],
    "bonds": [{"a": "mira", "b": "kai", "status": "dating", "agreement": "open"}],
    "profiles": {"mira": {"resistance": 75, "allowInfidelity": true, "anchor": "รักษาบุคลิกและคำมั่นเดิม", "corruption": 0}}
  }
}
```

## ผลทดสอบและขอบเขต

ฐานก่อนพัฒนา: main `7284e4d17b4e83a23e8866ab7d05b0780f5e25a8` รุ่น 0.78.1 ตรวจ remote revision ก่อนแก้ไข งานเริ่มใน worktree แยกและรวมกลับ main หลังตรวจเสร็จ

**Unit/host integration:** `npm run check` ผ่าน และ `npm test` ผ่าน **1,483 / 1,483** รายการ ตรวจการ normalize/ย้ายข้อมูลเดิม ความรู้สึกมีทิศทาง อันดับแยกกัน งบฉาก milestone การยืนยันข้อตกลง Counter ของ NPC ทั้งสอง การกันนับซ้ำ parentage การแก้มือ Preset/snapshot และการป้องกัน raw AI operation ข้ามกติกา ทดสอบการ reject promise จาก host เพื่อให้การแก้และ Import ล้มเหลวไม่ค้างข้อมูลที่บันทึกครึ่งหนึ่ง

**SillyTavern จริง:** ใช้ 1.19.0 commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`, ธีม Dark Lite, Chromium บน desktop และ touch/mobile emulation ผ่าน native card Import, Generate/StreamingProcessor, swipe, save/reload, เปลี่ยนการ์ด และปุ่ม Save setup/Export card จริง การตอบ AI ในรอบทดสอบเป็น streaming fixture ที่ควบคุมไว้ ไม่ได้ใช้ผู้ให้บริการโมเดลสด [รายงานผล JSON](previews/relationships-v0.79.0/native-validation.json) มี 8 generation requests และตรวจ 15 layout combinations ที่ 320, 390, 430, 768, 1440 px

**Native chatbar regression:** ผ่านอีก 190 layout combinations รวมชื่อ/ข้อมูลยาวทั้ง 5 หมวด H-Stats และการเลื่อนแท็บบนจอสัมผัส โดยไม่เผลอสั่ง swipe ข้อความ ไม่ส่งข้อความ User และมี model requests 0 ครั้ง [รายงาน JSON](previews/relationships-v0.79.0/chatbar-validation.json)

ทดสอบ UI เดิมเพิ่มเติมด้วย browser fixture สำหรับ H-Stats directory/portrait/hide/undo/ภาษา/Groups, World Preset และ Character Pack จอ 320/390/1280 px แยกจากการรัน native SillyTavern ข้างต้น

ข้อจำกัด: ยังไม่ได้ทดสอบบน iPhone/Safari จริง ข้อมูลที่ติดตามต้องอาศัย AI ส่งเหตุการณ์พร้อมคำอ้างอิงที่อ่านได้ ระบบจำกัดค่าที่บันทึกและส่งกติกาให้โมเดล แต่รับประกันไม่ได้ว่าร้อยแก้วทุกโมเดลจะทำตามกติกาทั้งหมด ไม่มีการเรียก API ซ่อมคำตอบเพิ่มเติมโดยอัตโนมัติ

SillyTavern 1.19.0 อาจกลืน HTTP error บางชนิดในตัวบันทึกของ host การทดสอบ rollback ด้วย promise rejection เป็น host integration test และไม่ใช่หลักฐานว่าตรวจพบ HTTP failure ได้ทุกกรณี การบันทึก/reload ตามปกติผ่านในเบราว์เซอร์จริง
