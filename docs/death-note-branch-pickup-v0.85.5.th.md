# RoleForge 0.85.5 — แก้การหยิบสมุดจากแชท Branch

## สาเหตุที่ยืนยันจากไฟล์

ข้อความเปิดที่มองเห็นเหมือนกับการ์ดใช้ CRLF ส่วนข้อมูล `greetingBooks` ของการ์ดใช้ LF การเทียบแบบตรงตัวจึงไม่พบสมุดเริ่มต้น `dn-fallen-notebook` และไม่มีสมุดให้ระบบรับการหยิบ

คำตอบ AI หลังผู้เล่นเก็บสมุดส่ง `acquire` โดยอ้าง `dn-opening-notebook` และคัดลอกข้อความผู้เล่นเป็น evidence แทนข้อความยืนยันในคำตอบ AI ตัวตรวจจึงปฏิเสธตามกติกาเดิม นอกจากนี้สำนวน “เก็บขึ้นมาใส่กระเป๋า” และการบรรยายแบบ “สมุดเล่มนั้นที่เพิ่งสอดเก็บลงในกระเป๋า” ไม่ตรงกับตัวตรวจการหยิบเดิม ชื่อผู้เล่นใน State ยังเป็นค่าเริ่มต้น จึงใช้ชื่อใน State ยืนยันผู้กระทำไม่ได้

## การแก้ไข

- ปรับเฉพาะการขึ้นบรรทัด CRLF/CR ให้เทียบกับ LF ได้ โดยยังต้องเป็นข้อความเปิดที่ใช้งานจริงและมีเนื้อหาตรงกัน ไม่อ่านข้อเท็จจริงจาก alternate greeting ที่ไม่ได้เลือก
- ใช้ตัวตรวจเจตนาหยิบร่วมกันทั้งเหตุการณ์จาก AI และการกู้จากข้อความ รองรับสำนวนการเก็บขึ้นมาใส่กระเป๋า รวมถึงประโยคที่บอกการกระทำสำเร็จหลังคำเชื่อม “ก่อนที่จะ…” โดยยังปฏิเสธแผนหรือคำปฏิเสธที่ไม่มีการเก็บจริง
- กู้จากข้อความบรรยายที่มองเห็นเมื่อมีสมุดที่พบแล้วเพียงเล่มเดียว ไม่มีผู้ถือ และมีทั้งการหยิบจริงในข้อความ User กับคำยืนยันที่สอดคล้องในคำตอบ AI ไม่เชื่อ ID หรือ evidence ที่ผิดเพียงอย่างเดียว ไม่สร้างสมุดชื่อ `dn-opening-notebook` เพิ่มเพื่อให้ตรงกับคำสั่งผิด
- ข้อเท็จจริงจากข้อความเปิดเป็นจุดเริ่มต้นของประวัติ ไม่ให้ทะเบียนสรุปที่บันทึกภายหลังหรือ Inventory ปลายทางย้อนการถือครองกลับไปก่อนหยิบ การแก้ข้อความ สลับ swipe และตัด Branch ยังคงอ่านเฉพาะหลักฐานที่เหลือในช่วงนั้น
- หากการโหลดแฟ้ม NPC รอบแรกถูกยกเลิกระหว่างแฟ้มเปลี่ยน revision จะอ่านใหม่ได้หนึ่งครั้งเฉพาะเมื่อยังอยู่ใน scope เดิม เปลี่ยนแชทแล้วหยุด ไม่เขียน Inventory ข้ามแชท

ไม่เปลี่ยนตัวตรวจพิกัด `notebookInScene` และไม่สร้างตำแหน่งให้ State การกู้ยังแยกจากการกดปุ่มหยิบ: ปุ่มต้องผ่านการตรวจฉากตามเดิม ส่วนการกู้ใช้ประวัติการหยิบที่เกิดขึ้นไปแล้วจริง สมุดที่ NPC ถือ สมุดหลายเล่มที่ยังระบุไม่ได้ เศษกระดาษ คำบอกเล่าใน dialogue/ความคิดเห็นซ่อน และคำสั่ง AI ที่ไม่มีความยินยอมผู้เล่นไม่เข้าเงื่อนไขการกู้อัตโนมัตินี้

Inventory ใช้ขั้นตอนซิงก์เดิมของ Addon เมื่อเปิดแชท ไม่ต้องเปิดใช้ตัวติดตามสถานะหลักเพื่อบังคับให้พิกัดเปลี่ยน ไม่มีการเพิ่มข้อความ User ไม่มีการเปลี่ยนข้อความโรล และการกู้ไฟล์เดิมไม่เรียก AI

## ผลทดสอบ

[ดูภาพ PC / มือถือและรายงาน](previews/death-note-v0855/index.html)

ทดสอบหน่วย 1,800 รายการและ syntax checks ผ่าน ตรวจบน SillyTavern 1.19.0 ด้วย Chromium และ WebKit ทั้ง PC / mobile emulation: พิมพ์หยิบพร้อมคำสั่ง AI ผิด ID, Inventory จำนวน 1, Branch จริงก่อนหยิบกลับเป็นจำนวน 0, ปุ่มหยิบผ่าน Continue โดยไม่สร้าง User turn และยังเก็บ draft ที่ไม่ได้ส่งไว้ รวมถึงจำลองการอ่านแฟ้มถูกยกเลิกหนึ่งครั้ง

นำเข้าสำเนาไฟล์จริงพร้อมคลังตัวละครของการ์ด ผลคือ `dn-fallen-notebook` อยู่กับ player และ Inventory มีจำนวน 1 โดยข้อความต้นฉบับไม่เปลี่ยน พิกัดยังเป็น Unknown และไม่มีการเรียกโมเดลเพิ่มเพื่อกู้ข้อมูล ภาพสาธารณะใช้ตัวอย่างทดสอบ ไม่เผยแพร่ไฟล์แชทหรือภาพจากแชทส่วนตัวใน Git

คำตอบสำหรับทดสอบการกด Send/Continue ใช้ controlled SSE ภายในเครื่อง ไม่เรียกบริการโมเดลหรือเสียงจริง การทดสอบมือถือเป็น browser emulation ไม่ใช่การใช้ iPhone จริง
